## 0. 大前提

これは売買推奨ルールではない。

```text
過去チャート上で
自分が何を見ていたのかを再現し、
Entry / Hold / Close / Reset / NoTrade を
自動シミュレーション可能な形へ分解する
```

ための仮説仕様である。

v0.24では、v0.23で追加した「Entry前Dow崩壊失効」を、Normal HSI AnchorのLifecycleまで含めて明確化する。

```text
1. Entry前にM5 Dow構造の崩壊が確定した時点で、
   旧Dow Confirmation / 旧Normal HSI Anchor / 旧Entry Opportunityを同時に終了する。

2. Dow崩壊後は、次の新しいM5 Dow Confirmationが成立するまで
   Normal HSI Anchorを持たない。

3. Dow再確定時は、その新しいDow構造の根拠となる
   previous Low / previous Highを新しいNormal HSI Anchorとして採用する。

4. R2到達履歴は新しい起点から再計算し、
   新しいDow Confirmationと新しい起点に対する最初のR2成立だけをEntry判定に使う。

5. R2タッチ等でEntry成立後は、Dow崩壊だけを理由にCloseしない。
   Entry時のHSI起点・Target・StopはTrade終了まで固定する。
```

Dow再確定点はEntry Triggerであり、HSI起点そのものではない。
HSI起点は、再確定した新しいDow構造の開始点となるprevious Swingである。

v0.23で追加したJSON固定倍率Stopは維持する。
Entry前の切符失効と、Entry後のClose判断は別責務として扱う。

v0.22では、NORMAL Rule Laneの新規M5 Entryに、H4現在波の伸び切りGuardを追加する。

```text
Rule Lane = NORMAL
AND Entry方向 = H4現在波方向
AND H4現在波のHSI進行度 >= R4
→ 新規Normal Entry禁止
```

方向別には次のとおり。

```text
LONG
AND H4現在波 = UP
AND H4上昇波のHSI進行度 >= R4
→ 新規Normal Long Entry禁止

SHORT
AND H4現在波 = DOWN
AND H4下降波のHSI進行度 >= R4
→ 新規Normal Short Entry禁止
```

Day Trendは本Guardの必須条件にしない。方向が正しくても、H4波がすでにR4まで進んでいるなら「今から乗るには遅い」と判断する。

v0.21のDay Up / H4調整下降R5 Short Guardは、NORMALへの適用をv0.22で置き換える。EXPANSION_LITEおよび将来EXPANSIONへのv0.21 Guardは変更せず、今回R4へ厳格化しない。


v0.19では、NORMAL Rule LaneのCycle Late Guardを改定する。

```text
変更前: H4 / H1 Cycle Lateで通常Entry禁止
変更後: H1 Cycle Lateだけで通常Entry禁止
```

H4 Cycleは通常Entryの観測情報として残すが、通常Entryの禁止条件には使用しない。EXPANSION / EXPANSION_LITEの条件には一切影響させない。

最重要原則は、**Rule Lane間でEntry / Add-on / Exit / Anchor Lifecycleを混ぜないこと**である。

最重要変更は次のとおり。

```text
M5 Dow Confirmation成立
→ その確認の根拠となるprevious Swingを通常HSI起点として採用
→ Normal Entry
→ CloseOK または CloseMiss
→ その瞬間に通常HSI起点を破棄
→ Close後の新しいM5 Dow Confirmationを待つ
→ 新しいprevious Swingから次の通常HSI起点を採用
```

通常HSI起点をClose後も維持する考え方はExpansion専用であり、NORMAL Rule Laneへ混ぜない。

```text
確定済みの押し安値 / 戻り高値
↓
直前構造高値 / 安値をM5確定足で突破
↓
M5 Dow Confirmation Event成立
↓
その時点ですでにR2以上なら即Entry
↓
実Entry地点より先の次HSI境界で全Close
```

このv0.15の定義は、v0.14のEntry / Close条件を引き継ぎ、NORMAL Rule Laneの語彙とLifecycleを上書きする。

## 0.1 Rule Laneごとの語彙境界

```text
NORMAL Rule Lane
- Entry
- Hold
- CloseOK
- CloseMiss
- Reset / Wait / Missed / Expired

NORMAL Rule Laneでは使わない
- ReEntry
- Add-on
- Expansion Core
- Expansion Detection Anchor
- Expansion Entry Anchor
```

NORMAL Rule Laneでは、過去に通常Tradeが完了しているかどうかに関係なく、新しいM5 Dow Confirmation Eventから成立したTradeはすべて独立した **Normal Entry** と呼ぶ。

```text
Normal Entry #1
→ Close
→ 新しいM5 Dow Confirmation Event
→ Normal Entry #2
→ Close
```

これは `ReEntry` ではない。回数識別が必要な場合は `normal_entry_sequence_no` を使用する。

```text
1 Dow Confirmation Event
= 最大1 Normal Entry Opportunity
= 最大1 Normal Entry
```

前回Trade終了後の次のNormal Entryには、新しいM5 Dow Confirmation Eventが必要である。ただし、この制約をReEntry条件とは呼ばない。

`ReEntry` と `Add-on` は、今後定義するExpansion / Expansion-Lite Rule Laneの専用語として予約する。NORMAL Rule Laneの判定・表示・集計・Traceへ混ぜてはならない。

## 0.2 Rule Lane完全分離原則（v0.18）

```text
NORMAL
EXPANSION
EXPANSION_LITE
```

各Rule Laneは、次の要素を独立して所有する。

```text
Entry Gate
Entry Trigger
Entry Price契約
Anchor Lifecycle
Add-on条件
Exit条件
Action語彙
Trade Lifecycle
Trace / 集計
```

共有してよいのは、ローソク足、T3、HSI境界、Cycle位置、確定済みDow点などの**観測事実**だけである。

```text
禁止
- 他LaneのEntry条件を補完利用する
- 他LaneのExit条件へFallbackする
- 他LaneのAnchorを流用する
- 未定義部分をNORMAL Rule Laneの契約で埋める
```

EXPANSION_LITEの仕様が未定義の場合は、他Laneのルールを流用せず、判定不能として扱う。

## 1. v0.14の変更理由

v0.13では、M5 Dow Confirmation EventをHigh / Low比較ペアが完成した時点で発行していた。

しかし実際に人間が見ていたDow Up確定は、単にHigher Lowが確認された時点ではない。

```text
押し安値が確定
＋
その後に直前高値を上抜く
＝ Dow Up確定
```

Dow Downは対称形である。

```text
戻り高値が確定
＋
その後に直前安値を下抜く
＝ Dow Down確定
```

したがって、通常Entryの切符となるDow Confirmation Eventは、Swing比較ペアの完成時ではなく、**構造高値 / 安値の突破時**に発行する。

## 2. 時間足の役割

```text
WEEK = Expansion Season / 高値づかみ防止
DAY  = Expansion格付け / 上位地図
H4   = T3による通常方向許可 / Expansion判断
H1   = T3による通常方向確認 / 通常Cycle Guard / Expansion観測
M5   = Dow Confirmation Event / Entry / Closeの実行
```

通常M5 Entryの必須要素は次のとおり。

```text
H4 T3方向
＋ H4 CloseのT3上下位置
＋ H1 T3方向
＋ H1 CloseのT3上下位置
＋ H1 Cycle Late除外
＋ M5 Dow Confirmation Event
＋ 確定HSI起点からR2以上
```

H4 Dow、H1 Dow、WEEK、DAY、Expansion Confirmedは通常M5 Entryの必須条件にしない。

## 3. M5 Dow StateとDow Confirmation Eventを分ける

### 3.1 M5 Dow State

```text
UP
DOWN
REVERSAL_WATCH
NO_TREND
UNDETERMINED
```

現在の方向状態を表す。

### 3.2 M5 Dow Confirmation Event

新しい構造が確定した出来事を表す。

```text
1 Dow Confirmation Event
= 1 dow_confirmation_id
= 1 HSI起点
= 最大1回の通常Entry機会
```

同じ `Dow State = UP` が続いていても、新しいDow Confirmation Eventがなければ次のNormal Entry Opportunityは発生しない。

## 4. Dow Up Confirmation

Long側の確認順序。

```text
① previous Lowがある
② その後に直前構造Highが形成される
③ さらにHigher Lowが確定する
④ ④以降のM5確定足が、②の構造Highを上抜く
⑤ そのM5確定足でDow Up Confirmation Event成立
```

HSI起点は、Higher Lowそのものではない。

```text
Normal HSI Anchor = previous Low
```

つまり、押し安値へ起点を乗り換えるのではなく、今回のDow波が始まった比較ペア先頭のLowを採用する。

---

## 5. Dow Down Confirmation

Short側は対称形。

```text
① previous Highがある
② その後に直前構造Lowが形成される
③ さらにLower Highが確定する
④ ④以降のM5確定足が、②の構造Lowを下抜く
⑤ そのM5確定足でDow Down Confirmation Event成立
```

```text
Normal HSI Anchor = previous High
```

## 6. 通常HSI起点Lifecycle（v0.24）

通常HSI起点は、現在有効なM5 Dow Confirmation Eventに属する一時的な基準点である。

```text
1 有効なM5 Dow Confirmation Event
= 1 dow_confirmation_id
= 1 Normal HSI Anchor
= 最大1 Normal Entry Opportunity
= 最大1 Normal Entry
```

Normal HSI Anchorは、Trade Closeだけでなく、**Entry前のDow構造崩壊確定時にも終了する。**

### 6.1 新しいDow Confirmation成立時の起点採用

Long:

```text
新しいM5 Dow Up Confirmation成立
→ その新しいDow構造の根拠となるprevious Lowを採用
→ Normal HSI Anchor = previous Low
```

Short:

```text
新しいM5 Dow Down Confirmation成立
→ その新しいDow構造の根拠となるprevious Highを採用
→ Normal HSI Anchor = previous High
```

Dow突破を確定した価格・時刻はConfirmation Triggerであり、Normal HSI Anchorではない。

```text
Dow再確定点
≠ Normal HSI Anchor

Normal HSI Anchor
= 再確定した新しいDow構造の開始点となるprevious Swing
```

Higher Low / Lower HighはDow構造を確認する構成要素だが、それ自体を自動的にNormal HSI Anchorへ採用しない。

### 6.2 Entry前Dow崩壊確定時の一括終了

現在有効なDow Confirmationを根拠にEntry待機している間に、そのDow構造の崩壊が確定した場合、次を同一Lifecycle終了イベントとして処理する。

```text
旧dow_confirmation_id = INVALID / RETIRED
旧Normal HSI Anchor   = RETIRED
旧Entry Opportunity   = EXPIRED
旧起点に対するR2到達履歴 = 破棄
```

状態遷移:

```text
ACTIVE_CONFIRMATION / WAITING_R2
↓ Dow構造崩壊確定
NO_ACTIVE_CONFIRMATION
NO_NORMAL_HSI_ANCHOR
WAIT_NEW_M5_DOW_CONFIRMATION
```

崩壊後に価格が旧起点のR2へ到達してもEntryしてはならない。

### 6.3 Dow崩壊後の再確定

Dow崩壊後に、同じ方向を含む新しいDow Confirmationが成立した場合、それは旧Confirmationの継続ではなく、**新しい構造の新しいConfirmation**として扱う。

```text
旧Dow Up
↓ 崩壊確定
旧Confirmation / 旧Anchor / 旧Opportunityを終了
↓
新しいDow Up Confirmation
↓
新しいdow_confirmation_id
新しいprevious Low
新しいNormal HSI Anchor
新しいEntry Opportunity
```

Short側も対称とする。

新しいNormal HSI Anchorを採用した後、R2価格とR2初回到達履歴をゼロから作り直す。

### 6.4 起点乗り換え禁止と再確定後の新規採用

現在のDow Confirmationが有効で、Dow崩壊が確定していない間は、後続の同方向Swingや同方向状態更新を理由にNormal HSI Anchorを乗り換えてはならない。

```text
有効な同一Dow構造の継続
→ Anchor固定

Dow崩壊確定
→ Anchor終了

崩壊後の新しいDow Confirmation
→ 新しいAnchor採用
```

したがって、次の二つを区別する。

```text
同一構造内の同方向継続
≠ Anchor更新

崩壊後の同方向Dow再確定
= 新しいConfirmation + 新しいAnchor
```

### 6.5 Entry成立後

R2タッチ等でEntryが成立した後は、Entry Opportunityを `USED` とし、Entry前LifecycleからTrade Lifecycleへ移行する。

```text
WAITING_R2
↓ R2成立 + 全Gate成立
USED / IN_TRADE
```

Entry時に採用したNormal HSI Anchorは、当該Tradeの次の用途に固定する。

```text
Entry距離計算
Target価格
倍率Stop / Effective Stop
当該Tradeの判断Trace
```

Entry後にDow構造が崩壊しても、**Dow崩壊単独ではCloseしない。**

```text
USED / IN_TRADE
AND Dow構造崩壊
↓
Position = HOLD
Trade用Normal HSI Anchor = 固定維持
Target / Stop = 固定維持
自動Close = しない
```

Entry後に新しいDow Confirmationが成立しても、現在TradeのNormal HSI Anchorへ乗り換えず、次回Trade用として先取りもしない。

v0.24のEntry前失効規則を、保有Positionへ適用してはならない。

### 6.6 Close時

```text
Target到達
または
Effective Stop到達
または
将来Close Strategy側で明示的に採用したClose条件
↓
Position Close
normal_hsi_anchor = NONE
normal_entry_opportunity = NONE
next_state = WAIT_NEW_M5_DOW_CONFIRMATION
```

Close済みNormal HSI Anchorを、次回Normal Entryへ再利用してはならない。

### 6.7 次の通常Entry

次の通常Entryには、前Trade Close後、またはEntry前Dow崩壊による失効後に成立した、新しいM5 Dow Confirmation Eventが必要である。

```text
前Trade Close
または
Entry前Dow構造崩壊
↓
新しいM5 Dow Confirmation
↓
新しいprevious Swing
↓
新しいNormal HSI Anchor
↓
新しいNormal Entry Opportunity
```

同じ方向へのEntryであっても、新しい独立Tradeとして扱う。ReEntryとは呼ばない。

### 6.8 Expansionとの分離

```text
NORMAL
- Entry前Dow崩壊で旧Anchorを失効
- Entry後はTrade用AnchorをCloseまで固定
- Trade CloseでAnchorを破棄

EXPANSION
- Detection Anchorを大波追跡用に維持する場合がある
```

Expansion Detection Anchor、Expansion Entry Anchor、Expansion-Lite AnchorをNormal Entry判定へ流用してはならない。

## 7. 通常Entryの判定順

### 7.1 Dow確認時点でR2未到達

```text
M5 Dow Confirmation Event成立
↓
固定HSI起点からR2未到達
↓
Entry Opportunity = WAITING_R2
↓
確認後のR2初回到達
↓
全Gate成立ならR2境界価格でEntry
```

R2初回到達時にGate不成立なら、そのOpportunityは `MISSED` とする。

### 7.2 Dow確認時点ですでにR2以上

```text
M5 Dow Confirmation Event成立
↓
固定HSI起点からR2以上
↓
Dow確認成立を最後のTriggerとして即Entry
```

これは遅れEntryではない。

```text
HSI距離条件は先に成立済み
＋
最後に不足していたDow確認が成立
＝ 即Entry
```

Entry価格はR2境界へ遡らない。

```text
Entry Price = Dow突破確認M5確定足の利用可能価格
```

初期実装では確定足Closeを使用する。

## 8. 通常Target

v0.13の「通常Targetは常にR2.5」を廃止する。

v0.14では、実Entry地点より先に残っている**次のHSI境界**をTargetとして固定する。

```text
Entry距離がR2〜R2.5
→ Target R2.5

Entry距離がR2.5〜R3
→ Target R3

Entry距離がR3〜R3.5
→ Target R3.5

Entry距離がR3.5〜R4
→ Target R4
```

同様に以後の境界へ続く。

Entry時にTargetを一つだけ固定し、到達時は10単位を全Closeする。

```text
1 Entry ID
= 1 Position
= 1 Stop
= 1 Target
= 1回の全Close
```

Partial Close、Runner、通常Add-onは使用しない。

## 9. NORMAL CloseMiss Stop（v0.23）

NORMALのCloseMiss Stopは、Entry時に確定したTargetまでの利益幅へ、JSON固定倍率を掛けて計算する。

```text
Reward Distance
= abs(Target Price - Entry Price)

Max Loss Distance
= Reward Distance × max_loss_to_reward_ratio
```

Long:

```text
Ratio Stop Price
= Entry Price - Max Loss Distance
```

Short:

```text
Ratio Stop Price
= Entry Price + Max Loss Distance
```

Entryに使用した通常HSI起点は、構造上のHard Limitとして残す。倍率計算StopがHSI起点より遠くなる場合は、HSI起点を超えて損失を許容しない。

Long:

```text
Effective Stop Price
= max(Ratio Stop Price, Normal HSI Anchor Price)
```

Short:

```text
Effective Stop Price
= min(Ratio Stop Price, Normal HSI Anchor Price)
```

初期JSON設定例:

```json
{
  "normal": {
    "close_miss": {
      "strategy_id": "target_distance_ratio_v0_1",
      "max_loss_to_reward_ratio": 1.0,
      "hsi_anchor_hard_limit": true,
      "fix_price_at_entry": true
    }
  }
}
```

`max_loss_to_reward_ratio` は正の有限数とする。初期Draft値は `1.0` とし、シミュレーションごとに人間がJSONを変更して比較する。過去勝率・直近成績・Lane別成績からの動的算出は将来候補とし、v0.23では使用しない。

Stop価格はEntry時に一度だけ固定する。Entry後にTarget、倍率、HSI起点、勝率推定値を使って再計算しない。

Target / Stop到達判定はM5 High / Lowを使用する。

同一M5足でTargetとStopの両方へ到達した場合は、保守的にStopを先に適用する。

## 10. ReEntry

Close直後に同じDow状態を再利用して即ReEntryしない。

```text
Target到達 / StopClose
↓
そのTrade終了
↓
同じdow_confirmation_idは使用済み
↓
新しいM5 Dow Confirmation Eventを待つ
```

通常ReEntryの最低条件。

```text
前TradeのTerminal Close後
＋
新しいM5 Dow突破確認Event成立
＋
新しいdow_confirmation_id
＋
新しい通常HSI起点
```

新しいDow確認時点ですでにR2以上なら、その確認価格でReEntryする。

```text
新しいDow確認
→ R3.5〜R4地点で成立
→ その場でReEntry
→ Target R4
```

これは、同じ確認IDを使ってR2.5 / R3 / R3.5へ階段状に入り直す処理とは異なる。

### 禁止する処理

```text
R2 Entry → R2.5 Close
→ 同じDow確認IDで即R2.5 Entry
→ R3 Close
→ 同じDow確認IDで即R3 Entry
```

### 許可する処理

```text
R2 Entry → R2.5 Close
→ 新しい押し構造
→ 新しい直前高値突破
→ 新しいDow Confirmation Event
→ 現在地点からReEntry
→ 次HSI境界Close
```

## 11. Entry Opportunity Lifecycle

```text
WAITING_R2
= Dow確認済み。確認時点でR2未到達。

USED
= Entry実行済み。同じ確認IDは再利用禁止。

MISSED
= Entry判定時にGate不成立、または次Targetなし。

EXPIRED
= 表示範囲開始前の確認、前Trade Close以前の確認、
  またはEntry前に採用Dow構造が崩壊した確認。
```

`WAITING_R2`中に、Entry根拠となったM5 Dow構造が崩壊した場合は、そのOpportunityを即時 `EXPIRED` とする。

```text
Entry前のM5 Dow構造崩壊
↓
normal_entry_opportunity = EXPIRED
採用Normal HSI Anchor = Entry判定への使用禁止
同じdow_confirmation_id = 再利用禁止
次の新しいM5 Dow Confirmationを待つ
```

崩壊の判定対象は、少なくとも次を含む。

```text
- Entry候補方向と反対方向のM5 Dow Confirmation成立
- Entry根拠となったM5 Dow構造の支持点・抵抗点が逆方向へ破綻
- 採用済みNormal HSI Anchorが、Dow構造破綻によりRetired / Invalidとなった
```

Entry後に同じ現象が発生しても、本節を理由に既存PositionをCloseしない。

```text
WAITING_R2 + Dow崩壊
→ EXPIRED

USED / IN_TRADE + Dow崩壊
→ HOLD継続
→ Trade用Anchor固定
→ Target / Stop固定
→ 自動Closeなし
```

Entry後のDow崩壊は、将来Close Strategy側で明示的に採用されない限り、Close Eventを発生させない。

1つの `dow_confirmation_id` は最大1つのOpportunityしか所有しない。

## 12. Entry Gate

通常Entry / ReEntryは次の全条件を満たす必要がある。

### Long

```text
H4 T3上向き
AND H4 Close > H4 T3
AND H4現在波 = UP
AND H4上昇波のHSI進行度 < R4
AND H1 T3上向き
AND H1 Close > H1 T3
AND H1 Cycle != Late
AND M5 Dow Up Confirmation Event
AND Confirmation方向とEntry方向が一致
AND Confirmation採用HSI起点が解決済み
AND 固定起点からR2以上
AND 通常PositionがFlat
```

### Short

```text
H4 T3下向き
AND H4 Close < H4 T3
AND H4現在波 = DOWN
AND H4下降波のHSI進行度 < R4
AND H1 T3下向き
AND H1 Close < H1 T3
AND H1 Cycle != Late
```

## 19. Dow突破確認時のEntry価格契約（v0.16）

Dow Confirmation Eventが成立したM5足で、HSI起点からR2へすでに到達している場合、通常Entry価格は確認足のCloseではない。

```text
LONG Entry価格
= max(Dow突破閾値, R2価格)

SHORT Entry価格
= min(Dow突破閾値, R2価格)
```

つまり、**Dow突破条件とR2条件の双方が初めて同時成立する価格**を通常Entry価格とする。

確認足が閾値を大きく飛び越えていても、Closeまで待ってEntry価格を悪化させない。M5足のOpenがすでに必要価格を飛び越えているギャップケースだけは、最初に利用可能なOpen価格を採用する。

```text
禁止
Dow突破確認足のCloseを無条件にEntry価格とする
```

Entry時刻は、Dow突破閾値へ実際に到達したM5足に属する。チャート上の十字カーソルで示した時刻・価格は観測補助であり、カーソル位置そのものを注文として扱わない。

```text

Dow突破閾値           153.135
確認足Close            153.498

正しい通常Entry価格   153.135
誤った通常Entry価格   153.498
```

Entry距離は153.135から再計算し、その地点より先の次HSI境界をNormal Close Targetへ固定する。

## 21. Day Up / H4調整下降R5 Short Entry Guard（v0.21）

### 21.1 目的

Day上昇トレンドの中で発生しているH4調整下降が、すでに大きく進行した後に、M5 / H1 / H4の下降整合だけを根拠として新規Short Entryすることを防ぐ。

今回の代表観測は次の構造である。

```text
Day Trend = UP
H4現在波 = DOWN（Day上昇波に対する調整下降）
H4下降波 = R5付近まで進行済み
M5 Dow Down Confirmation成立
→ 下降末期の安値圏から新規ShortしてStop Close
```

問題はShort方向の判定そのものではなく、**調整下降が十分進行した後から新規Shortしたこと**にある。

### 21.2 Guard条件

次の全条件が成立した場合、新規Short Entryを禁止する。

```text
Entry方向 = SHORT
AND Day Trend = UP
AND H4現在波 = DOWN
AND H4下降波のHSI進行度 >= R5
→ Entry NG
```

初期判定では「R5付近」を曖昧値にせず、**H4下降波がR5境界へ到達または超過した状態**として扱う。

```text
R4.5未満 / R4.5到達:
  本Guardだけでは禁止しない

R5到達以上:
  新規Short Entry禁止
```

R4.5 / R5未満のEntry可否は、各Rule Lane固有の既存Entry Gateで判断する。本Guardは、既存Gateを成立させる条件ではなく、成立済みEntry候補を最後に拒否できるGuardである。

### 21.3 H4下降波のHSI進行度

H4下降波の進行度は、現在のH4調整下降を開始した採用高値を起点として、既存のHSI Range境界で評価する。

```text
H4 Correction Anchor
= 現在のH4調整下降の起点として採用された確定高値

H4 Correction Distance
= H4 Correction AnchorからEntry候補価格までの下方向距離

H4 Correction Range Level
= 上記距離が到達した最大HSI境界
```

Entry候補時点で利用可能な確定情報だけを使い、将来足を参照してH4起点や到達境界を変更してはならない。

### 21.4 Rule Laneへの適用

v0.22以降、NORMALは本Guardを使用せず、より厳しい「H4同方向波R4 Guard」を使用する。

本Guardを維持する対象は次のとおり。

```text
EXPANSION_LITE Short Entry候補
→ EXPANSION_LITE Lane内で本Guardを評価

EXPANSION Short Entry候補
→ 将来Entry仕様を実装する際、本Guardを独立評価
```

```text
NORMAL
→ v0.22 H4同方向波R4 Guardを使用
→ 本v0.21 Guardとの二重評価はしない
```

他LaneのEntry結果、Position、Anchor、Cycle状態を参照して判定してはならない。

```text
Rule Lane完全分離
＋
同じ上位足・HSI観測事実を各Laneで独立評価
```

という契約を維持する。

### 21.5 対象範囲

本改定で禁止するのは**新規Short Entry**である。

```text
対象:
- EXPANSION_LITEの初回Short Entry
- 将来実装するEXPANSIONの初回Short Entry

本改定の対象外:
- NORMAL Entry（v0.22 H4同方向波R4 Guardで評価）
- 既存Short PositionのHold
- 既存PositionのClose / Stop / Target
- Long Entry
- Add-on条件
```

既存Positionを強制Closeする条件ではない。Add-onへの追加Guardは、本改定では定義しない。

### 21.6 判定順

本Guardは、各Rule Lane固有のEntry候補が成立した後、Entry実行直前に評価する。

```text
EXPANSION_LITE / 将来EXPANSION固有Entry Gate成立
↓
Entry候補生成
↓
Day Up / H4調整下降R5 Guard評価
↓
BLOCKならEntry不実行
ALLOWなら各Lane契約に従ってEntry実行
```

Guardで拒否されたEntry Opportunityは、同じTriggerを再利用して後続足でEntryしてはならない。

```text
EXPANSION_LITE:
  対象Entry候補をBLOCKEDとして終了
  同じDow確定と同じR3到達を再利用しない
```

### 21.7 Trace契約

Entryを拒否した場合も、次をTraceへ残す。

```text
day_trend_state
h4_wave_direction
h4_correction_anchor_time
```

## 22. NORMAL H4同方向波R4 Entry Guard（v0.22）

### 22.1 目的

NORMAL Rule Laneでは、H4・H1・M5の方向がきれいに一致していても、H4現在波がすでに大きく進行している場合、その地点から新規Entryすると高値づかみ・安値売りになりやすい。

今回の代表観測は次のとおり。

```text
H4現在波 = UP
H4上昇波 = R4以上まで進行済み
M5 Dow Up Confirmation成立
→ H4高値圏からNormal Long Entry
→ 直後に反転してCloseMiss
```

問題は方向判定ではなく、**方向は正しいが、乗る場所が遅すぎたこと**にある。

本Guardは天井・底を予測するためのルールではない。

```text
もうH4でR4まで来ている
→ 今から同方向へ乗らない
```

という、Entry地点の伸び切りを避けるための単純なGuardである。

### 22.2 Guard条件

NORMALの新規Entry候補について、次を評価する。

```text
Rule Lane = NORMAL
AND Entry方向 = H4現在波方向
AND H4現在波のHSI進行度 >= R4
→ Entry NG
```

方向別には次のとおり。

```text
LONG
AND H4現在波 = UP
AND H4上昇波のHSI進行度 >= R4
→ 新規Normal Long Entry禁止
```

```text
SHORT
AND H4現在波 = DOWN
AND H4下降波のHSI進行度 >= R4
→ 新規Normal Short Entry禁止
```

Day Trendは条件に含めない。

```text
方向が合っている
≠
Entry地点が良い
```

Day / H4 / H1 / M5の方向整合が成立していても、H4現在波がR4まで進行していれば新規NORMAL Entryを禁止する。

### 22.3 R4境界契約

初期仕様では、R4境界を厳格な禁止境界として扱う。

```text
H4現在波のHSI進行度 < R4:
  本Guardだけでは禁止しない

H4現在波がR4へ到達または超過:
  新規NORMAL Entry禁止
```

R4ちょうどへの到達もBLOCKとする。

R3.5以下のEntry可否は、既存のNORMAL Entry Gate、H1 Cycle Guard、M5 Dow Confirmation、通常HSI起点からのR2条件で判断する。

### 22.4 H4現在波とHSI進行度

本Guardで使用するH4起点は、M5 Normal HSI Anchorではない。

```text
H4現在波 = UP
H4 Wave Anchor = 現在のH4上昇波を開始した採用済み確定安値

H4現在波 = DOWN
H4 Wave Anchor = 現在のH4下降波を開始した採用済み確定高値
```

```text
H4 Wave Distance
= H4 Wave AnchorからEntry候補価格までの現在波方向距離

H4 Wave Range Level
= 上記距離が到達した最大HSI境界
```

Entry候補時点で利用可能な確定情報だけを使用する。将来足を参照してH4起点やR4到達を確定してはならない。

H4 Wave Anchorが未解決の場合は、推測で補完せず、既存のH4状態不足・判定不能契約へ従う。

### 22.5 適用範囲

本GuardはNORMAL Rule Laneの新規Entryだけに適用する。

```text
対象:
- NORMALの新規Long Entry
- NORMALの新規Short Entry

対象外:
- 既存NORMAL PositionのHold
- 既存NORMAL PositionのClose / Stop / Target
- EXPANSION_LITE Entry / Add-on / Exit
- EXPANSION Entry / Add-on / Exit
```

EXPANSION系は、伸びた波を扱う目的を持つため、NORMALのR4禁止条件を自動適用しない。

v0.21のDay Up / H4調整下降R5 Short Guardは、EXPANSION_LITEおよび将来EXPANSIONに対して従来どおり維持する。

### 22.6 判定順

```text
NORMAL固有Entry Gate成立
↓
Normal Entry候補生成
↓
H4現在波方向とEntry方向を照合
↓
H4現在波のHSI進行度を評価
↓
R4到達以上ならBLOCK
R4未到達なら既存契約に従ってEntry
```

Guardで拒否したOpportunityは、同じ `dow_confirmation_id` を後続足で再利用しない。

```text
normal_entry_opportunity = BLOCKED
または
normal_entry_opportunity = MISSED

reason_code = NORMAL_H4_SAME_DIRECTION_R4_ENTRY_BLOCKED
```

### 22.7 Trace契約

Entryを拒否した場合も、次をTraceへ残す。

```text

entry_candidate_time
entry_candidate_price
```

Reason Code:

```text

```

日本語説明:

```text

伸び切り後の新規Normal Entryを見送りました。
```

### 22.8 v0.21 Guardとの優先関係

NORMALでは、本v0.22 Guardを使用する。


```text

```

同じNORMAL Entry候補へv0.21とv0.22の両方を二重評価してはならない。

### 22.9 Day Fibonacci 0.382候補

Day上昇幅・下降幅に対するFibonacci Retracement 0.382は、上位波に対する調整進行度を補助する将来候補として保持する。

ただしv0.22では使用しない。


### 22.10 検証観点

1. NORMAL LongでH4現在波=UPかつH4進行度R4到達以上ならEntryを禁止するか。
2. NORMAL ShortでH4現在波=DOWNかつH4進行度R4到達以上ならEntryを禁止するか。
3. R4ちょうどをBLOCKとして扱うか。
4. R4未到達では、本Guardだけを理由にEntryを禁止しないか。
5. Day Trendを本Guardの条件に使用していないか。

7. EXPANSION_LITE / EXPANSIONへ本Guardを誤適用しないか。

## 23. Entry前Dow崩壊失効 / JSON固定倍率Stop（v0.23）

### 23.1 Entry前Dow崩壊によるOpportunity失効

NORMAL Entryは、M5 Dow Confirmation Eventと、その確認から採用したNormal HSI Anchorを一組のEntry根拠として扱う。

```text
M5 Dow Confirmation成立
↓
Normal HSI Anchor採用
↓
R2未到達ならWAITING_R2
```

この待機中に、Entry根拠となったM5 Dow構造が崩壊した場合、そのEntryの切符は失効する。

```text
WAITING_R2
AND Entry前にM5 Dow構造崩壊
↓
Entry Opportunity = EXPIRED
Normal HSI Anchor = Entry判定への使用禁止
同じdow_confirmation_id = 再利用禁止
後からR2へ到達してもEntryしない
```

Reason Code:

```text
NORMAL_DOW_STRUCTURE_BROKEN_BEFORE_ENTRY
```

日本語説明:

```text
Entry前にM5 Dow構造が崩壊したため、
採用済みのDow Confirmation、HSI起点、Entry Opportunityを失効しました。
後からR2へ到達しても、このEntry根拠は再利用しません。
```

Entry後のDow構造崩壊は、本ルールではClose条件にしない。

```text
Entry前の崩壊
= Entry権利の失効

Entry後の崩壊
= Close Strategy側で別途判断
```

### 23.2 max_loss_to_reward_ratioによるStop

NORMAL CloseMiss Stopは、Targetまでの利益幅を基準にする。

```text
Reward Distance
= abs(Target Price - Entry Price)

Max Loss Distance
= Reward Distance × max_loss_to_reward_ratio
```

Long:

```text
Ratio Stop Price
= Entry Price - Max Loss Distance
```

Short:

```text
Ratio Stop Price
= Entry Price + Max Loss Distance
```

通常HSI起点はHard Limitとして保持する。

```text
Long Effective Stop
= max(Ratio Stop Price, Normal HSI Anchor Price)

Short Effective Stop
= min(Ratio Stop Price, Normal HSI Anchor Price)
```

初期設定:

```json
{
  "normal": {
    "close_miss": {
      "strategy_id": "target_distance_ratio_v0_1",
      "max_loss_to_reward_ratio": 1.0,
      "hsi_anchor_hard_limit": true,
      "fix_price_at_entry": true
    }
  }
}
```

初期Draftでは、`max_loss_to_reward_ratio = 1.0` とする。

```text
Targetまでの利益幅 = 50
max_loss_to_reward_ratio = 1.0
→ 許容損失幅 = 50
```

設定値は人間がJSONで変更し、Runごとに比較する。

```text
例:
0.75 / 1.00 / 1.25 / 1.50
```

v0.23では、過去勝率から倍率を動的算出しない。勝率は、倍率候補を人間が決めるための参考値、およびシミュレーション結果の評価指標として使用する。

### 23.3 判定順

```text
新しいM5 Dow Confirmation成立
↓
Normal HSI Anchor採用
↓
Entry前Dow構造崩壊Guard
  BLOCK → Opportunity EXPIRED
  ALLOW → 次へ
↓
R2 / H4 R4 / H1 Cycle / T3などのEntry Gate評価
↓
Entry成立
↓
Target Price確定
↓
max_loss_to_reward_ratioからRatio Stop計算
↓
HSI Anchor Hard Limitと比較
↓
Effective StopをEntry時に固定
```

### 23.4 検証観点

1. `WAITING_R2`中にM5 Dow構造が崩壊した場合、後からR2へ到達してもEntryしないか。
2. 崩壊済みの `dow_confirmation_id`、Normal HSI Anchor、Opportunityを再利用しないか。
3. Entry後のDow構造崩壊を、本ルールだけで自動Closeしないか。
4. `max_loss_to_reward_ratio` をJSONから取得してStopを計算するか。
5. Long / Shortで計算方向が対称になっているか。
6. Ratio StopがNormal HSI Anchorより遠い場合、HSI起点をHard Limitとして採用するか。
7. Stop価格をEntry時に固定し、Entry後に再計算しないか。
8. TargetとStopが同一M5足で到達した場合、Stopを先に適用するか。
9. Traceへ倍率、Reward幅、Ratio Stop、HSI Hard Limit、Effective Stopを残すか。
10. 動的勝率計算をv0.23へ混入させていないか。
