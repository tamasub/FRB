## 0. まず大前提

これは売買推奨ルールではない。

```text
過去チャート上で
自分が何を見ていたのかを再現し、
Entry / Hold / Close / Reset / NoTrade を
自動シミュレーション可能な形に分解する
```

ための仮説仕様である。

今回の整理で、HSIルールは単なるEntry条件ではなく、

```text
今どの状態かを分類し、
Expansionとして扱ってよい波かを格付けし、
Entryしてよい局面かを段階的に判断する
```

状態遷移ルールとして扱う。

---

v0.4では、Entry後の管理時間足を分離した。

v0.5では、Entry RuleとClose Policyを分離し、Scale-out仮説を導入した。

v0.6では、通常M5 EntryをExpansion Entryから分離した。

v0.7では、従来のHSIルールに近づけるため、建玉管理を1 Entry / 1 Closeへ単純化した。

v0.8では、Entry頻度を確保するため、H1の方向判定もDowではなくT3へ変更する。

v0.9では、通常ルールとExpansionルールでHSI起点の扱いが混線していた差分を修正する。

v0.10では、M5 Dow成立時に比較した2つの谷・山のうち、どちらを通常HSI起点へ採用するかを明確化する。

v0.11では、通常Dow起点とExpansion Detection Anchorの解除条件を分離する。

```text
通常Dow起点:
  REVERSAL_WATCH / NO_TREND / UNDETERMINEDで解除
  同方向へ再成立しても新しいDowとしてprevious Swingを採用

Expansion Detection Anchor:
  REVERSAL_WATCH等では解除しない
  反対方向Dow成立まで大起点として維持
```

v0.12では、通常Entryを「R2初回到達を1回だけ取るルール」へ改定する。

```text
1 M5 Dow Confirmation Event
= 1 Normal HSI Anchor
= 最大1回の通常Entry機会
= R2初回到達でEntry
= R2.5で全Close
```

R2.5 Close後に、同じDow状態・同じ起点を再利用してR2.5 / R3 / R3.5から即ReEntryする処理は禁止する。

```text
通常ReEntryの最低条件:
  前TradeのTerminal Close後に
  新しいM5 Dow Confirmation Eventが成立すること
```

新しい確認Eventが成立した場合は、新しい `dow_confirmation_id` と新しいprevious Swing起点を採用し、そこから再びR2初回到達を待つ。

```text
Dow UP成立:
  previous Low → current Low（Higher Low）
  通常HSI起点 = previous Low

Dow DOWN成立:
  previous High → current High（Lower High）
  通常HSI起点 = previous High
```

成立直前のHigher Low / Lower Highではなく、ダウ波が始まった比較ペア先頭のSwingを起点にする。

```text
通常ルール:
  赤丸・緑丸の確定 = HSI起点候補
  M5 Dow Confirmation Event成立 = 比較ペア先頭のSwingをEvent用起点として採用・固定
  Event有効中の後続Swing        = 現Eventの起点を変更しない
  新しいConfirmation Event成立  = 新Event用の起点を別途採用できる

Expansionルール:
  元のDow起点をExpansion Detection Anchorとして維持
  Expansion後の押し目 / 戻り目だけ、Entry専用起点を追加採用
```

v0.9の中心原則は次のとおり。

```text
通常は起点固定。
Expansionだけ二重起点。
```

通常Entryで新しい赤丸・緑丸が確定するたびにEntry用HSI起点を最新地点へ乗り換える処理は禁止する。

```text
1 Entry ID
= 1 Position
= 1 Stop
= 1 Target
= 1回の全Close
```

1回のEntryに対するPartial Close、Runner、複数Closeは使用しない。

```text
Entry
↓
Target到達なら全建玉CloseOK
または
Entryに使用したHSI起点へ到達したら全建玉StopClose
↓
そのEntryは終了
```

通常Entryは、同時に1つだけ保有する。

```text
通常Entry:
  Add-on禁止
  Partial Close禁止
  Runner禁止
```

通常Close後の即時ReEntryは禁止する。ReEntryには、Close後に発生した新しいM5 Dow Confirmation Eventを必須とする。

Add-onはExpansion Entryだけで許可する。
ただし、Expansion Add-onも独立したEntryとして扱う。

```text
Expansion Core Entry
= 1 Stop + 1 Target + 1 Close

Expansion Add-on Entry
= 1 Stop + 1 Target + 1 Close
```

Expansion全体では複数Entryを持ちうるが、1つのEntryが複数Closeを持つことはない。

v0.12の通常M5 Entry条件は、H4/H1 T3、M5 Dow Confirmation Event、固定HSI起点からのR2初回到達を中心に判定する。

```text
通常M5 Entry
= H4 T3方向
+ H1 T3方向
+ 新しいM5 Dow Confirmation Event
+ H4 / H1 Cycle Late除外
+ Confirmation Eventに紐づく固定HSI起点からR2へ初回到達
```

H4 Dow、WEEK、DAY、Expansion Confirmedは、通常M5 Entryの必須条件にしない。

今回の目的は、完成された勝ちルールを先に作ることではない。

```text
まずEntry候補を出す
↓
チャート上で違和感を見つける
↓
「なぜここでEntryするのか」を検証する
↓
Entry条件を育てる
```

Entry回数そのものを品質とはみなさないが、検証体験を成立させるための観測目安として、
**1営業日あたり約1回**を暫定的なEntry頻度目標に置く。

## 1. 時間足の役割

### WEEK = Expansion Season / Macro Context / 高値づかみ防止ガード

WEEKは通常M5 Entryの必須条件には使わない。

WEEKの役割は、Expansion Entryを探してよい季節かを判断すること。

```text
WEEK = Expansion Entryを探してよい季節かを見る足
WEEK = 大きな方向とサイクル位置を見る足
WEEK = 高値づかみ回避のためのSeason Filter
```

```text
WEEK Cycle Early / Middle
→ Expansion Entry候補を検討してよい

WEEK Cycle Late
→ 新規Expansion Entry禁止
→ Expansion ReEntry禁止
→ Expansion Add-on禁止
→ H1弱化観測を強める（v0.8では直接Closeしない）
```

WEEK自体を直接のClose判定足にはしない。

---

### DAY = UpperMap / Expansion格付け / 管理時間足の上限

DAYも通常M5 Entryの必須条件には使わない。

DAYの役割は、H4で見えているExpansion候補が、
日足スケールでも意味のある波なのかを確認すること。

```text
DAY = 上位地図
DAY = Expansion誤判定防止フィルター
DAY = 大きな山谷・調整タイミングを見る足
DAY = Position Management Timeframeの昇格上限
```

DAYの赤丸・緑丸は、通常M5 Entry材料ではなく、
H4 Expansion候補を日足スケールで格付けするための大局材料点である。

---

### H4 = Normal方向許可 / Expansion判断 / Target候補観測

通常M5 Entryでは、H4 Dowを使わない。

H4はT3だけを使って、大きな方向を許可する。

```text
Long方向許可:
  最新確定H4 T3 > 1本前の確定H4 T3
  AND 最新確定H4 Close > 最新確定H4 T3

Short方向許可:
  最新確定H4 T3 < 1本前の確定H4 T3
  AND 最新確定H4 Close < 最新確定H4 T3

それ以外:
  H4方向未確定
  → 通常M5 Entry不可
```

H4 Dowは画面上の観測情報として残してよいが、
通常M5 Entryの許可・禁止には使用しない。

```text
H4 Dow confirmed
≠ 通常M5 Entry条件
```

一方、Expansion Entryでは引き続き、
H4構造・BB・Cycle・HSIを使って大波を判断する。

また、H4 Cycle Lateの場合は、
通常Entry / ReEntry / Expansion Add-onを含む新規建玉を禁止する。

Expansion保有中は、H4で大きな波の成熟度とTarget候補を観測する。

```text
H4 Cycle Late
+ H4 BB ContractingToMA
+ HSI Confluence
→ Expansion Target候補を強める
→ 新規Add-onを抑制する
```

ただしv0.8では、Entry後に新しいClose Eventを追加しない。Entry時に固定したTargetまたはStopで1回だけ全Closeする。

---

### H1 = T3方向確認 / Cycle Guard / Expansion観測

通常M5 Entryでは、H1 Dowを使用しない。
H1はH4と同じく、T3の傾きと確定足終値のT3上下位置で方向を判定する。

```text
Long候補:
  最新確定H1 T3 > 1本前の確定H1 T3
  AND 最新確定H1 Close > 最新確定H1 T3

Short候補:
  最新確定H1 T3 < 1本前の確定H1 T3
  AND 最新確定H1 Close < 最新確定H1 T3

それ以外:
  H1方向未確定
  → 通常M5 Entryなし
```

H4 T3とH1 T3が同じ方向になった場合だけ、M5 Dow Triggerの探索へ進む。

```text
H4 T3 UP   + H1 T3 UP   → Long方向候補
H4 T3 DOWN + H1 T3 DOWN → Short方向候補

H4/H1 T3不一致
→ 通常M5 Entryなし
```

H1 Dowは画面上の観測情報として残してよいが、通常Entryの許可・禁止には使用しない。

```text
H1 Dow confirmed
≠ 通常M5 Entry条件
```

H1 Cycle Lateの場合は、新規Entry / ReEntry / Expansion Add-onを禁止する。

Expansion保有中のH1 Structure Break / Rebound Failureは、波の弱まりを確認する観測情報として残す。

```text
H1 Structure Break / Rebound Failure
→ 新規Expansion Add-on禁止候補
→ 次回ルール改定材料
```

v0.8では、この観測だけで既存Positionを追加Closeしない。

---

### M5 = Dow実行トリガー / Entry・Close実行

M5はDow Confirmation Event、Entry / ReEntry / Expansion Add-on / CloseOK / StopCloseの実行足。

通常M5 Entryでは、M5 Dow方向がH4/H1 T3方向と一致し、かつ未使用のDow Confirmation Eventが存在することを必須とする。

```text
H4 T3で方向許可
↓
H4 / H1 Cycle Lateではない
↓
H1 T3方向確認
↓
H4/H1 T3が同方向
↓
新しいM5 Dow Confirmation Eventが成立
↓
Eventにprevious Low / previous High起点を固定
↓
固定起点からR2へ初回到達
↓
R2価格でEntry
```

M5単独ではEntryしない。

M5 Dowは次の2層に分けて扱う。

```text
M5 Dow State
= 現在の方向状態
= UP / DOWN / REVERSAL_WATCH / NO_TREND / UNDETERMINED

M5 Dow Confirmation Event
= 新しい高値・安値構造が成立した出来事
= dow_confirmation_idを一意に発行
= 通常Entry機会を最大1回だけ所有する
```

同じ `M5 Dow State = UP` が続いているだけでは、新しいReEntry権は発生しない。

v0.9では、M5 DowはEntry Triggerだけでなく、通常HSI起点の所有者でもある。

```text
赤丸 / 緑丸確定
→ HSI起点候補

M5 Dow UP / DOWN Confirmation Event成立
→ そのEventで比較した2つのSwingのうち、波の始点側を
  Normal Dow Adopted HSI Anchorとして固定

同じConfirmation Eventが有効
→ 後続Swingは候補として記録
→ 現Eventの採用済み起点は変更しない

新しいConfirmation Event成立
→ 新Event用のprevious Swing起点を別途採用できる
```

---

### 時間足の役割まとめ

```text
WEEK = Expansionの季節 / 通常Entryには使わない
DAY  = Expansion格付け / 通常Entryには使わない
H4   = T3による通常Entry方向許可 / Cycle Guard / Expansion判断
H1   = T3による通常Entry方向確認 / Cycle Guard / Expansion弱化観測
M5   = Dow実行トリガー / Entry・Close実行
```

### 通常EntryとExpansion Entryの責務分離

```text
通常M5 Entry:
  H4 T3
  + H1 T3
  + M5 Dow
  + H4/H1 Cycle Guard
  + HSI R2

Expansion Entry:
  WEEK Season
  + DAY Grade
  + H4 Structure / BB / Cycle
  + H1 Permission
  + M5 Trigger
```

## 2. DataSource / 画面構成

M5だけからH1/H4/DAY/WEEKをすべて内部生成すると、表示期間と大局判断に限界がある。
そのため、最小構成として以下を採用する。

```text
Primary DataSource = M5
UpperMap DataSource = DAY / D1
WEEK Context        = 外部DAYデータを週足へ集約
```

現時点の画面構成。

```text
Expansion検討モード:
左     H4 main review       = M5から内部生成
右上   DAY UpperMap          = 外部D1 JSONを直接参照
右下   WEEK expansion context = 外部D1 JSONから週足集約

M5実行モード:
左     M5 entry observation
右上   H1 context
右下   H4 macro context
```

重要な責務分離。

```text
D1 Data JSON
= 差し替え可能な相場データ

plugin.json
= DAY/WEEK Confirm bars、marker policy、表示期間などUI設定の正本

chart_comments.json
= HSI / コメント / 保存縦線 / サイクル線など、注釈系データの正本

URL
= 画面を開くためのView状態
```

WEEK Confirm barsはDAY Confirm barsと独立してplugin.jsonで手動調整する。
WEEK窓では大局確認を優先し、保存済み通常縦線・サイクル縦線は表示しない。

HSI系URLパラメータはLegacy扱い。  
保存済みHSIはchart_comments.jsonを正本とし、URLコピーでは基本的にHSIを正本化しない。

## 3. HSI起点の絶対ルール

Entryに使うR判定は、必ず確定済みかつルールにより採用されたHSI起点から計算する。

```text
赤丸 / 緑丸が確定した
≠ ただちにEntry用HSI起点が切り替わる
```

v0.9では、起点状態を次のように分ける。

```text
Candidate HSI Basis
= 未確定の材料点。Entry計算には使わない。

Confirmed HSI Candidate
= 赤丸 / 緑丸として確定済み。
= Dow起点またはExpansion Entry起点の候補。

Normal Dow Adopted HSI Anchor
= M5 Dow Confirmation Event成立時に、そのEventの起点として採用された固定HSI起点。
= 1つのdow_confirmation_idに紐づく。
= 通常EntryのR2初回到達判定に最大1回だけ使う。

Expansion Detection Anchor
= Expansion全体を観測する大起点。
= 元のDow起点を維持する。

Expansion Entry Anchor
= Expansion後の押し目 / 戻り目から例外的に追加採用するEntry専用起点。
= Expansion Entry / Add-onのR計算とStopに使う。

Entry Fixed HSI Anchor
= 実際のEntry成立時に、そのEntry IDへコピーして固定した起点。
= Entry後は差し替えない。
```

### 3.1 通常ルール：Dow成立時に波の始点を採用・固定する

通常ルールでは、HSI起点の所有者は「最新の赤丸・緑丸」ではなく、成立中のM5 Dow Trendである。

Dow成立時に比較する構造点を次のように置く。

```text
Dow UP:
  previous High → current High（Higher High）
  previous Low  → current Low（Higher Low）

Dow DOWN:
  previous High → current High（Lower High）
  previous Low  → current Low（Lower Low）
```

通常HSI起点へ採用するのは、成立直前の新しい押し・戻りではなく、比較ペア先頭の波の始点である。

```text
Long / M5 Dow UP成立:
  Normal Dow Adopted HSI Anchor = previous Low

Short / M5 Dow DOWN成立:
  Normal Dow Adopted HSI Anchor = previous High
```

したがって、次の選択は禁止する。

```text
Dow UP成立  → current Low（Higher Low）を通常HSI起点にする
Dow DOWN成立 → current High（Lower High）を通常HSI起点にする
```

これらのcurrent Low / current Highは、Dow成立を確認させた最後の押し・戻りであり、通常ルールにおけるダウ波の始点ではない。

採用後は、そのDow Confirmation Eventが有効な間、後続Swingだけを理由に起点を変更しない。

```text
Current Confirmation Event = UP
→ 新しいConfirmed Lowができただけ
→ 候補として記録
→ 現EventのLong用Anchorはprevious Lowのまま

Current Confirmation Event = DOWN
→ 新しいConfirmed Highができただけ
→ 候補として記録
→ 現EventのShort用Anchorはprevious Highのまま
```

ただし、新しいSwing構造から別のM5 Dow Confirmation Eventが成立した場合は、新しい `dow_confirmation_id` 用の起点を採用できる。
これは「最新Swingへの自動乗り換え」ではなく、「新しいEntry資格の発行」である。

通常Entry用Resolverで、次の処理は禁止する。

```text
新しい同方向Swingが確定
→ 最新SwingへEntry起点を自動差し替え
→ R距離をゼロ付近へリセット
```

通常EntryのR2到達は、固定されたNormal Dow Adopted HSI Anchorから計算する。

### 3.2 通常Dow起点の解除・再採用

通常Dow起点は、成立中のM5 Dow Trendにだけ所属する。
次の非方向状態へ遷移した時点で、通常Dowは終了したものとして起点を解除する。

```text
- REVERSAL_WATCH
- NO_TREND
- UNDETERMINED
```

```text
UP
→ REVERSAL_WATCH
→ 通常Dow起点を解除
→ UP再成立
→ 同じUP方向でも新しいDow
→ 新しいprevious Lowを通常HSI起点として採用
```

Shortも同様。

```text
DOWN
→ NO_TREND / REVERSAL_WATCH / UNDETERMINED
→ 通常Dow起点を解除
→ DOWN再成立
→ 新しいprevious Highを通常HSI起点として採用
```

重要。

```text
同じ方向へ戻った
≠ 同じDow Trendが継続している
```

非方向状態を挟まずUP / DOWNが継続している間だけ、通常Dow起点を維持する。

Expansionだけは例外で、元のDow起点をExpansion Detection Anchorとして保持できる。
ただし、その大起点を通常ReEntryのR計算へ流用してはならない。

### 3.3 M5 Dow Confirmation Eventと通常ReEntry

通常Entryでは、Dowの方向状態とDow確認Eventを分ける。

```text
M5 Dow State
= 現在の方向状態

M5 Dow Confirmation Event
= 新しい高値・安値構造が確定した一回限りのEntry資格
```

Confirmation Eventごとに一意なIDを持つ。

```text
dow_confirmation_id
confirmation_time
confirmation_direction
normal_hsi_anchor_id
normal_hsi_anchor_price
entry_opportunity_status
```

通常Entry機会の契約。

```text
1 dow_confirmation_id
= 1 Normal Dow Adopted HSI Anchor
= 最大1回の通常Entry
= R2初回到達だけをEntry地点とする
= Entry後はUSED
```

Entry機会の状態候補。

```text
WAITING_R2
= Dow確認済み。R2初回到達待ち。

USED
= R2初回到達でEntry済み。再利用禁止。

MISSED
= R2初回到達時に上位条件・Cycle・建玉条件が成立せず、Entryを見送った。
= R2.5やR3で遅れてEntryしない。

EXPIRED
= REVERSAL_WATCH / NO_TREND / UNDETERMINED / 反対方向Dow等で無効化。
```

通常PositionがR2.5 CloseOKまたはStopCloseで終了しても、使用済みの `dow_confirmation_id` は再利用しない。

```text
Trade終了
+ M5 Dow Stateが同じUP / DOWNのまま
≠ ReEntry許可
```

通常ReEntryの最低条件は、前TradeのTerminal Close後に新しいM5 Dow Confirmation Eventが発生すること。

```text
前Trade終了
↓
その後に新しいM5 Dow Confirmation Event成立
↓
新しいdow_confirmation_idを発行
↓
新しいprevious Low / previous Highを通常HSI起点として採用
↓
新起点からR2初回到達を待つ
↓
R2でReEntry
↓
R2.5で全Close
```

同じ方向への継続確認でも、新しいSwing構造により新しいConfirmation Eventが成立したならReEntry候補になり得る。
ただし、単に価格がR2.5、R3、R3.5へ進んだだけでは新しいConfirmation Eventとはみなさない。

```text
R2.5 Close
→ 次足もDow State = UP
→ 即ReEntry禁止

R2.5 Close
→ 新しい押し安値確定
→ 新しい高値更新でDow UP継続確認Event成立
→ 新起点R2待ち
→ ReEntry候補
```

### 3.4 Expansionだけ二重起点を許可する

Expansionは通常ルールの例外である。

```text
通常:
  1つのDow起点を固定してEntry / ReEntryを判断する

Expansion:
  元のDow起点を残したまま
  押し目 / 戻り目のEntry専用起点を追加する
```

Expansion時に起点を「差し替える」のではない。

```text
Expansion Detection Anchor
= 元のNormal Dow Adopted HSI Anchor
= 大波の起点
= Expansion判定 / 文脈 / 大きなTarget計算に使用

Expansion Entry Anchor
= Expansion後の確定押し安値 / 戻り高値
= Entry判定 / Tactical Stopに使用
```

つまり、Expansionでは次の二重構造を持つ。

```text
大起点は残す
+
Entry専用の小起点を追加する
```

新しい赤丸・緑丸をExpansion Entry Anchorとして採用できるのは、Expansion Entry Modeが成立している場合だけとする。
通常Entry Modeへ、この例外的な起点移動を流用してはならない。

### 3.5 Entry時のHSI固定契約

Entryが成立した時点で、そのEntryに使用した起点をEntry Fixed HSI Anchorとして固定する。

```text
entry_hsi_anchor_id
entry_hsi_anchor_price
stop_price
target_anchor_id
```

は同じEntry IDへ紐づける。

通常Entry。

```text
Entry Fixed HSI Anchor
= Normal Dow Adopted HSI Anchor
```

Expansion Entry / Add-on。

```text
Entry Fixed HSI Anchor
= Expansion Entry Anchor
```

Stop Price。

```text
Stop Price
= Entry Fixed HSI Anchorの価格
```

Entry後に新しい起点候補、Dow起点、Expansion Entry Anchorが確定しても、既存PositionのStopは変更しない。

```text
1 Entry ID
= 1 Entry Fixed HSI Anchor
= 1 Stop Price
= 1 Target Price
```

## 4. Position Management / Entry Unit Contract

v0.8では、管理の最小単位をTrade全体ではなくEntry単位とする。

```text
1 Entry ID
= 1 Position ID
= 1 Direction
= 1 Entry Price
= 1 Entry HSI Anchor
= 1 Stop Price
= 1 Target Price
= 1 Terminal Close Event
```

Terminal Close Eventは、次のどちらか一つ。

```text
CLOSE_OK
STOP_CLOSE / CLOSE_MISS
```

同一Entry IDでPartial Closeや複数回Closeは行わない。

### 通常Entry

```text
同時保有数 = 1
initial_units = 10
Add-on = 不可
Close = 全10単位を一度に決済
```

Close後は使用済みDow Confirmation Eventを再利用しない。前Trade終了後に新しいM5 Dow Confirmation Eventが成立した場合だけ、別TradeとしてReEntryできる。

### Expansion Entry

ExpansionではCore Entryに加えて、条件成立時だけAdd-onを許可する。

```text
Expansion Core
= 独立したEntry ID / Position ID

Expansion Add-on
= Coreとは別のEntry ID / Position ID
```

CoreとAdd-onは、それぞれ別のHSI起点・Stop・Targetを持つ。

```text
Core Entry    → Core用HSI起点でStop判定 → Core Targetで1回Close
Add-on Entry  → Add-on用HSI起点でStop判定 → Add-on Targetで1回Close
```

### Management Timeframeの扱い

Management Timeframeは、Entryの背景やExpansion文脈を記録するために保持する。
ただしv0.8では、管理時間足の昇格を理由に既存EntryのStopを広げない。

```text
H1管理からH4管理へ昇格した
→ Stopを下へ広げる
```

という損切り先延ばしは禁止。

既存EntryのStop / TargetはEntry時に固定する。
上位足の状態変化は、次のEntry・ReEntry・Expansion Add-onを許可するかどうかの判断に使う。

## 5. NoTrade / Watch を先に判定する

Entry判定では、通常M5 EntryとExpansion EntryのNoTrade条件を分ける。

### 5.1 通常M5 EntryのNoTrade

```text
1. H4 T3方向が未確定
2. H4 T3方向とH1 T3方向が不一致
3. H1 T3方向が未確定
4. M5 Dow方向がH4/H1 T3方向と不一致
5. M5 DowがREVERSAL_WATCH / NO_TREND / UNDETERMINED
6. H4 Cycle = LATE
7. H1 Cycle = LATE
8. 未使用のM5 Dow Confirmation Eventがない
9. Confirmation Eventに紐づくNormal Dow Adopted HSI Anchorがない
10. Normal Dow Adopted HSI AnchorからR2初回到達前
11. R2初回到達をすでに通過した / Entry機会がMISSED・USED・EXPIRED
12. 通常Positionをすでに保有中
13. R2 Entry Price / R2.5 Target / Stop Priceを固定できない
14. future data insufficient / 検証不能
```

通常M5 Entryでは、以下をNoTrade条件にしない。

```text
- H4 Dow Trend
- H1 Dow Trend
- WEEK Cycle
- DAY Cycle
- Expansion Confirmed
- H4 BB Opening
- DAY Expansion Grade
```

通常Entry中のAdd-onは常に禁止する。

```text
Normal Add-on Allowed = false
```

通常EntryではLate Entryも禁止する。

```text
R2を通過後に条件が揃った
→ R2.5 / R3 / R3.5で遅れてEntryしない
→ 現Confirmation EventはMISSED
→ 次のM5 Dow Confirmation Eventを待つ
```

### 5.2 Expansion Entry / Add-onのNoTrade

Expansion Entryでは、従来どおり上位足を厳しく扱う。

```text
1. WEEK Expansion Season = CLOSED
2. DAY Expansion Age = 60本超
3. H4 Trend / Structureが未確定
4. H4 Cycle = LATE
5. H1 Cycle = LATE
6. PostExpansion PullbackWindow中
7. Expansion Confirmed未成立
8. Entryに使う確定済みHSI起点がない
9. Stop Price / Target PriceをEntry時に固定できない
10. future data insufficient / 検証不能
```

Expansion Add-onは、Expansion Core保有中かつAdd-on条件成立時だけ許可する。
通常EntryをExpansion Add-onへ読み替えない。

### 5.3 Entry判定順序

```text
第0関門: Entry Modeを選ぶ
第1関門: Cycle Lateではないか
第2関門: H4/H1 T3とM5 Dow方向が一致しているか
第3関門: 未使用のM5 Dow Confirmation Eventがあるか
第4関門: Eventに紐づくNormal Dow Adopted HSI Anchorがあるか
第5関門: R2初回到達前か / Entry機会がWAITING_R2か
第6関門: R2へ初回到達したか
第7関門: 建玉状態がEntry可能か
第8関門: Entry Price = R2、Stop = HSI起点、Target = R2.5を固定できるか
```

R2初回到達時にGateを通過できなければ、そのConfirmation Eventでの通常Entryは見送る。
後からR2.5やR3でEntryしない。

## A. Normal Trend Entry

v0.12の通常M5 Entryは、H4 DowとH1 Dowを使わず、H4 T3・H1 T3・M5 Dow Confirmation Event・R2初回到達を中心に判定する。

### Long Entry

```text
H4 Direction Permission:
  最新確定H4 T3 > 1本前の確定H4 T3
  AND 最新確定H4 Close > 最新確定H4 T3

H1 Direction Permission:
  最新確定H1 T3 > 1本前の確定H1 T3
  AND 最新確定H1 Close > 最新確定H1 T3

M5 Trigger:
  新しいM5 Dow UP Confirmation Eventが成立
  AND dow_confirmation_idが未使用

Cycle Guard:
  H4 Cycle != LATE
  AND H1 Cycle != LATE

HSI:
  Event成立時のprevious LowをNormal Dow Adopted HSI Anchorとして固定
  AND Entry機会 = WAITING_R2
  AND 固定起点からLong方向へR2初回到達

Position:
  通常Positionを保有していない
```

### Short Entry

```text
H4 Direction Permission:
  最新確定H4 T3 < 1本前の確定H4 T3
  AND 最新確定H4 Close < 最新確定H4 T3

H1 Direction Permission:
  最新確定H1 T3 < 1本前の確定H1 T3
  AND 最新確定H1 Close < 最新確定H1 T3

M5 Trigger:
  新しいM5 Dow DOWN Confirmation Eventが成立
  AND dow_confirmation_idが未使用

Cycle Guard:
  H4 Cycle != LATE
  AND H1 Cycle != LATE

HSI:
  Event成立時のprevious HighをNormal Dow Adopted HSI Anchorとして固定
  AND Entry機会 = WAITING_R2
  AND 固定起点からShort方向へR2初回到達

Position:
  通常Positionを保有していない
```

### R2 First-Touch Entry Contract

通常Entry地点はR2だけとする。

```text
Long Entry Price  = Normal Dow Adopted HSI Anchorから上方向のR2価格
Short Entry Price = Normal Dow Adopted HSI Anchorから下方向のR2価格
```

```text
Dow確認後、R2へ初回到達
→ 全Gate成立
→ R2価格で10単位Entry
→ dow_confirmation_idをUSEDへ変更
```

R2を超えた実価格から遅れて入らない。

```text
R2初回到達時にEntry不可
→ Entry機会 = MISSED
→ R2.5 / R3 / R3.5で通常Entryしない
```

同一M5足でDow Confirmation Event成立とR2到達が同時に見える場合の約定順序は、未確定パラメータとしてTraceへ記録する。
初期版では未来参照を避けるため、Event成立前にR2へ触れた可能性が否定できないケースを自動的に有利約定へしない。

### 明示的に使わない条件

通常M5 Entryでは、以下を必須条件にしない。

```text
H4 Dow Trend
H1 Dow Trend
WEEK Expansion Season
DAY Expansion Grade
Expansion Confirmed
H4構造ブレイク
H4 BB Opening
```

### Cycle Guard

```text
H4 Cycle EARLY / MIDDLE → Entry可
H4 Cycle LATE           → Entry不可

H1 Cycle EARLY / MIDDLE → Entry可
H1 Cycle LATE           → Entry不可
```

CycleがUNDETERMINEDの場合は、初期版ではEntry不可として扱う。

### 通常HSI起点の採用と固定

```text
新しいM5 Dow Confirmation Event成立
→ UPはprevious Low / DOWNはprevious Highを採用
→ dow_confirmation_idへ紐づけて固定
→ R2初回到達まで維持
```

後続Swingが確定しても、現在のConfirmation Eventの起点は変更しない。
ただし、その後に新しいDow Confirmation Eventが成立した場合は、新しいEvent用の起点を別途採用できる。

### HSI Stop / Target / Close Policy

通常Entryでは、Normal Dow Adopted HSI AnchorをEntry Fixed HSI Anchorとしてコピーし、Stop Priceに固定する。

```text
Long Stop:
  stop_price = Entryに使用したprevious Low起点価格

Short Stop:
  stop_price = Entryに使用したprevious High起点価格
```

通常TargetはEntry帯によって変えない。

```text
Normal Entry = R2 Entry
Normal Target = R2.5
```

```text
Long:
  M5 High >= R2.5 target_price
  → 10単位すべてCloseOK

Short:
  M5 Low <= R2.5 target_price
  → 10単位すべてCloseOK
```

Stop判定。

```text
Long:
  M5 Low <= stop_price
  → 10単位すべてStopClose

Short:
  M5 High >= stop_price
  → 10単位すべてStopClose
```

```text
R2 Entry
↓
R2.5到達
→ 全CloseOK
→ 使用済みdow_confirmation_idは再利用しない
```

Partial Close、Target更新、Runner、同一Confirmation Eventによる階段ReEntryは使用しない。

### 検証上のEntry頻度目安

v0.12適用後はEntry回数・利益が大きく減る可能性がある。
これは同じDow確認を複数Tradeへ再利用していた利益を除去するためであり、まずは従来ルールの基準線として観測する。

```text
0.5回未満 / 営業日
→ 直ちに緩和せず、Dow Confirmation Event数・R2到達数・MISSED数を確認

0.5〜1.5回 / 営業日
→ 違和感を回収しやすい観測帯

1.5回超 / 営業日
→ Confirmation Eventの重複発行を疑う
```

## B. ReEntry / Expansion Add-on Entry

### 通常ReEntry

通常ReEntryは、R2.5 Close直後の階段Entryではない。

```text
R2 Entry
→ R2.5 Close
→ 同じDow Stateが継続
→ 即ReEntry禁止
```

通常ReEntryの最低条件。

```text
1. 前TradeがCLOSE_OKまたはSTOP_CLOSEで終了済み
2. Terminal Close時刻より後に、新しいM5 Dow Confirmation Eventが成立
3. 新しいdow_confirmation_idが発行されている
4. 新しいEventのprevious Low / previous HighをHSI起点として採用
5. H4/H1 T3方向がEvent方向と一致
6. H4/H1 Cycle != LATE
7. 新起点からR2へ初回到達
8. 通常Positionを保有していない
```

ReEntryも通常Entryと同じ1サイクルで扱う。

```text
新しいDow確認
↓
新しいHSI起点
↓
新起点R2初回到達
↓
R2でReEntry
↓
新起点R2.5で全Close
```

禁止事項。

```text
- 使用済みdow_confirmation_idの再利用
- 前TradeのHSI起点をそのまま再利用
- R2.5 Close直後、次のM5足で条件状態が残っているだけのReEntry
- R2.5 / R3 / R3.5を新しい通常Entry地点として扱う
- 新しいDow Confirmation EventなしのReEntry
```

新しいConfirmation Eventが同じUP / DOWN方向で成立することは許容する。
重要なのは方向が同じかではなく、Close後に新しい構造確認Eventが発生したかである。

```text
同じ方向
≠ 同じEntry機会

新しいDow Confirmation Event
= 新しいEntry機会
```

### 通常Add-on禁止

```text
Normal Add-on Allowed = false
```

通常Position保有中に新しいDow Confirmation Eventが発生してもAdd-onしない。
そのEventをClose後まで保留してReEntryへ流用するかは、初期版では禁止する。
ReEntryに使えるConfirmation Eventは、前TradeのTerminal Close後に成立したEventだけとする。

### Expansion Add-on

Add-onはExpansion方向だけで許可する。

```text
Expansion Add-on Allowed =
  Expansion Core Positionが存在
  AND Core Positionが含み益
  AND H4 Expansion方向と同じ
  AND WEEK Expansion Season = OPEN
  AND H4 Cycle PhaseがEarlyまたはMiddle
  AND H1 Cycle != LATE
  AND 新しい確定済み押し目 / 戻り目HSI起点がある
  AND その起点からR2到達
  AND M5 Dow confirmed
```

Add-on禁止条件。

```text
H4 Cycle Late
OR H1 Cycle Late
OR WEEK Cycle Late
OR BBが閉じ始め
OR H1高値更新失敗
OR 価格がMA/T3へ戻り始め
OR Coreが含み損
```

Expansion Add-onは、Coreへ単位を足し込むのではなく、独立Positionとして作る。

```text
Add-on Entry ID
Add-on HSI Anchor ID
Add-on Stop Price
Add-on Target Price
Add-on Units
```

を個別に固定する。

```text
1 Expansion Add-on
= 1 Entry
= 1 Stop
= 1 Target
= 1回の全Close
```

合言葉。

```text
買い増しはナンピンではない。
勝っているExpansion波にだけ追加する。
```

## C. Expansion Pullback Entry

H4でR4級のExpansionが出ても、そこで即Entryしない。

```text
R4到達 = Entryではない
R4到達 = Expansion Watch / 例外アラート
```

R4到達後に押しを待つ。

```text
Expansion Detection Anchor
= Expansion判定用の大起点

Expansion Entry Anchor
= R4到達後の直近押し安値/戻り高値

Entry Trigger Anchor
= 実際にR2判定する確定済み押し目起点
```

この起点追加はExpansion Entry Modeだけに許可する例外である。

```text
通常Trend中の新しい赤丸 / 緑丸
→ Normal Dow Adopted HSI Anchorを変更しない

Expansion成立後の押し目 / 戻り目
→ Expansion Entry Anchorとして追加採用できる
→ 元のDow起点はExpansion Detection Anchorとして残す
```

④→⑤→⑯パターンなら、

```text
④ = Expansion Detection Anchor
⑤ = Pullback / Entry Trigger Anchor
⑯ = ⑤起点R2 + M5 Dow Up confirmed
```

ただし、勝負している波は⑤ではなく④。

```text
Entry判定  = ⑤起点R2
Hold判定   = ④起点Expansion文脈
Target判定 = ④起点R5以上
```

Expansion EntryのStopは、実際のEntry判定に使用したHSI起点へ固定する。

```text
⑤ Pullback / Entry Trigger Anchor
= Expansion Core Entryに使用するHSI起点
= Expansion CoreのStop Price

④ Expansion Detection Anchor
= Expansion文脈の観測起点
= v0.8では直接のStop Priceにしない
```

Expansion Add-onも、Add-on判定に使用した新しい確定済みHSI起点を、そのAdd-on専用Stopとして固定する。

Expansion Entryでは、通常Entryより大きなTarget候補を使う。  
ただしTargetはEntry時に一つだけ固定し、到達時はそのEntryの全建玉を1回でCloseする。

```text
minimum target  = ④起点R5
extended target = ④起点R5.5 / R6 / R6.5
```

```text
Expansion Core Entry
→ Targetを一つ固定
→ Target到達でCore全建玉CloseOK

Expansion Add-on Entry
→ Add-on用Targetを一つ固定
→ Target到達でAdd-on全建玉CloseOK
```

## 7. Expansion候補の再定義

今回の整理で、Expansionは距離だけでは判定しないことが明確になった。

```text
Expansionは値幅だけでは判定しない。
DAYサイクル年齢で格付けする。
```

また、R4到達だけでExpansion候補にするのは弱い。

```text
R4到達はアラート
構造ブレイクで候補
押し戻り成功でEntry検討
DAY足で格付け
```

### Expansion Watch

```text
Expansion Watch
= 確定済み起点からR4以上に到達した状態
```

これはまだ候補ではなく、観察対象入り。

### Expansion Candidate

```text
Expansion Candidate
= R4到達
  AND H4構造ブレイク
  AND H4 BB Opening / ボラ拡大
```

H4構造ブレイク例。

```text
直近H4高値/安値を明確に抜いた
下降/上昇トレンドラインを明確に抜いた
レンジ上限/下限を抜いた
MA20/T3をまたいで反対側に定着した
BB外側に沿って走り始めた
```

### Expansion Grade

DAYで格付けする。

```text
これはH4だけの小爆発か？
それとも日足構造を変えに来ている爆発か？
```

を見る。

### Expansion Confirmed

```text
Expansion Confirmed
= Expansion Candidate
  AND 押し/戻りを作った
  AND 押し戻り後に再度継続方向へ動いた
  AND H1/H4文脈が崩れていない
```

### Expansion Invalid

```text
Expansion Invalid
= R4到達後、構造ブレイクできずレンジ回帰
  OR MA20/T3下へ戻る
  OR BB Openingが続かない
  OR DAY格付けでLate Cycle扱い
```

## 8. DAY Expansion Age Rule

今回の最重要追加ルール。

DAY Confirm=45で見ると、1サイクルがおおむね90日級に見える。
つまり、日足安値から45本を超えた場所は、上昇波の前半ではなく後半・成熟期として扱う必要がある。

Long Expansionの場合。

```text
DAY basis = 直近の日足Active Low
day_cycle_age = 現在足 - DAY basis足
```

Short Expansionの場合。

```text
DAY basis = 直近の日足Active High
day_cycle_age = 現在足 - DAY basis足
```

判定。

```text
45本以内:
  Expansion候補として見てよい

45本超え:
  だいぶ怪しい
  Expansion Grade Down / 要警戒

60本超え:
  Expansion扱いしない
  Late Cycle / 調整待ち扱い
```

これはEntry禁止ルールではなく、Expansion判定の格付けルール。

```text
45本超えだから絶対NoTrade
```

ではなく、

```text
45本超えだから、それをExpansionとして扱うのは怪しい
```

という整理。

60本超えたら、もうExpansionではない。

```text
R4到達 / H4で勢いあり
  ↓
でもDAY安値から何本経っている？
  ↓
45本以内ならExpansion候補
45本超えならLate寄り
60本超えならExpansion却下
```

### 22×2意識

```text
22営業日 ≒ 1か月
45営業日 ≒ 約2か月
```

日足で大きな山谷を見るなら、1か月単位より少し長め、つまり2か月級の確認幅が自然。

```text
DAY Confirm 45
= 日足の短期ノイズを捨てて、
  約2か月級の大きな山谷だけを材料点として見る設定
```

### DAYの右端解釈

DAY右端で、緑丸が立ったあとに価格がT3/MA20から浮き、BB上限側に寄っている場合、

```text
上昇は継続している
でも、もうすぐ調整下げが来そう
```

という絵に見える。

この感覚を可視化するために、DAY Confirm=45を暫定defaultとする。

## 9. WEEK Expansion Season / Late-Cycle Entry Guard

WEEKの季節判定は難しいため、初期版では「大波を最大限取る」より「Expansion Entry可能期間を短くする」方向へ倒す。

目的。

```text
取り逃し回避より、高値づかみ回避を優先する。
WEEKの1サイクル後半ではExpansion Entryをさせない。
```

初期状態は、まず2状態で扱う。

```text
WEEK_EXPANSION_OPEN
= Expansion Entry候補を検討してよい

WEEK_EXPANSION_CLOSED
= 新規Expansion Entry禁止
= Expansion ReEntry禁止
= Expansion Add-on禁止
= H1弱化観測を強める（v0.8では直接Closeしない）
```

将来的にはTransitionを追加してもよい。

```text
EXPANSION_ALLOWED
TRANSITION
EXIT_PERMISSION
```

### WEEK Cycle Lateの効果

```text
WEEK Cycle Late = true

Expansion Entry Allowed  = false
Expansion ReEntry Allowed = false
Expansion Add-on Allowed  = false
WEEK Direct Close         = false
H1 Early Exit Trigger     = true
```

重要。

```text
WEEK Cycle Late
≠ 即Close
```

WEEKは「もう新しく乗る季節ではない」「H1で崩れたら早めに降りてよい」という許可を出す。
実際のCloseはH1以下で判断する。

### Late判定の初期候補

最初から完全なCycle判定を目指さない。
次のような終盤要素が増えたら、保守的にCLOSEDへ倒す。

```text
- WEEK起点からの経過バー数が上限を超えた
- WEEKの高値更新 / 安値更新が鈍化した
- WEEK BBの拡大が止まり、収縮へ向かった
- WEEK MA20 / T3の傾きが鈍化した
- WEEKでミニサイクルを複数消化した
- 長期トレンドライン突破後でも、次の週足押し目時期が接近している
```

初期実装では、経過バー数など単純な条件から始め、後からOPEN期間を延長する方向で調整する。

## 15. Close / Stop Architecture

v0.8では、Close Policyを `SINGLE_CLOSE` に統一する。

```text
1 Entry ID
= 1 Stop Price
= 1 Target Price
= 1 Terminal Close Event
```

同一Entryで複数Closeを行わない。

```text
Partial Close = 使用しない
Scale-out     = 使用しない
Runner        = 使用しない
Target更新    = 使用しない
```

### 15.1 通常EntryのClose

通常EntryはR2でのみ成立し、Targetは常に同じ起点のR2.5とする。

```text
R2 Entry
→ R2.5 Close
```

次の階段は通常ルールに存在しない。

```text
R2.5 Entry → R3 Close     = 禁止
R3 Entry   → R3.5 Close   = 禁止
R3.5 Entry → R4 Close     = 禁止
```

10単位でEntryした場合、R2.5到達で10単位すべてCloseOKする。

```text
Entry 10単位 @ R2
↓
R2.5到達
↓
CloseOK 10単位
↓
Position = Flat
↓
使用済みDow Confirmation Eventは終了
↓
次のM5 Dow Confirmation Eventを待つ
```

### 15.2 通常EntryのStop

StopはEntryに使用したHSI起点価格へ固定する。

```text
Long:
  M5 Low <= Entry HSI Anchor Price
  → 10単位すべてStopClose

Short:
  M5 High >= Entry HSI Anchor Price
  → 10単位すべてStopClose
```

Entry後に別のHSI起点が確定しても、既存EntryのStopを変更しない。

### 15.3 Expansion Core / Add-onのClose

Expansion CoreとExpansion Add-onは、Expansionグループとして関連づける。
ただしPositionは混ぜない。

```text
Expansion Group
  Core Entry     = 独立Position
  Add-on Entry 1 = 独立Position
  Add-on Entry 2 = 独立Position
```

各Positionは、Entry時に一つのTargetを固定し、Target到達で全単位を1回Closeする。

```text
Core Entry
→ Core Target到達
→ Core全単位CloseOK

Add-on Entry
→ Add-on Target到達
→ Add-on全単位CloseOK
```

### 15.4 Expansion Core / Add-onのStop

Expansion Coreは、Core Entryに使用したPullback / Entry Trigger HSI起点をStopにする。

Expansion Add-onは、Add-on Entryに使用した新しい確定済みHSI起点をStopにする。

```text
Core Stop
= Core Entry HSI Anchor

Add-on Stop
= Add-on Entry HSI Anchor
```

Expansion Detection Anchorは大波の文脈観測に使用するが、v0.8では既存PositionのStopを広げる理由にはしない。

### 15.5 H4 / H1 Profit-Take情報の扱い

H4 Cycle、BB Phase、HSI Confluence、H1 Structure Breakは、ExpansionのTarget選択や次のAdd-on可否を考える観測情報として残す。

ただしv0.8では、Entry後に別のClose Eventを追加するためには使わない。

```text
Entry時:
  StopとTargetを固定

Entry後:
  Target到達 → CloseOK
  Stop到達   → StopClose
```

H1/H4構造Exitを再導入する場合は、Single Close契約を壊さず、TargetまたはStopと競合しない独立ルールとして将来検討する。

### 15.6 同一M5足でStopとTargetの両方へ到達した場合

同一M5足内の到達順序はOHLCだけでは分からない。
このケースの優先順位は未確定パラメータとして記録し、Simulation Traceに `AMBIGUOUS_STOP_TARGET` を残す。

初期結果へ都合よくCloseOKを採用しない。

### 15.7 Close理由コード

```text
CLOSE_OK_NEXT_HSI_TARGET
STOP_CLOSE_ENTRY_HSI_ANCHOR
AMBIGUOUS_STOP_TARGET
```

表示例。

```text
R2.5到達：10単位全決済

または

Entry HSI起点 158.305到達：10単位StopClose
```

```text

↓
Confirmed Swing
  赤丸 / 緑丸 = HSI起点候補
↓
新しいM5 Dow Confirmation Event成立
  dow_confirmation_idを発行
  UPはprevious Low / DOWNはprevious Highを
  Normal Dow Adopted HSI Anchorとして固定
  Entry Opportunity = WAITING_R2
↓
H4 T3 Direction Permission
  LONG / SHORT / UNDETERMINED
↓
H4 / H1 Cycle Guard
  EARLY / MIDDLE = 継続
  LATE / UNDETERMINED = NoEntry
↓
H1 T3 Direction Permission
↓
H4/H1 T3とConfirmation Event方向が一致
↓
固定起点からR2へ初回到達
↓
全Gate成立
  Entry Price = R2
  Stop = Entry Fixed HSI Anchor
  Target = R2.5
  Entry Opportunity = USED
↓
Normal Entry 10単位
↓
R2.5到達 → 10単位CloseOK → Flat
または
Stop到達 → 10単位StopClose → Flat
↓
同じDow Stateが継続していても待機
  使用済みdow_confirmation_idは再利用しない

  新しいprevious Swing起点
```

R2初回到達時にGate不成立なら、Entry Opportunity = MISSEDとして、そのEventでのLate Entryを禁止する。
通常LaneにAdd-onと階段ReEntryは存在しない。

### 17.2 Expansion Entry Lane

```text

↓

↓

↓

↓

↓
M5 Trigger
↓

  Stop = Expansion Entry Anchor

↓
Expansion継続中のみAdd-on候補
↓
新しい押し / 戻り起点をAdd-on専用Expansion Entry Anchorとして採用
↓
Core / Add-onを独立Positionとして管理
↓
各PositionがTargetまたはStopで1回だけ全Close
```

```text

= 通常Entryの中間方向許可

= 通常Entryには使わない
```

## 20. 今日の結論

v0.12の最大変更は、通常Entryを「R2以上ならいつでも入れる状態判定」から、「新しいDow確認ごとにR2初回到達を一度だけ取るEvent駆動ルール」へ変更したこと。

これまでの通常Entryは、同じM5 Dow Stateと同じHSI起点を再利用し、次のような階段Tradeを許していた。

```text
R2帯 Entry → R2.5 Close
R2.5帯 ReEntry → R3 Close
R3帯 ReEntry → R3.5 Close
R3.5帯 ReEntry → R4 Close
```

しかし、この動きではR2.5で一度Closeする意味が薄くなり、同じDow確認を複数のEntry判断として数えることになる。

v0.12では次のように改定する。

```text
新しいM5 Dow Confirmation Event
↓
一意なdow_confirmation_id
↓
UPはprevious Low / DOWNはprevious HighをHSI起点として固定
↓
固定起点からR2へ初回到達
↓
R2価格で10単位Entry
↓
R2.5で10単位全Close
↓
そのdow_confirmation_idは使用済み
↓
同じDow Stateが続いても即ReEntryしない
↓
前Trade終了後の新しいM5 Dow Confirmation Eventを待つ
```

通常ReEntryも、毎回ゼロから同じ形を作る。

```text
新しいDow確認
→ 新しいHSI起点
→ 新起点R2 Entry
→ 新起点R2.5 Close
```

重要な言い換え。

```text
同じDow方向が続いている
≠ 新しいEntry機会がある

新しいM5 Dow Confirmation Eventが成立した
= 新しいEntry機会が生まれた
```

R2初回到達時に条件が揃わなければ、そのEventでの通常Entryは見送る。
R2を通過した後、R2.5やR3で遅れてEntryしない。

この改定により、Entry回数と利益は大きく減る可能性がある。
ただし、それは同じDow確認を何度もTradeへ再利用していた利益を剥がし、従来の思考に近い基準線へ戻すための変更である。

Expansionルールは別Laneとして維持する。

```text
通常:
  1 Dow Confirmation Event
  → R2 Entry
  → R2.5 Close
  → 1回で終了

Expansion:
  大起点をDetection Anchorとして維持
  + 押し / 戻りのEntry Anchorを追加
  + Core / Add-on / 大きなTargetを別ルールで扱う
```

v0.12の通常Entry原則。

```text
通常は、R2を一度だけ取る。
ReEntryは、次のDow確認を待つ。
Expansionだけ、別の伸ばし方を設計する。
```
