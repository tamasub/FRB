## 0. 大前提

これは売買推奨ルールではない。

```text
過去チャート上で
自分が何を見ていたのかを再現し、
Entry / Hold / Close / Reset / NoTrade を
自動シミュレーション可能な形へ分解する
```

ための仮説仕様である。

v0.21では、Day上昇トレンド中にH4調整下降がR5以上まで進行した後の、新規Short Entryを禁止する。

```text
Entry方向 = SHORT
AND Day Trend = UP
AND H4現在波 = DOWN
AND H4下降波のHSI進行度 >= R5
→ 新規Short Entry禁止
```

このGuardは、下降方向そのものを否定するものではない。Day上昇トレンド内の調整下降が十分進んだ後に、安値圏から遅れてShortへ入ることを防ぐための上位足・HSI進行度Guardである。


v0.19では、NORMAL Rule LaneのCycle Late Guardを改定する。

```text
変更前: H4 / H1 Cycle Lateで通常Entry禁止
変更後: H1 Cycle Lateだけで通常Entry禁止
```

H4 Cycleは通常Entryの観測情報として残すが、通常Entryの禁止条件には使用しない。EXPANSION / EXPANSION_LITEの条件には一切影響させない。

最重要原則は、**Rule Lane間でEntry / Add-on / Exit / Anchor Lifecycleを混ぜないこと**である。

最重要変更は次のとおり。

```text
M5 Dow Confirmation成立
→ その確認の根拠となるprevious Swingを通常HSI起点として採用
→ Normal Entry
→ CloseOK または CloseMiss
→ その瞬間に通常HSI起点を破棄
→ Close後の新しいM5 Dow Confirmationを待つ
→ 新しいprevious Swingから次の通常HSI起点を採用
```

通常HSI起点をClose後も維持する考え方はExpansion専用であり、NORMAL Rule Laneへ混ぜない。

```text
確定済みの押し安値 / 戻り高値
↓
直前構造高値 / 安値をM5確定足で突破
↓
M5 Dow Confirmation Event成立
↓
その時点ですでにR2以上なら即Entry
↓
実Entry地点より先の次HSI境界で全Close
```

このv0.15の定義は、v0.14のEntry / Close条件を引き継ぎ、NORMAL Rule Laneの語彙とLifecycleを上書きする。

## 0.1 Rule Laneごとの語彙境界

```text
NORMAL Rule Lane
- Entry
- Hold
- CloseOK
- CloseMiss
- Reset / Wait / Missed / Expired

NORMAL Rule Laneでは使わない
- ReEntry
- Add-on
- Expansion Core
- Expansion Detection Anchor
- Expansion Entry Anchor
```

NORMAL Rule Laneでは、過去に通常Tradeが完了しているかどうかに関係なく、新しいM5 Dow Confirmation Eventから成立したTradeはすべて独立した **Normal Entry** と呼ぶ。

```text
Normal Entry #1
→ Close
→ 新しいM5 Dow Confirmation Event
→ Normal Entry #2
→ Close
```

これは `ReEntry` ではない。回数識別が必要な場合は `normal_entry_sequence_no` を使用する。

```text
1 Dow Confirmation Event
= 最大1 Normal Entry Opportunity
= 最大1 Normal Entry
```

前回Trade終了後の次のNormal Entryには、新しいM5 Dow Confirmation Eventが必要である。ただし、この制約をReEntry条件とは呼ばない。

`ReEntry` と `Add-on` は、今後定義するExpansion / Expansion-Lite Rule Laneの専用語として予約する。NORMAL Rule Laneの判定・表示・集計・Traceへ混ぜてはならない。

## 0.2 Rule Lane完全分離原則（v0.18）

```text
NORMAL
EXPANSION
EXPANSION_LITE
```

各Rule Laneは、次の要素を独立して所有する。

```text
Entry Gate
Entry Trigger
Entry Price契約
Anchor Lifecycle
Add-on条件
Exit条件
Action語彙
Trade Lifecycle
Trace / 集計
```

共有してよいのは、ローソク足、T3、HSI境界、Cycle位置、確定済みDow点などの**観測事実**だけである。

```text
禁止
- 他LaneのEntry条件を補完利用する
- 他LaneのExit条件へFallbackする
- 他LaneのAnchorを流用する
- 未定義部分をNORMAL Rule Laneの契約で埋める
```

EXPANSION_LITEの仕様が未定義の場合は、他Laneのルールを流用せず、判定不能として扱う。

## 1. v0.14の変更理由

v0.13では、M5 Dow Confirmation EventをHigh / Low比較ペアが完成した時点で発行していた。

しかし実際に人間が見ていたDow Up確定は、単にHigher Lowが確認された時点ではない。

```text
押し安値が確定
＋
その後に直前高値を上抜く
＝ Dow Up確定
```

Dow Downは対称形である。

```text
戻り高値が確定
＋
その後に直前安値を下抜く
＝ Dow Down確定
```

したがって、通常Entryの切符となるDow Confirmation Eventは、Swing比較ペアの完成時ではなく、**構造高値 / 安値の突破時**に発行する。

## 2. 時間足の役割

```text
WEEK = Expansion Season / 高値づかみ防止
DAY  = Expansion格付け / 上位地図
H4   = T3による通常方向許可 / Expansion判断
H1   = T3による通常方向確認 / 通常Cycle Guard / Expansion観測
M5   = Dow Confirmation Event / Entry / Closeの実行
```

通常M5 Entryの必須要素は次のとおり。

```text
H4 T3方向
＋ H4 CloseのT3上下位置
＋ H1 T3方向
＋ H1 CloseのT3上下位置
＋ H1 Cycle Late除外
＋ M5 Dow Confirmation Event
＋ 確定HSI起点からR2以上
```

H4 Dow、H1 Dow、WEEK、DAY、Expansion Confirmedは通常M5 Entryの必須条件にしない。

## 3. M5 Dow StateとDow Confirmation Eventを分ける

### 3.1 M5 Dow State

```text
UP
DOWN
REVERSAL_WATCH
NO_TREND
UNDETERMINED
```

現在の方向状態を表す。

### 3.2 M5 Dow Confirmation Event

新しい構造が確定した出来事を表す。

```text
1 Dow Confirmation Event
= 1 dow_confirmation_id
= 1 HSI起点
= 最大1回の通常Entry機会
```

同じ `Dow State = UP` が続いていても、新しいDow Confirmation Eventがなければ次のNormal Entry Opportunityは発生しない。

## 4. Dow Up Confirmation

Long側の確認順序。

```text
① previous Lowがある
② その後に直前構造Highが形成される
③ さらにHigher Lowが確定する
④ ④以降のM5確定足が、②の構造Highを上抜く
⑤ そのM5確定足でDow Up Confirmation Event成立
```

HSI起点は、Higher Lowそのものではない。

```text
Normal HSI Anchor = previous Low
```

つまり、押し安値へ起点を乗り換えるのではなく、今回のDow波が始まった比較ペア先頭のLowを採用する。

---

## 5. Dow Down Confirmation

Short側は対称形。

```text
① previous Highがある
② その後に直前構造Lowが形成される
③ さらにLower Highが確定する
④ ④以降のM5確定足が、②の構造Lowを下抜く
⑤ そのM5確定足でDow Down Confirmation Event成立
```

```text
Normal HSI Anchor = previous High
```

## 6. 通常HSI起点Lifecycle（v0.17）

通常HSI起点は、Normal Tradeごとの一時的な基準点である。

```text
1 M5 Dow Confirmation Event
= 1 Normal HSI Anchor
= 最大1 Normal Entry
= 1 Normal Close
= Close時にAnchor破棄
```

### 6.1 起点の採用

```text
Close後に新しいM5 Dow Up確認
→ その確認の根拠となるprevious Lowを採用

Close後に新しいM5 Dow Down確認
→ その確認の根拠となるprevious Highを採用
```

### 6.2 Entry中

Entry時に採用した通常HSI起点は、次の用途だけに固定する。

```text
Entry距離計算
Stop価格
Close Target計算
当該Tradeの判断Trace
```

Entry中に別の同方向Dow Confirmationが発生しても、次回Trade用の起点として先取りしない。

### 6.3 Close時

```text
CloseOK
または
CloseMiss
↓
normal_hsi_anchor = NONE
normal_entry_opportunity = NONE
next_state = WAIT_NEW_M5_DOW_CONFIRMATION
```

Close済み通常HSI起点を、次回Normal Entryへ再利用してはならない。

### 6.4 次の通常Entry

次の通常Entryは、前TradeのClose後に成立した新しいM5 Dow Confirmation Eventが必須である。

```text
前Trade Close
↓
新しいM5 Dow Confirmation
↓
新しいprevious Swing
↓
新しいNormal HSI Anchor
↓
新しいNormal Entry
```

同じ方向へのEntryであっても、新しい独立Tradeとして扱う。ReEntryとは呼ばない。

### 6.5 Expansionとの分離

```text
NORMAL
Trade Closeで通常HSI起点を破棄

EXPANSION
Detection Anchorを大波追跡用に維持する場合がある
```

Expansion Detection Anchor、Expansion Entry Anchor、Expansion-Lite AnchorをNormal Entry判定へ流用してはならない。

## 7. 通常Entryの判定順

### 7.1 Dow確認時点でR2未到達

```text
M5 Dow Confirmation Event成立
↓
固定HSI起点からR2未到達
↓
Entry Opportunity = WAITING_R2
↓
確認後のR2初回到達
↓
全Gate成立ならR2境界価格でEntry
```

R2初回到達時にGate不成立なら、そのOpportunityは `MISSED` とする。

### 7.2 Dow確認時点ですでにR2以上

```text
M5 Dow Confirmation Event成立
↓
固定HSI起点からR2以上
↓
Dow確認成立を最後のTriggerとして即Entry
```

これは遅れEntryではない。

```text
HSI距離条件は先に成立済み
＋
最後に不足していたDow確認が成立
＝ 即Entry
```

Entry価格はR2境界へ遡らない。

```text
Entry Price = Dow突破確認M5確定足の利用可能価格
```

初期実装では確定足Closeを使用する。

## 8. 通常Target

v0.13の「通常Targetは常にR2.5」を廃止する。

v0.14では、実Entry地点より先に残っている**次のHSI境界**をTargetとして固定する。

```text
Entry距離がR2〜R2.5
→ Target R2.5

Entry距離がR2.5〜R3
→ Target R3

Entry距離がR3〜R3.5
→ Target R3.5

Entry距離がR3.5〜R4
→ Target R4
```

同様に以後の境界へ続く。

Entry時にTargetを一つだけ固定し、到達時は10単位を全Closeする。

```text
1 Entry ID
= 1 Position
= 1 Stop
= 1 Target
= 1回の全Close
```

Partial Close、Runner、通常Add-onは使用しない。

---

## 9. Stop

```text
Stop Price = Entryに使用した通常HSI起点
```

Entry後に新しいSwingが確定しても、既存PositionのStopは移動しない。

Target / Stop到達判定はM5 High / Lowを使用する。

同一M5足でTargetとStopの両方へ到達した場合は、保守的にStopを先に適用する。

## 10. ReEntry

Close直後に同じDow状態を再利用して即ReEntryしない。

```text
Target到達 / StopClose
↓
そのTrade終了
↓
同じdow_confirmation_idは使用済み
↓
新しいM5 Dow Confirmation Eventを待つ
```

通常ReEntryの最低条件。

```text
前TradeのTerminal Close後
＋
新しいM5 Dow突破確認Event成立
＋
新しいdow_confirmation_id
＋
新しい通常HSI起点
```

新しいDow確認時点ですでにR2以上なら、その確認価格でReEntryする。

```text
新しいDow確認
→ R3.5〜R4地点で成立
→ その場でReEntry
→ Target R4
```

これは、同じ確認IDを使ってR2.5 / R3 / R3.5へ階段状に入り直す処理とは異なる。

### 禁止する処理

```text
R2 Entry → R2.5 Close
→ 同じDow確認IDで即R2.5 Entry
→ R3 Close
→ 同じDow確認IDで即R3 Entry
```

### 許可する処理

```text
R2 Entry → R2.5 Close
→ 新しい押し構造
→ 新しい直前高値突破
→ 新しいDow Confirmation Event
→ 現在地点からReEntry
→ 次HSI境界Close
```

## 11. Entry Opportunity Lifecycle

```text
WAITING_R2
= Dow確認済み。確認時点でR2未到達。

USED
= Entry実行済み。同じ確認IDは再利用禁止。

MISSED
= Entry判定時にGate不成立、または次Targetなし。

EXPIRED
= 表示範囲開始前の確認、前Trade Close以前の確認など。
```

1つの `dow_confirmation_id` は最大1つのOpportunityしか所有しない。

## 12. Entry Gate

通常Entry / ReEntryは次の全条件を満たす必要がある。

### Long

```text
H4 T3上向き
AND H4 Close > H4 T3
AND H1 T3上向き
AND H1 Close > H1 T3
AND H1 Cycle != Late
AND M5 Dow Up Confirmation Event
AND Confirmation方向とEntry方向が一致
AND Confirmation採用HSI起点が解決済み
AND 固定起点からR2以上
AND 通常PositionがFlat
```

### Short

```text
H4 T3下向き
AND H4 Close < H4 T3
AND H1 T3下向き
AND H1 Close < H1 T3
AND H1 Cycle != Late
AND M5 Dow Down Confirmation Event
AND Confirmation方向とEntry方向が一致
AND Confirmation採用HSI起点が解決済み
AND 固定起点からR2以上
AND 通常PositionがFlat
```

今回の観測例。

```text
通常HSI起点
= 2025-10-30 06:10 Low
= 152.164

直前構造高値
= 2025-10-30 06:30 High
= 153.135

Higher Low
= 2025-10-30 07:25 Low
= 152.560

Dow Up突破確認足
= 2025-10-30 09:40
High  = 153.513
Close = 153.498
```

09:40のM5確定足が構造高値153.135を上抜いた時点でDow Up確定。

```text
HSI起点 152.164
Entry価格 153.498
Entry距離 raw ≒ 222.3
```

これはR3.5〜R4帯にある。

```text
Dow確認時点でR2以上
→ 153.498で即Entry

次HSI境界
→ R4
→ Target 153.562
```

したがって、図㉘では通常Entryが発生しなければならない。

## 14. Expansionとの責務分離

通常EntryとExpansion Entryを混ぜない。

```text
通常Entry
= 新しいM5 Dow突破確認
+ 通常HSI起点
+ R2以上
+ 次HSI境界Target

Expansion Entry
= WEEK Season
+ DAY Grade
+ H4 Structure / BB / Cycle
+ H1 Permission
+ M5 Trigger
+ Expansion Detection Anchor
+ Expansion Entry Anchor
```

Expansionのみ二重起点を持ち得る。

```text
大起点
= Expansion Detection / 大波Target用

小起点
= Expansion Entry / Stop用
```

Expansion Core / Expansion Add-onの実行条件は未確定・未実装のままとする。

## 15. NORMAL Rule Laneの実装契約（v0.15追加）

```text
Entry Evaluator Action
= ENTRYのみ

Close Evaluator Action
= FULL_CLOSE / STOP_CLOSE / WAIT

禁止Action
= REENTRY / ADD_ON
```

通常Entry Eventはすべて次の形式で記録する。

```json
{
  "rule_lane": "NORMAL",
  "event_type": "entry",
  "execution": {
    "action": "ENTRY",
    "normal_entry_sequence_no": 1
  }
}
```

Run集計では、NORMAL Laneの全Entryを `Entry` に合算する。`ReEntry` 件数へ含めない。

Close判定はEntry Rule Laneに従い、NORMAL Entryから生まれた建玉は必ずNormal Close Evaluatorで評価する。Expansion / Expansion-LiteのClose条件を参照しない。

## 19. Dow突破確認時のEntry価格契約（v0.16）

Dow Confirmation Eventが成立したM5足で、HSI起点からR2へすでに到達している場合、通常Entry価格は確認足のCloseではない。

```text
LONG Entry価格
= max(Dow突破閾値, R2価格)

SHORT Entry価格
= min(Dow突破閾値, R2価格)
```

つまり、**Dow突破条件とR2条件の双方が初めて同時成立する価格**を通常Entry価格とする。

確認足が閾値を大きく飛び越えていても、Closeまで待ってEntry価格を悪化させない。M5足のOpenがすでに必要価格を飛び越えているギャップケースだけは、最初に利用可能なOpen価格を採用する。

```text
禁止
Dow突破確認足のCloseを無条件にEntry価格とする
```

Entry時刻は、Dow突破閾値へ実際に到達したM5足に属する。チャート上の十字カーソルで示した時刻・価格は観測補助であり、カーソル位置そのものを注文として扱わない。

### 具体例

```text
Normal HSI起点       152.164
R2                    152.698
Dow突破閾値           153.135
確認足Close            153.498

正しい通常Entry価格   153.135
誤った通常Entry価格   153.498
```

Entry距離は153.135から再計算し、その地点より先の次HSI境界をNormal Close Targetへ固定する。

- 次の通常HSI起点は、新しいDow Confirmationの根拠となるprevious Low / previous Highから採用する。
- Close後の通常HSI起点再利用を禁止する。
- ExpansionのDetection Anchor維持ルールをNORMAL Rule Laneへ混ぜない。
- HSI境界ぴったりでEntryした場合も、Targetを同一境界ではなく次の境界へ進める浮動小数点境界補正を明記する。

## 20. Expansion-Lite Rule Lane（v0.18）

### 20.1 目的と境界

```text
rule_lane = EXPANSION_LITE
方向 = Long / Short
目的 = R3からEntryし、R5までのExpansion波を取る
Dayサイクル位置条件 = 使用しない
```

EXPANSION_LITEは独立Rule Laneであり、NORMAL / EXPANSIONのEntry・Add-on・Exit・Anchor Lifecycleを参照しない。

### 20.2 Entry前提

```text
Long
H4 Close >= H4 T3
AND H1 Close >= H1 T3
AND H1 Cycle起点から14本以内

Short
H4 Close <= H4 T3
AND H1 Close <= H1 T3
AND H1 Cycle起点から14本以内
```

H1 Cycle Entry Windowは、Longでは採用安値、Shortでは採用高値から14本以内とする。Confirm barsはSwing確定用であり、Entry許可本数の計算には使用しない。

### 20.3 Entry

```text
Long
M5 DowUp確定
AND 採用Dow HSI起点からR3へタッチ

Short
M5 DowDown確定
AND 採用Dow HSI起点から下方向R3へタッチ
```

成立順は両方許可する。

```text
A. Dow確定時点でR3タッチ済み
   → Dow確定時にEntry

B. Dow確定後にR3へ初タッチ
   → R3初回タッチ時にEntry
```

### 20.4 Add-on

```text
R3.5タッチ → Add-on
R4タッチ   → Add-on
R4.5タッチ → Add-on
```

各境界につき1回だけ実行し、Add-on上限はR4.5とする。

### 20.5 Exit

すべてのExitは、EXPANSION_LITEの全建玉をCloseする。

```text
Target Exit
R5タッチ
→ 全建玉Close
```

```text
T3 Exit
Long  = M5 Low < M5 T3
Short = M5 High > M5 T3
→ 全建玉Close
```

```text
Structural Exit
新しいM5 Dow点が確定し、
それまでのDow構造が破綻
→ 全建玉Close
```

```text
Anchor Exit
Long  = M5 Low < 採用HSI起点
Short = M5 High > 採用HSI起点
→ 全建玉Close
```

### 20.6 最終要約

```text
H4・H1のCloseがT3方向に整合し、
H1 Cycle起点から14本以内で、M5 Dow確定後のR3タッチからEntryする。
R3.5 / R4 / R4.5タッチで各1回Add-onし、R5をTargetとする。
R5タッチ、M5 T3逆抜け、M5 Dow構造破綻、採用HSI起点逆抜けの
いずれかで全建玉Closeする。

他Rule Laneの条件・Lifecycle・Exit契約は混ぜない。
```

### 20.7 Rule Laneパラレル走行原則

```text
Rule Laneの完全分離
≠
Rule Laneの排他実行
```

NORMAL / EXPANSION / EXPANSION_LITEは、同じM5足でそれぞれ独立評価する。
複数LaneのEntry条件が同時に成立した場合、成立したEntryをすべて実行する。

```text
NORMAL Entry成立
AND Expansion-Lite Entry成立
→ 両方Entry

NORMAL Entry成立
AND Expansion Entry成立
AND Expansion-Lite Entry成立
→ 3つすべてEntry
```

各Rule Laneは、次の状態を個別に所有する。

```text
Entry条件
HSI起点
Entry Opportunity
Trade / Position
Add-on履歴
Close条件
Exit理由
```

あるRule Laneの建玉保有を理由に、別Rule LaneのEntryを禁止してはならない。
各建玉は、EntryしたRule Lane専用のClose Evaluatorだけで終了する。

EXPANSIONの具体的Entry条件が未実装の期間も、並列実行可能な独立Laneとして契約を維持する。

## 21. Day Up / H4調整下降R5 Short Entry Guard（v0.21）

### 21.1 目的

Day上昇トレンドの中で発生しているH4調整下降が、すでに大きく進行した後に、M5 / H1 / H4の下降整合だけを根拠として新規Short Entryすることを防ぐ。

今回の代表観測は次の構造である。

```text
Day Trend = UP
H4現在波 = DOWN（Day上昇波に対する調整下降）
H4下降波 = R5付近まで進行済み
M5 Dow Down Confirmation成立
→ 下降末期の安値圏から新規ShortしてStop Close
```

問題はShort方向の判定そのものではなく、**調整下降が十分進行した後から新規Shortしたこと**にある。

### 21.2 Guard条件

次の全条件が成立した場合、新規Short Entryを禁止する。

```text
Entry方向 = SHORT
AND Day Trend = UP
AND H4現在波 = DOWN
AND H4下降波のHSI進行度 >= R5
→ Entry NG
```

初期判定では「R5付近」を曖昧値にせず、**H4下降波がR5境界へ到達または超過した状態**として扱う。

```text
R4.5未満 / R4.5到達:
  本Guardだけでは禁止しない

R5到達以上:
  新規Short Entry禁止
```

R4.5 / R5未満のEntry可否は、各Rule Lane固有の既存Entry Gateで判断する。本Guardは、既存Gateを成立させる条件ではなく、成立済みEntry候補を最後に拒否できるGuardである。

### 21.3 H4下降波のHSI進行度

H4下降波の進行度は、現在のH4調整下降を開始した採用高値を起点として、既存のHSI Range境界で評価する。

```text
H4 Correction Anchor
= 現在のH4調整下降の起点として採用された確定高値

H4 Correction Distance
= H4 Correction AnchorからEntry候補価格までの下方向距離

H4 Correction Range Level
= 上記距離が到達した最大HSI境界
```

Entry候補時点で利用可能な確定情報だけを使い、将来足を参照してH4起点や到達境界を変更してはならない。

### 21.4 Rule Laneへの適用

本Guardは共通観測条件として定義するが、各Rule Laneが独立して評価する。

```text
NORMAL Short Entry候補
→ NORMAL Lane内で本Guardを評価

EXPANSION_LITE Short Entry候補
→ EXPANSION_LITE Lane内で本Guardを評価

EXPANSION Short Entry候補
→ 将来Entry仕様を実装する際、本Guardを独立評価
```

他LaneのEntry結果、Position、Anchor、Cycle状態を参照して判定してはならない。

```text
Rule Lane完全分離
＋
同じ上位足・HSI観測事実を各Laneで独立評価
```

という契約を維持する。

### 21.5 対象範囲

本改定で禁止するのは**新規Short Entry**である。

```text
対象:
- NORMALの新規Short Entry
- EXPANSION_LITEの初回Short Entry
- 将来実装するEXPANSIONの初回Short Entry

本改定の対象外:
- 既存Short PositionのHold
- 既存PositionのClose / Stop / Target
- Long Entry
- Add-on条件
```

既存Positionを強制Closeする条件ではない。Add-onへの追加Guardは、本改定では定義しない。

### 21.6 判定順

本Guardは、各Rule Lane固有のEntry候補が成立した後、Entry実行直前に評価する。

```text
各Rule Lane固有Entry Gate成立
↓
Entry候補生成
↓
Day Up / H4調整下降R5 Guard評価
↓
BLOCKならEntry不実行
ALLOWなら各Lane契約に従ってEntry実行
```

Guardで拒否されたEntry Opportunityは、同じTriggerを再利用して後続足でEntryしてはならない。

```text
NORMAL:
  対象dow_confirmation_idのOpportunityをMISSED / BLOCKEDとして終了

EXPANSION_LITE:
  対象Entry候補をBLOCKEDとして終了
  同じDow確定と同じR3到達を再利用しない
```

### 21.7 Trace契約

Entryを拒否した場合も、次をTraceへ残す。

```text
day_trend_state
h4_wave_direction
h4_correction_anchor_time
h4_correction_anchor_price
h4_correction_distance_raw
h4_correction_range_level
entry_candidate_side
entry_candidate_time
entry_candidate_price
guard_decision
reason_code
```

Reason Code:

```text
DAY_UP_H4_DOWN_R5_SHORT_ENTRY_BLOCKED
```

日本語説明:

```text
Day上昇トレンド中のH4調整下降がR5以上進行しているため、
下降末期からの新規Short Entryを見送りました。
```

### 21.8 対称条件の扱い

次のLong側対称条件は、本改定ではまだ採用しない。

```text
Entry方向 = LONG
AND Day Trend = DOWN
AND H4現在波 = UP
AND H4上昇波のHSI進行度 >= R5
```

対称形だからという理由だけで自動追加せず、実際の失敗Entry観測後に別ルールとして判断する。

### 21.9 Day Fibonacci 0.382候補

Day上昇波に対するFibonacci Retracement 0.382は、追加の過熱・調整進行度判定候補として保持する。

```text
将来候補:
Day上昇幅に対する調整下降が0.382へ到達
＋
H4下降波がLate
→ Short Entry Guardを補強
```

ただしv0.21ではEntry Gateへ使用しない。まずHSI R5 Guard単独の効果をシミュレーションで確認し、取りこぼし・防止件数を観測してから追加判断する。

### 21.10 検証観点

1. Day Trend = UP、H4現在波 = DOWN、H4下降波R5到達以上で新規Short Entryが発生しないか。
2. R4.5以下では、本Guardだけを理由にEntryを禁止しないか。
3. Day TrendがUP以外の場合、本Guardが発動しないか。
4. H4現在波がDOWN以外の場合、本Guardが発動しないか。
5. Long Entryへ誤適用しないか。
6. NORMALとEXPANSION_LITEが他Lane状態を参照せず独立して本Guardを評価するか。
7. Guardで拒否した同一Triggerを後続足で再利用しないか。
8. 既存PositionのHold / Close / Stop / Targetへ影響しないか。
9. H4調整起点・R5到達判定で将来足を参照しないか。
10. TraceにGuard条件・HSI進行度・Reason Codeが残るか。
