## 0. まず大前提

これは売買推奨ルールではない。

```text
過去チャート上で
自分が何を見ていたのかを再現し、
Entry / Hold / Close / Reset / NoTrade を
自動シミュレーション可能な形に分解する
```

ための仮説仕様である。

今回の整理で、HSIルールは単なるEntry条件ではなく、

```text
今どの状態かを分類し、
Expansionとして扱ってよい波かを格付けし、
Entryしてよい局面かを段階的に判断する
```

状態遷移ルールとして扱う。

## 1. 時間足の役割

### DAY = UpperMap / Expansion格付け / 大局フィルター

DAYはEntry足ではない。

DAYの役割は、H4で見えているExpansion候補が、日足スケールでも意味のある波なのかを確認すること。

```text
DAY = 上位地図
DAY = Expansion誤判定防止フィルター
DAY = 大きな山谷・調整タイミングを見る足
```

DAYでは、細かいEntry材料や保存縦線ではなく、日足スケールの大局だけを見る。

```text
DAYで見るもの:
- 大きな山谷
- Active basis high / low
- Confirm bars単位の縦点線
- MA20 / T3 / BB
- 現在位置

DAYで基本的に見ないもの:
- M5/H1/H4由来の細かい材料点
- Candidate / Retired basis
- 保存済み通常縦線
- サイクル縦線
- H/Lレンジ縦線
```

ただし、DAYの赤丸・緑丸は必要。
これはEntry材料点ではなく、H4 Expansion候補を日足スケールで格付けするための大局材料点である。

---

### H4 = 主役 / Expansion review main

H4は、Expansion候補そのものを観察する主役。

```text
今は大きな波のどの局面か
Expansionなのか
反転直後なのか
終盤なのか
まだ様子見なのか
```

を見る足。

H4で Dow Up / Dow Down が確定しても、それは即Entryではない。

```text
H4 Dow Up confirmed
→ LongWatch / UpCandidate

H4 Dow Down confirmed
→ ShortWatch / DownCandidate
```

つまりH4のDow確定は発射ボタンではなく、上位足の許可証。

---

### H1 = Permission Check / Rebound Test

H1は、H4とM5の橋渡し。

```text
H4の大文脈が本当に継続しているか
押しなのか崩壊なのか
MA20 / T3 / BB に対して強いのか弱いのか
反発失敗したのか
```

を見る。

H1は、Entryの直前許可やPost Expansion Rebound Testに使う。

---

### M5 = Execution / Trigger

M5はEntry / Add-on / Small TP / Exitの実行足。

```text
DAY/H4/H1が許可
↓
M5でDow confirmed
↓
確定済みHSI起点から距離判定
↓
Entry / Add-on / Close
```

M5単独ではEntryしない。  
M5は最後のトリガー。

## 2. DataSource設計メモ

今回、M5だけからH1/H4/DAYを内部生成する限界が見えた。

M5由来DAYでは表示期間が短く、大きなトレンド・レンジ・節目が見えない。
そのため、最小構成として以下を採用する。

```text
Primary DataSource = M5
UpperMap DataSource = DAY / D1
```

現時点の画面構成は以下。

```text
左     H4 main review      = M5から内部生成
右上   DAY UpperMap         = 外部D1 JSONを直接参照
右下   H1 permission check  = M5から内部生成
```

重要な責務分離。

```text
D1 Data JSON
= 差し替え可能な相場データ

plugin.json
= DAY UpperMapのConfirm bars / marker policyなど、育てるUI設定の正本

chart_comments.json
= HSI / コメント / 保存縦線 / サイクル線など、注釈系データの正本

URL
= 画面を開くためのView状態
```

HSI系URLパラメータはLegacy扱い。  
保存済みHSIはchart_comments.jsonを正本とし、URLコピーでは基本的にHSIを正本化しない。

## 3. HSI起点の絶対ルール

Entryに使うR判定は、必ず確定済みHSI起点から計算する。

```text
Entryに使うR2 / R3.5 / R4 は、
必ず「確定済みHSI起点」から計算する
```

未確定の赤丸候補からR2を引いてEntryすると、後からその起点が否定された瞬間にEntry根拠が消える。

起点は3段階に分ける。

```text
Candidate basis
= 候補。まだEntry計算には使わない。

Confirmed basis
= 確定済み。HSI起点候補として使える。

Adopted HSI basis
= 今回の波の基準点として採用済み。
```

Entry判定に使えるのはConfirmed以降。

## 4. NoTrade / Watch を先に判定する

Entry判定の順番はこれ。

```text
第0関門: 売買対象外ゾーンではないか？
第1関門: Watch / Candidate / Bias か？
第2関門: どのEntryモードか？
第3関門: どのHSI起点を使うか？
第4関門: M5で実行根拠があるか？
第5関門: Stop / Target がリスクに見合うか？
```

特にNoTradeは先。

```text
NoTrade候補

1. H4 TrendState = Undetermined
2. H4 TrendState = NoTrend
3. H4反転直後で、まだWatch段階
4. PostExpansion PullbackWindow中
5. H4 Cycle Late で新規Add-onしようとしている
6. すでにTrade中
7. future data insufficient / 検証不能
```

## 5. Entryモード整理

現時点では、Entryモードはこの5種類に分ける。

```text
A. Normal Trend Entry
B. ReEntry / Add-on Entry
C. Expansion Pullback Entry
D. Pre-Expansion R3.5 Breakout Entry
E. Post-Expansion Reverse Entry
```

---

## A. Normal Trend Entry

一番素直な通常ルール。

Longなら、

```text
H4 = Longを邪魔しない
H1 = Up文脈
M5 = Dow Up confirmed
Anchor = 確定済みTrend Anchor
distance >= R2
not inTrade
```

CloseOKは通常の次境界。

```text
R2〜R2.5   → R2.5
R2.5〜R3   → R3
R3〜R3.5   → R3.5
R3.5〜R4   → R4
R4〜R4.5   → R4.5
```

通常Entryでは、Entry位置が属するHSIエリアの次境界をClose Targetにする。

---

## B. ReEntry / Add-on Entry

CloseOK後もH1/H4文脈が継続しているなら、HSI起点は消さない。  
HSIは1回のTradeではなく、上位足トレンド単位で維持する。

```text
ReEntry条件

前TradeがCloseOK
AND HSI起点は維持中
AND H1/H4方向が継続
AND M5で再び同方向Dow confirmed
AND Entry位置が次のHSIエリア内
```

Add-onは通常M5理論でよい。  
ただし、Expansion方向と同じ方向だけ。

```text
Add-on Allowed =
  Core position が含み益
  AND H4 Expansion方向と同じ
  AND H4 Cycle Phase が Early or Middle
  AND 新しい確定済み押し目/戻り目 basis がある
  AND そのbasisからR2到達
  AND M5 Dow confirmed
```

Add-on禁止条件。

```text
H4 Cycle Late
OR BBが閉じ始め
OR H1高値更新失敗
OR 価格がMA/T3へ戻り始め
OR Coreが含み損
```

合言葉。

```text
買い増しはナンピンではない。
勝っている波にだけ追加する。
```

## C. Expansion Pullback Entry

H4でR4級のExpansionが出ても、そこで即Entryしない。

```text
R4到達 = Entryではない
R4到達 = Expansion Watch / 例外アラート
```

R4到達後に押しを待つ。

```text
Expansion Detection Anchor
= Expansion判定用の大起点

Expansion Entry Anchor
= R4到達後の直近押し安値/戻り高値

Entry Trigger Anchor
= 実際にR2判定する確定済み押し目起点
```

④→⑤→⑯パターンなら、

```text
④ = Expansion Detection Anchor
⑤ = Pullback / Entry Trigger Anchor
⑯ = ⑤起点R2 + M5 Dow Up confirmed
```

ただし、勝負している波は⑤ではなく④。

```text
Entry判定  = ⑤起点R2
Hold判定   = ④起点Expansion文脈
Target判定 = ④起点R5以上
```

Stopも2層に分ける。

```text
構造Stop:
  ⑤ Pullback Anchor 割れ

大波Stop / Thesis Stop:
  ④ Expansion Anchor 文脈崩壊
```

Expansion Entryでは、通常CloseOKをそのまま使わない。  
リスクが広がるため、CloseOK候補がRiskに見合わないならEntryしない。

```text
minimum target  = ④起点R5
extended target = ④起点R5.5 / R6 / R6.5
```

## 6. Expansion候補の再定義

今回の整理で、Expansionは距離だけでは判定しないことが明確になった。

```text
Expansionは値幅だけでは判定しない。
DAYサイクル年齢で格付けする。
```

また、R4到達だけでExpansion候補にするのは弱い。

```text
R4到達はアラート
構造ブレイクで候補
押し戻り成功でEntry検討
DAY足で格付け
```

### Expansion Watch

```text
Expansion Watch
= 確定済み起点からR4以上に到達した状態
```

これはまだ候補ではなく、観察対象入り。

### Expansion Candidate

```text
Expansion Candidate
= R4到達
  AND H4構造ブレイク
  AND H4 BB Opening / ボラ拡大
```

H4構造ブレイク例。

```text
直近H4高値/安値を明確に抜いた
下降/上昇トレンドラインを明確に抜いた
レンジ上限/下限を抜いた
MA20/T3をまたいで反対側に定着した
BB外側に沿って走り始めた
```

### Expansion Grade

DAYで格付けする。

```text
これはH4だけの小爆発か？
それとも日足構造を変えに来ている爆発か？
```

を見る。

### Expansion Confirmed

```text
Expansion Confirmed
= Expansion Candidate
  AND 押し/戻りを作った
  AND 押し戻り後に再度継続方向へ動いた
  AND H1/H4文脈が崩れていない
```

### Expansion Invalid

```text
Expansion Invalid
= R4到達後、構造ブレイクできずレンジ回帰
  OR MA20/T3下へ戻る
  OR BB Openingが続かない
  OR DAY格付けでLate Cycle扱い
```

## 7. DAY Expansion Age Rule

今回の最重要追加ルール。

DAY Confirm=45で見ると、1サイクルがおおむね90日級に見える。
つまり、日足安値から45本を超えた場所は、上昇波の前半ではなく後半・成熟期として扱う必要がある。

Long Expansionの場合。

```text
DAY basis = 直近の日足Active Low
day_cycle_age = 現在足 - DAY basis足
```

Short Expansionの場合。

```text
DAY basis = 直近の日足Active High
day_cycle_age = 現在足 - DAY basis足
```

判定。

```text
45本以内:
  Expansion候補として見てよい

45本超え:
  だいぶ怪しい
  Expansion Grade Down / 要警戒

60本超え:
  Expansion扱いしない
  Late Cycle / 調整待ち扱い
```

これはEntry禁止ルールではなく、Expansion判定の格付けルール。

```text
45本超えだから絶対NoTrade
```

ではなく、

```text
45本超えだから、それをExpansionとして扱うのは怪しい
```

という整理。

60本超えたら、もうExpansionではない。

```text
R4到達 / H4で勢いあり
  ↓
でもDAY安値から何本経っている？
  ↓
45本以内ならExpansion候補
45本超えならLate寄り
60本超えならExpansion却下
```

### 22×2意識

```text
22営業日 ≒ 1か月
45営業日 ≒ 約2か月
```

日足で大きな山谷を見るなら、1か月単位より少し長め、つまり2か月級の確認幅が自然。

```text
DAY Confirm 45
= 日足の短期ノイズを捨てて、
  約2か月級の大きな山谷だけを材料点として見る設定
```

### DAYの右端解釈

DAY右端で、緑丸が立ったあとに価格がT3/MA20から浮き、BB上限側に寄っている場合、

```text
上昇は継続している
でも、もうすぐ調整下げが来そう
```

という絵に見える。

この感覚を可視化するために、DAY Confirm=45を暫定defaultとする。

## D. Pre-Expansion R3.5 Breakout Entry

⑮みたいな波は、Expansion Pullback Entryでは取れない。  
まだR4越え確定前で、Expansion後の押し目でもないため。

そこで、

```text
R3.5 = 先行Entryライン
R4   = Expansion昇格ライン
```

と分ける。

```text
PreExpansionBreakoutAllowed =
  confirmed_basis_low exists
  AND price >= R3.5 from basis low
  AND price breaks equal-high cluster
  AND Close > MA20
  AND Close > T3
  AND BBOpeningStart == true
  AND M5 Dow Up confirmed
```

この時点ではまだ正式Expansionではない。

```text
R3.5高値群ブレイク
= 早乗りEntry候補

R4越え
= Expansion Watch / Candidate昇格候補
```

ただし、DAY Expansion Age Ruleで45本超えならGrade Down、60本超えならExpansion扱いしない。

## E. Post-Expansion Reverse Entry

上昇Expansionを利確したあと、すぐShortしない。  
下落Expansionを利確したあと、すぐLongしない。

```text
Long Exit ≠ Short Entry
Short Exit ≠ Long Entry
```

反転直後のH4 Dow確定は、EntryではなくWatch。

```text
H4 Dow Down confirmed
→ ShortWatch / ShortCandidate

H4 Dow Up confirmed
→ LongWatch / UpCandidate
```

そのあと、反発テストを行う。

```text
ShortWatch
↓
一定期間だけ反発を見る
↓
高値更新できない
↓
MA20 / T3 / BB付近で失速
↓
M5 Dow Down confirmed
↓
ShortBias / ShortEntry候補
```

サイクルの切れ目を完璧に判定しない。  
代わりに期限付き反発テストとして扱う。

```text
Post Expansion Rebound Test
```

## 9. False Expansion Filter

R4越え単独ではExpansion確定にしない。

```text
ExpansionCandidate =
  確定済み起点からR4越え
  + H4構造ブレイク
  + H4 BB Opening
  + DAY Expansion Age Ruleで許容範囲
```

```text
ExpansionConfirmed =
  Candidate後、押し/戻りを作って、
  再度継続方向に動いた状態
```

逆に、

```text
R4越え
BUT
MA20/T3下
OR Dowがすぐ崩壊
OR BBが開かない
OR DAY 60本超え
```

なら、

```text
False Expansion
ExpansionCandidate止まり
Expansion扱いしない
```

HSIは見えている。  
でもHSIだけ信じると騙される。

## 10. BB Phase

BBはEntry / Hold / TP の全部に効く。

```text
BB Squeeze
= 溜め

BB OpeningStart
= 開き始め。Entry / Hold / Add-on候補

BB Expansion
= 伸びている。Hold優先

BB Mature
= 拡張はしているが鈍化。一部利確候補

BB ContractingToMA
= 閉じ始め、MA/T3へ接近。本命利確候補
```

同じHSI重なりでもBB状態で意味が変わる。

```text
HSI Confluence + BB Opening
= 利確ではなく継続理由

HSI Confluence + BB ContractingToMA
= 本命利確理由
```

## 11. HSI Confluence Target

複数起点のRが重なる場所は重要。

```text
④起点R6.5
≒
⑨起点R6
```

これは強い利確候補。

ただし、重なりなら何でも利確ではない。

```text
④R5.5 × ⑨R5
= 中間ターゲット / Hold継続もあり

④R6.5 × ⑨R6
= H4 Cycle Late + BB収縮なら本命利確
```

Confluenceはランク分けする。

```text
Confluence Rank B:
  大起点R5〜R5.5
  BB Opening / Expansion
  → 一部利確 or Hold

Confluence Rank A:
  大起点R6〜R6.5
  H4 Cycle Late
  BB ContractingToMA
  → 本命利確
```

## 12. H4 Cycle Maturity Guard

サイクルは完璧に切らない。  
でも、Expansion波が何合目かは判定する。

```text
Cycle Maturity Score =
  max(
    H4バー経過,
    到達Rレベル,
    ミニサイクル消化数,
    DAY Expansion Age
  )
```

状態は3つ。

```text
Early:
  耐える / 育てる / Add-on可

Middle:
  Add-on可 / 小利確開始

Late:
  Add-on禁止 / 利益保護 / Exit感度上げる
```

```text
前半は育てる
中盤は増やす
後半は刈り取る
```

## 13. 建玉管理

建玉は3種類に分ける。

```text
Core Position
= 大波を取る本玉

Add-on Position
= ミニサイクルで追加する追撃玉

Runner
= 最後に残す夢玉
```

細切れ利確は、たとえば10単位なら、

```text
R4.5到達:
  2単位利確
  目的 = リスク軽減 / 建値化準備

R5到達:
  2単位利確
  目的 = 最低目標回収

R5.5到達:
  2単位利確
  目的 = 中間ターゲット回収

R6 / R6.5 Confluence:
  3単位利確
  目的 = 本命利確

残り1単位:
  Runner
```

Add-on玉は小波で回収。  
Core玉は大波で回収。

```text
本玉は大波を見る。
追撃玉は小波で回収する。
```

## 15. 現時点の最重要ルールだけ短く

```text
1. Entry前にNoTrade / Watch / Candidateを必ず判定する。

2. HSIのR判定は、確定済み起点からしか使わない。

3. DAYはEntry足ではなく、Expansion格付け用のUpperMap。

4. DAY Confirm=45を暫定defaultとし、
   約2か月級の山谷を大局材料点として見る。

   45本以内 = Expansion候補として見てよい
   45本超え = だいぶ怪しい
   60本超え = Expansion扱いしない

6. ExpansionはR4で即Entryしない。
   R4はExpansion Watch / アラート。

7. Expansion Candidateには、R4到達に加えて
   H4構造ブレイク / BB Opening / DAY格付けが必要。

    が本命利確。
```

## 17. 今日の結論

今回の最大成果は、Expansion判定にDAY UpperMapが必要だと見えたこと。

```text
M5 = 顕微鏡
H1 = 検問
H4 = 判断盤

```

そして、Expansionは価格幅だけでなく、DAYサイクル年齢で格付けする。

```text
Expansionは値幅だけでは判定しない。
DAYサイクル年齢で格付けする。
```

DAY Confirm=45は、単なる見た目調整ではなく、日足の大局材料点を可視化するための暫定仮説。

```text
45本以内:

60本超え:
  Expansion扱いしない
```

このルールにより、⑮のようなH4では強く見える候補を、日足スケールではLate Cycleとして扱える可能性が出てきた。
