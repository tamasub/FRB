## 0. まず大前提

これは売買推奨ルールではない。

```text
過去チャート上で
自分が何を見ていたのかを再現し、
Entry / Hold / Close / Reset / NoTrade を
自動シミュレーション可能な形に分解する
```

ための仮説仕様である。

今回の整理で、HSIルールは単なるEntry条件ではなく、

```text
今どの状態かを分類し、
Expansionとして扱ってよい波かを格付けし、
Entryしてよい局面かを段階的に判断する
```

状態遷移ルールとして扱う。

---

v0.4では、Entry条件だけでなく、Entry後のポジション管理を明示的に分離する。

```text
Entry時に管理時間足を固定する。
上位足の波へ接続した場合だけ管理時間足を昇格できる。
利益確定を検討する時間足と、実際に降りるトリガー時間足を分ける。
```

---

## 1. 時間足の役割

### WEEK = Expansion Season / Macro Context / 高値づかみ防止ガード

WEEKはEntry実行足でも、通常の管理時間足でもない。

```text
WEEK = Expansion Entryを探してよい季節かを見る足
WEEK = 大きな方向とサイクル位置を見る足
WEEK = 高値づかみ回避のためのSeason Filter
```

WEEKの役割は、上昇・下降の大局を見たうえで、Expansion Entryの営業期間を開閉すること。

```text
WEEK Cycle Early / Middle
→ Expansion Entry候補を検討してよい

WEEK Cycle Late
→ 新規Expansion Entry禁止
→ Expansion ReEntry禁止
→ Expansion Add-on禁止
→ 既存ポジションのH1早期Closeトリガーを許可
```

ただし、WEEK自体を直接のClose判定足にはしない。

```text
WEEKが上だからWEEKの押し目を丸ごと耐える
```

という運用は採用しない。

WEEKは「乗る波を選ぶ足」であり、「降りる場所を決める足」ではない。

---

### DAY = UpperMap / Expansion格付け / 管理時間足の上限

DAYはEntry足ではない。

DAYの役割は、H4で見えているExpansion候補が、日足スケールでも意味のある波なのかを確認すること。

```text
DAY = 上位地図
DAY = Expansion誤判定防止フィルター
DAY = 大きな山谷・調整タイミングを見る足
DAY = Position Management Timeframeの昇格上限
```

DAYでは、細かいEntry材料や保存縦線ではなく、日足スケールの大局だけを見る。

```text
DAYで見るもの:
- 大きな山谷
- Active basis high / low
- Confirm bars単位の縦点線
- MA20 / T3 / BB
- 現在位置

DAYで基本的に見ないもの:
- M5/H1/H4由来の細かい材料点
- Candidate / Retired basis
- 保存済み通常縦線
- サイクル縦線
- H/Lレンジ縦線
```

DAYの赤丸・緑丸は、Entry材料点ではなく、H4 Expansion候補を日足スケールで格付けするための大局材料点である。

---

### H4 = Expansion判断盤 / 利益確定判断

H4は、Expansion候補そのものを観察する主役。

```text
今は大きな波のどの局面か
Expansionなのか
反転直後なのか
終盤なのか
まだ様子見なのか
```

を見る。

H4で Dow Up / Dow Down が確定しても、それは即Entryではない。

```text
H4 Dow Up confirmed
→ LongWatch / UpCandidate

H4 Dow Down confirmed
→ ShortWatch / DownCandidate
```

また、Expansion保有中の利益確定は、H4で大きく判断する。

```text
H4 Cycle Late
+ H4 BB ContractingToMA
+ HSI Confluence
→ Profit Take Armed / 利益確定準備
```

H4は「今すぐ降りる足」ではなく、「そろそろ刈り取る季節か」を判断する足。

---

### H1 = Permission Check / Exit Trigger

H1は、H4とM5の橋渡し。

```text
H4の大文脈が本当に継続しているか
押しなのか崩壊なのか
MA20 / T3 / BB に対して強いのか弱いのか
反発失敗したのか
```

を見る。

通常時はEntryの直前許可やPost Expansion Rebound Testに使う。

Expansionの利益確定準備がONになった後は、H4確定を待って逃げ遅れないためのCloseトリガーとして使う。

```text
Profit Take Armed
AND H1 Structure Break / Rebound Failure
→ Close候補
```

WEEK Cycle Lateでは、H1 Close Triggerを早めに有効化する。

---

### M5 = Execution / Trigger

M5はEntry / Add-on / Small TP / Closeの実行足。

```text
WEEK / DAY / H4 / H1が許可
↓
M5で実行条件を確認
↓
Entry / Add-on / Close
```

M5単独ではEntryしない。
Expansion CoreはM5の小崩れだけでは降ろさない。

---

### 時間足の役割まとめ

```text
WEEK = Expansionの季節 / Entry Season Filter
DAY  = 大局地図 / 管理時間足の上限
H4   = Expansion判断 / 利益確定判断
H1   = Entry許可 / 実際に降りるClose Trigger
M5   = Entry・Closeの実行
```

## 2. DataSource / 画面構成

M5だけからH1/H4/DAY/WEEKをすべて内部生成すると、表示期間と大局判断に限界がある。
そのため、最小構成として以下を採用する。

```text
Primary DataSource = M5
UpperMap DataSource = DAY / D1
WEEK Context        = 外部DAYデータを週足へ集約
```

現時点の画面構成。

```text
Expansion検討モード:
左     H4 main review       = M5から内部生成
右上   DAY UpperMap          = 外部D1 JSONを直接参照
右下   WEEK expansion context = 外部D1 JSONから週足集約

M5実行モード:
左     M5 entry observation
右上   H1 context
右下   H4 macro context
```

重要な責務分離。

```text
D1 Data JSON
= 差し替え可能な相場データ

plugin.json
= DAY/WEEK Confirm bars、marker policy、表示期間などUI設定の正本

chart_comments.json
= HSI / コメント / 保存縦線 / サイクル線など、注釈系データの正本

URL
= 画面を開くためのView状態
```

WEEK Confirm barsはDAY Confirm barsと独立してplugin.jsonで手動調整する。
WEEK窓では大局確認を優先し、保存済み通常縦線・サイクル縦線は表示しない。

HSI系URLパラメータはLegacy扱い。  
保存済みHSIはchart_comments.jsonを正本とし、URLコピーでは基本的にHSIを正本化しない。

## 3. HSI起点の絶対ルール

Entryに使うR判定は、必ず確定済みHSI起点から計算する。

```text
Entryに使うR2 / R3.5 / R4 は、
必ず「確定済みHSI起点」から計算する
```

未確定の赤丸候補からR2を引いてEntryすると、後からその起点が否定された瞬間にEntry根拠が消える。

起点は3段階に分ける。

```text
Candidate basis
= 候補。まだEntry計算には使わない。

Confirmed basis
= 確定済み。HSI起点候補として使える。

Adopted HSI basis
= 今回の波の基準点として採用済み。
```

Entry判定に使えるのはConfirmed以降。

## 4. Position Management Timeframe

すべてのEntryは、Entry時点で「どの時間足の構造が壊れたら処分を検討するか」を固定する。

```text
Entry Timeframe
= 実際にEntryを実行した時間足

Management Timeframe
= ポジションの保有根拠と処分判断を管理する時間足

Exit Trigger Timeframe
= Management Timeframeが処分準備に入った後、実際に降りる契機を見る時間足

Direction Context Timeframe
= 売買方向や季節を参照する上位足
```

同じ価格・同じ方向のEntryでも、管理時間足が違えば別のポジションとして扱う。

```text
Entry A = H1管理
Entry B = H4管理
Entry C = DAY管理
```

### 管理時間足昇格

Entry後に上位足の波へ接続した場合だけ、Management Timeframeを昇格できる。

```text
M5 → H1 → H4 → DAY
```

昇格上限はDAY。
WEEKはDirection Context / Season Filterであり、Management Timeframeにはしない。

昇格条件候補。

```text
- 上位足の方向が一致している
- 上位足の構造が確定している
- ポジションが含み益である
- 昇格後の新しい無効化条件を定義できる
- 損失回避を理由とした昇格ではない
```

禁止事項。

```text
含み損になった
→ M5では切らずH1で見る
→ H1でも切らずH4で見る
```

という損切り先延ばしは禁止。

### Exit Triggerの下位足化

Management TimeframeはH4/DAYのままでも、利益確定準備後のExit TriggerはH1へ下げてよい。
これは管理時間足の降格ではなく、逃げ遅れを防ぐための実行トリガー分離である。

```text
Management Timeframe = H4 or DAY
Profit Take Decision  = H4
Exit Trigger Timeframe = H1
Execution Timeframe    = M5
```

## 5. NoTrade / Watch を先に判定する

Entry判定の順番はこれ。

```text
第0関門: 売買対象外ゾーンではないか？
第1関門: Watch / Candidate / Bias か？
第2関門: どのEntryモードか？
第3関門: どのHSI起点を使うか？
第4関門: M5で実行根拠があるか？
第5関門: Stop / Target がリスクに見合うか？
```

特にNoTradeは先。

```text
NoTrade候補

1. H4 TrendState = Undetermined
2. H4 TrendState = NoTrend
3. H4反転直後で、まだWatch段階
4. PostExpansion PullbackWindow中
5. H4 Cycle Late で新規Add-onしようとしている
6. すでにTrade中
7. WEEK Cycle Lateで新規Expansion Entry / ReEntry / Add-onをしようとしている
8. future data insufficient / 検証不能
```

## 6. Entryモード整理

現時点では、Entryモードはこの5種類に分ける。

```text
A. Normal Trend Entry
B. ReEntry / Add-on Entry
C. Expansion Pullback Entry
D. Pre-Expansion R3.5 Breakout Entry
E. Post-Expansion Reverse Entry
```

---

---

## A. Normal Trend Entry

一番素直な通常ルール。

Longなら、

```text
H4 = Longを邪魔しない
H1 = Up文脈
M5 = Dow Up confirmed
Anchor = 確定済みTrend Anchor
distance >= R2
not inTrade
```

CloseOKは通常の次境界。

```text
R2〜R2.5   → R2.5
R2.5〜R3   → R3
R3〜R3.5   → R3.5
R3.5〜R4   → R4
R4〜R4.5   → R4.5
```

通常Entryでは、Entry位置が属するHSIエリアの次境界をClose Targetにする。

---

---

## B. ReEntry / Add-on Entry

CloseOK後もH1/H4文脈が継続しているなら、HSI起点は消さない。  
HSIは1回のTradeではなく、上位足トレンド単位で維持する。

```text
ReEntry条件

前TradeがCloseOK
AND HSI起点は維持中
AND H1/H4方向が継続
AND M5で再び同方向Dow confirmed
AND Entry位置が次のHSIエリア内
```

Add-onは通常M5理論でよい。  
ただし、Expansion方向と同じ方向だけ。

```text
Add-on Allowed =
  Core position が含み益
  AND H4 Expansion方向と同じ
  AND H4 Cycle Phase が Early or Middle
  AND 新しい確定済み押し目/戻り目 basis がある
  AND そのbasisからR2到達
  AND M5 Dow confirmed
```

Add-on禁止条件。

```text
H4 Cycle Late
OR WEEK Cycle Late
OR BBが閉じ始め
OR H1高値更新失敗
OR 価格がMA/T3へ戻り始め
OR Coreが含み損
```

合言葉。

```text
買い増しはナンピンではない。
勝っている波にだけ追加する。
```

---

WEEK Cycle Lateでは、Expansion方向が継続して見えていても、新規ReEntry / Add-onを禁止する。
目的は取り逃し回避ではなく、高値づかみ回避を優先するため。

---

## C. Expansion Pullback Entry

H4でR4級のExpansionが出ても、そこで即Entryしない。

```text
R4到達 = Entryではない
R4到達 = Expansion Watch / 例外アラート
```

R4到達後に押しを待つ。

```text
Expansion Detection Anchor
= Expansion判定用の大起点

Expansion Entry Anchor
= R4到達後の直近押し安値/戻り高値

Entry Trigger Anchor
= 実際にR2判定する確定済み押し目起点
```

④→⑤→⑯パターンなら、

```text
④ = Expansion Detection Anchor
⑤ = Pullback / Entry Trigger Anchor
⑯ = ⑤起点R2 + M5 Dow Up confirmed
```

ただし、勝負している波は⑤ではなく④。

```text
Entry判定  = ⑤起点R2
Hold判定   = ④起点Expansion文脈
Target判定 = ④起点R5以上
```

Stopも2層に分ける。

```text
構造Stop:
  ⑤ Pullback Anchor 割れ

大波Stop / Thesis Stop:
  ④ Expansion Anchor 文脈崩壊
```

Expansion Entryでは、通常CloseOKをそのまま使わない。  
リスクが広がるため、CloseOK候補がRiskに見合わないならEntryしない。

```text
minimum target  = ④起点R5
extended target = ④起点R5.5 / R6 / R6.5
```

## 7. Expansion候補の再定義

今回の整理で、Expansionは距離だけでは判定しないことが明確になった。

```text
Expansionは値幅だけでは判定しない。
DAYサイクル年齢で格付けする。
```

また、R4到達だけでExpansion候補にするのは弱い。

```text
R4到達はアラート
構造ブレイクで候補
押し戻り成功でEntry検討
DAY足で格付け
```

### Expansion Watch

```text
Expansion Watch
= 確定済み起点からR4以上に到達した状態
```

これはまだ候補ではなく、観察対象入り。

### Expansion Candidate

```text
Expansion Candidate
= R4到達
  AND H4構造ブレイク
  AND H4 BB Opening / ボラ拡大
```

H4構造ブレイク例。

```text
直近H4高値/安値を明確に抜いた
下降/上昇トレンドラインを明確に抜いた
レンジ上限/下限を抜いた
MA20/T3をまたいで反対側に定着した
BB外側に沿って走り始めた
```

### Expansion Grade

DAYで格付けする。

```text
これはH4だけの小爆発か？
それとも日足構造を変えに来ている爆発か？
```

を見る。

### Expansion Confirmed

```text
Expansion Confirmed
= Expansion Candidate
  AND 押し/戻りを作った
  AND 押し戻り後に再度継続方向へ動いた
  AND H1/H4文脈が崩れていない
```

### Expansion Invalid

```text
Expansion Invalid
= R4到達後、構造ブレイクできずレンジ回帰
  OR MA20/T3下へ戻る
  OR BB Openingが続かない
  OR DAY格付けでLate Cycle扱い
```

## 8. DAY Expansion Age Rule

今回の最重要追加ルール。

DAY Confirm=45で見ると、1サイクルがおおむね90日級に見える。
つまり、日足安値から45本を超えた場所は、上昇波の前半ではなく後半・成熟期として扱う必要がある。

Long Expansionの場合。

```text
DAY basis = 直近の日足Active Low
day_cycle_age = 現在足 - DAY basis足
```

Short Expansionの場合。

```text
DAY basis = 直近の日足Active High
day_cycle_age = 現在足 - DAY basis足
```

判定。

```text
45本以内:
  Expansion候補として見てよい

45本超え:
  だいぶ怪しい
  Expansion Grade Down / 要警戒

60本超え:
  Expansion扱いしない
  Late Cycle / 調整待ち扱い
```

これはEntry禁止ルールではなく、Expansion判定の格付けルール。

```text
45本超えだから絶対NoTrade
```

ではなく、

```text
45本超えだから、それをExpansionとして扱うのは怪しい
```

という整理。

60本超えたら、もうExpansionではない。

```text
R4到達 / H4で勢いあり
  ↓
でもDAY安値から何本経っている？
  ↓
45本以内ならExpansion候補
45本超えならLate寄り
60本超えならExpansion却下
```

### 22×2意識

```text
22営業日 ≒ 1か月
45営業日 ≒ 約2か月
```

日足で大きな山谷を見るなら、1か月単位より少し長め、つまり2か月級の確認幅が自然。

```text
DAY Confirm 45
= 日足の短期ノイズを捨てて、
  約2か月級の大きな山谷だけを材料点として見る設定
```

### DAYの右端解釈

DAY右端で、緑丸が立ったあとに価格がT3/MA20から浮き、BB上限側に寄っている場合、

```text
上昇は継続している
でも、もうすぐ調整下げが来そう
```

という絵に見える。

この感覚を可視化するために、DAY Confirm=45を暫定defaultとする。

## 9. WEEK Expansion Season / Late-Cycle Entry Guard

WEEKの季節判定は難しいため、初期版では「大波を最大限取る」より「Expansion Entry可能期間を短くする」方向へ倒す。

目的。

```text
取り逃し回避より、高値づかみ回避を優先する。
WEEKの1サイクル後半ではExpansion Entryをさせない。
```

初期状態は、まず2状態で扱う。

```text
WEEK_EXPANSION_OPEN
= Expansion Entry候補を検討してよい

WEEK_EXPANSION_CLOSED
= 新規Expansion Entry禁止
= Expansion ReEntry禁止
= Expansion Add-on禁止
= 既存ポジションのH1早期Close Trigger許可
```

将来的にはTransitionを追加してもよい。

```text
EXPANSION_ALLOWED
TRANSITION
EXIT_PERMISSION
```

### WEEK Cycle Lateの効果

```text
WEEK Cycle Late = true

Expansion Entry Allowed  = false
Expansion ReEntry Allowed = false
Expansion Add-on Allowed  = false
WEEK Direct Close         = false
H1 Early Exit Trigger     = true
```

重要。

```text
WEEK Cycle Late
≠ 即Close
```

WEEKは「もう新しく乗る季節ではない」「H1で崩れたら早めに降りてよい」という許可を出す。
実際のCloseはH1以下で判断する。

### Late判定の初期候補

最初から完全なCycle判定を目指さない。
次のような終盤要素が増えたら、保守的にCLOSEDへ倒す。

```text
- WEEK起点からの経過バー数が上限を超えた
- WEEKの高値更新 / 安値更新が鈍化した
- WEEK BBの拡大が止まり、収縮へ向かった
- WEEK MA20 / T3の傾きが鈍化した
- WEEKでミニサイクルを複数消化した
- 長期トレンドライン突破後でも、次の週足押し目時期が接近している
```

初期実装では、経過バー数など単純な条件から始め、後からOPEN期間を延長する方向で調整する。

## D. Pre-Expansion R3.5 Breakout Entry

⑮みたいな波は、Expansion Pullback Entryでは取れない。  
まだR4越え確定前で、Expansion後の押し目でもないため。

そこで、

```text
R3.5 = 先行Entryライン
R4   = Expansion昇格ライン
```

と分ける。

```text
PreExpansionBreakoutAllowed =
  confirmed_basis_low exists
  AND price >= R3.5 from basis low
  AND price breaks equal-high cluster
  AND Close > MA20
  AND Close > T3
  AND BBOpeningStart == true
  AND M5 Dow Up confirmed
```

この時点ではまだ正式Expansionではない。

```text

= Expansion Watch / Candidate昇格候補
```

## E. Post-Expansion Reverse Entry

上昇Expansionを利確したあと、すぐShortしない。  
下落Expansionを利確したあと、すぐLongしない。

```text
Long Exit ≠ Short Entry
Short Exit ≠ Long Entry
```

反転直後のH4 Dow確定は、EntryではなくWatch。

```text
H4 Dow Down confirmed
→ ShortWatch / ShortCandidate

H4 Dow Up confirmed
→ LongWatch / UpCandidate
```

そのあと、反発テストを行う。

```text
ShortWatch
↓
一定期間だけ反発を見る
↓
高値更新できない
↓
MA20 / T3 / BB付近で失速
↓
M5 Dow Down confirmed
↓
ShortBias / ShortEntry候補
```

サイクルの切れ目を完璧に判定しない。  
代わりに期限付き反発テストとして扱う。

```text
Post Expansion Rebound Test
```

## 15. Expansion Close / Profit-Take Architecture

Expansionの処分は、「利益確定を検討する時間足」と「実際に降りる時間足」を分離する。

### 16.1 通常の利益確定準備

利益確定すべき大きな季節に入ったかはH4で判断する。

```text
H4 Cycle Late
AND H4 BB ContractingToMA
AND HSI Confluence Rank A
→ Profit Take Armed
```

H4で見る理由。

```text
- H1の小さな押しをExpansion終了と誤認しない
- BB収縮を大きな波の視点で判断する
- HSI到達度とサイクル成熟を同じ時間軸で見る
```

### 16.2 実際のClose Trigger

Profit Take Armed後は、H4足確定まで待って利益を削らないため、H1で実際の離脱契機を確認する。

H1 Close Trigger候補。

```text
- H1高値更新失敗 / 安値更新失敗
- H1確定押し安値 / 戻り高値のブレイク
- H1 Dow反転確定
- H1 MA20 / T3を割り、反発しても戻せない
- H1 Rebound Failure
```

```text
H4で「そろそろ刈り取る」と決める
↓
H1で「今、降りる」を決める
↓
M5でCloseを実行する
```

### 16.3 WEEK Lateによる処分前倒し

WEEK Cycle Lateでは、H4の完全な成熟シグナルを待つより、高値づかみ回避を優先する。

```text
WEEK Cycle Late
→ Expansion Entry Season CLOSED
→ Profit Protection Mode
→ H1 Early Exit Trigger Enabled
```

WEEKは直接Closeしない。
H1の崩れが出たときに、H4/DAYの確定を待たずClose可能とする。

### 16.4 Expansion中のHold原則

```text
WEEK Early / Middle
AND H4 BB Opening / Expansion
AND H4 Cycle Early / Middle
→ M5/H1の小崩れではCoreを降ろさない
```

### 16.5 Stop / Thesis崩壊

利益確定とは別に、Expansion Entryの無効化Stopは2層で管理する。

```text
構造Stop
= Pullback / Entry Trigger Anchor割れ
= Add-on / Tactical Positionの主な処分候補

大波Stop / Thesis Stop
= Expansion Detection Anchorの文脈崩壊
= Core Positionの主な処分候補
```

どの建玉をどちらのStopで処分するかは、Entry単位のManagement TimeframeとPosition Roleで管理する。

### 16.6 役割まとめ

```text
WEEK = Expansion Entry Season / Exit Permission
H4   = Profit Take Decision / Exit Armed
H1   = Actual Close Trigger
M5   = Close Execution
```

## 20. 今日の結論

v0.4の最大成果は、ExpansionのEntry・Hold・Closeを、時間足の役割として分離できたこと。

```text
WEEK = 季節を決める
DAY  = 大局と管理上限を決める
H4   = 利益確定を検討する
H1   = 実際に降りる契機を決める
M5   = Entry / Closeを実行する
```

管理時間足の基本原則。

```text
Entry単位で管理時間足を固定する。
上位足の波へ接続した場合だけ昇格できる。
昇格上限はDAY。
WEEKは管理時間足にしない。
```

WEEK Cycle Lateの基本原則。

```text
WEEKの1サイクル後半ではExpansion Entryをさせない。
取り逃しより、高値づかみ回避を優先する。
既存ポジションは即Closeせず、H1の崩れで早めに降りる。
```

Expansionの利益確定。

```text
H4で「そろそろ刈り取る」と判断し、
H1で「今、降りる」を判断し、
M5でCloseを実行する。
```

これは、WEEKの大波を無視するルールではない。
WEEKをEntryの参考に使いながら、週足の大きな押し目を丸ごと耐える運用を避けるための高値づかみ防止ルールである。
