## 0. まず大前提

これは売買推奨ルールではない。

```text
過去チャート上で
自分が何を見ていたのかを再現し、
Entry / Hold / Close / Reset / NoTrade を
自動シミュレーション可能な形に分解する
```

ための仮説仕様である。

今回の整理で、HSIルールは単なるEntry条件ではなく、

```text
今どの状態かを分類し、
Expansionとして扱ってよい波かを格付けし、
Entryしてよい局面かを段階的に判断する
```

状態遷移ルールとして扱う。

---

v0.4では、Entry後の管理時間足を分離した。

v0.5では、Entry RuleとClose Policyを分離し、Scale-out仮説を導入した。

v0.6では、通常M5 EntryをExpansion Entryから分離した。

v0.7では、いったん従来のHSIルールに近づけるため、建玉管理を単純化する。

```text
1 Entry ID
= 1 Position
= 1 Stop
= 1 Target
= 1回の全Close
```

1回のEntryに対するPartial Close、Runner、複数Closeは使用しない。

```text
Entry
↓
Target到達なら全建玉CloseOK
または
Entryに使用したHSI起点へ到達したら全建玉StopClose
↓
そのEntryは終了
```

通常Entryは、同時に1つだけ保有する。

```text
通常Entry:
  Add-on禁止
  Partial Close禁止
  Runner禁止
```

通常Close後に条件が再成立した場合は、別のEntry ID / Trade IDとしてReEntryを許可する。

Add-onはExpansion Entryだけで許可する。
ただし、Expansion Add-onも独立したEntryとして扱う。

```text
Expansion Core Entry
= 1 Stop + 1 Target + 1 Close

Expansion Add-on Entry
= 1 Stop + 1 Target + 1 Close
```

Expansion全体では複数Entryを持ちうるが、1つのEntryが複数Closeを持つことはない。

v0.6の通常M5 Entry条件は、引き続き検証対象として維持する。

```text
通常M5 Entry
= H4 T3方向
+ H1 / M5 Dow一致
+ H4 / H1 Cycle Late除外
+ 確定済みHSI起点からR2到達
```

H4 Dow、WEEK、DAY、Expansion Confirmedは、通常M5 Entryの必須条件にしない。

今回の目的は、完成された勝ちルールを先に作ることではない。

```text
まずEntry候補を出す
↓
チャート上で違和感を見つける
↓
「なぜここでEntryするのか」を検証する
↓
Entry条件を育てる
```

Entry回数そのものを品質とはみなさないが、検証体験を成立させるための観測目安として、
**1営業日あたり約1回**を暫定的なEntry頻度目標に置く。

## 1. 時間足の役割

### WEEK = Expansion Season / Macro Context / 高値づかみ防止ガード

WEEKは通常M5 Entryの必須条件には使わない。

WEEKの役割は、Expansion Entryを探してよい季節かを判断すること。

```text
WEEK = Expansion Entryを探してよい季節かを見る足
WEEK = 大きな方向とサイクル位置を見る足
WEEK = 高値づかみ回避のためのSeason Filter
```

```text
WEEK Cycle Early / Middle
→ Expansion Entry候補を検討してよい

WEEK Cycle Late
→ 新規Expansion Entry禁止
→ Expansion ReEntry禁止
→ Expansion Add-on禁止
→ H1弱化観測を強める（v0.7では直接Closeしない）
```

WEEK自体を直接のClose判定足にはしない。

---

### DAY = UpperMap / Expansion格付け / 管理時間足の上限

DAYも通常M5 Entryの必須条件には使わない。

DAYの役割は、H4で見えているExpansion候補が、
日足スケールでも意味のある波なのかを確認すること。

```text
DAY = 上位地図
DAY = Expansion誤判定防止フィルター
DAY = 大きな山谷・調整タイミングを見る足
DAY = Position Management Timeframeの昇格上限
```

DAYの赤丸・緑丸は、通常M5 Entry材料ではなく、
H4 Expansion候補を日足スケールで格付けするための大局材料点である。

---

### H4 = Normal方向許可 / Expansion判断 / Target候補観測

通常M5 Entryでは、H4 Dowを使わない。

H4はT3だけを使って、大きな方向を許可する。

```text
Long方向許可:
  最新確定H4 T3 > 1本前の確定H4 T3
  AND 最新確定H4 Close > 最新確定H4 T3

Short方向許可:
  最新確定H4 T3 < 1本前の確定H4 T3
  AND 最新確定H4 Close < 最新確定H4 T3

それ以外:
  H4方向未確定
  → 通常M5 Entry不可
```

H4 Dowは画面上の観測情報として残してよいが、
通常M5 Entryの許可・禁止には使用しない。

```text
H4 Dow confirmed
≠ 通常M5 Entry条件
```

一方、Expansion Entryでは引き続き、
H4構造・BB・Cycle・HSIを使って大波を判断する。

また、H4 Cycle Lateの場合は、
通常Entry / ReEntry / Expansion Add-onを含む新規建玉を禁止する。

Expansion保有中は、H4で大きな波の成熟度とTarget候補を観測する。

```text
H4 Cycle Late
+ H4 BB ContractingToMA
+ HSI Confluence
→ Expansion Target候補を強める
→ 新規Add-onを抑制する
```

ただしv0.7では、Entry後に新しいClose Eventを追加しない。Entry時に固定したTargetまたはStopで1回だけ全Closeする。

---

### H1 = Dow方向確認 / Cycle Guard / Expansion観測

通常M5 Entryでは、H1 Dowを中間トレンド確認に使う。

```text
Long候補:
  H1 Dow Trend = UP

Short候補:
  H1 Dow Trend = DOWN
```

H1 DowとM5 Dowが同じ方向になった場合だけEntry候補とする。

```text
H1 UP   + M5 UP   → Long候補
H1 DOWN + M5 DOWN → Short候補

不一致 / REVERSAL_WATCH / NO_TREND / UNDETERMINED
→ 通常M5 Entryなし
```

H1 Cycle Lateの場合は、新規Entry / ReEntry / Expansion Add-onを禁止する。

Expansion保有中のH1 Structure Break / Rebound Failureは、波の弱まりを確認する観測情報として残す。

```text
H1 Structure Break / Rebound Failure
→ 新規Expansion Add-on禁止候補
→ 次回ルール改定材料
```

v0.7では、この観測だけで既存Positionを追加Closeしない。

---

### M5 = Dow実行トリガー / Entry・Close実行

M5はEntry / ReEntry / Expansion Add-on / CloseOK / StopCloseの実行足。

通常M5 Entryでは、M5 DowがH1 Dowと一致していることを必須とする。

```text
H4 T3で方向許可
↓
H4 / H1 Cycle Lateではない
↓
H1 Dow方向確認
↓
M5 DowがH1と同方向
↓
確定済みHSI起点からR2到達
↓
Entry
```

M5単独ではEntryしない。

---

### 時間足の役割まとめ

```text
WEEK = Expansionの季節 / 通常Entryには使わない
DAY  = Expansion格付け / 通常Entryには使わない
H4   = T3による通常Entry方向許可 / Cycle Guard / Expansion判断
H1   = Dow方向確認 / Cycle Guard / Expansion弱化観測
M5   = Dow実行トリガー / Entry・Close実行
```

### 通常EntryとExpansion Entryの責務分離

```text
通常M5 Entry:
  H4 T3
  + H1 Dow
  + M5 Dow
  + H4/H1 Cycle Guard
  + HSI R2

Expansion Entry:
  WEEK Season
  + DAY Grade
  + H4 Structure / BB / Cycle
  + H1 Permission
  + M5 Trigger
```

## 2. DataSource / 画面構成

M5だけからH1/H4/DAY/WEEKをすべて内部生成すると、表示期間と大局判断に限界がある。
そのため、最小構成として以下を採用する。

```text
Primary DataSource = M5
UpperMap DataSource = DAY / D1
WEEK Context        = 外部DAYデータを週足へ集約
```

現時点の画面構成。

```text
Expansion検討モード:
左     H4 main review       = M5から内部生成
右上   DAY UpperMap          = 外部D1 JSONを直接参照
右下   WEEK expansion context = 外部D1 JSONから週足集約

M5実行モード:
左     M5 entry observation
右上   H1 context
右下   H4 macro context
```

重要な責務分離。

```text
D1 Data JSON
= 差し替え可能な相場データ

plugin.json
= DAY/WEEK Confirm bars、marker policy、表示期間などUI設定の正本

chart_comments.json
= HSI / コメント / 保存縦線 / サイクル線など、注釈系データの正本

URL
= 画面を開くためのView状態
```

WEEK Confirm barsはDAY Confirm barsと独立してplugin.jsonで手動調整する。
WEEK窓では大局確認を優先し、保存済み通常縦線・サイクル縦線は表示しない。

HSI系URLパラメータはLegacy扱い。  
保存済みHSIはchart_comments.jsonを正本とし、URLコピーでは基本的にHSIを正本化しない。

## 3. HSI起点の絶対ルール

Entryに使うR判定は、必ず確定済みHSI起点から計算する。

```text
Entryに使うR2 / R2.5 / R3 / R3.5 / R4 は、
必ず「確定済みHSI起点」から計算する
```

未確定の赤丸候補からR判定を行うと、後からその起点が否定された瞬間にEntry根拠が消える。

起点は3段階に分ける。

```text
Candidate basis
= 候補。まだEntry計算には使わない。

Confirmed basis
= 確定済み。HSI起点候補として使える。

Adopted HSI basis
= 今回のEntryで使用する起点として採用済み。
```

Entry判定に使えるのはConfirmed以降。

### Entry時のHSI固定契約

Entryが成立した時点で、そのEntryに使用したHSI起点を固定する。

```text
entry_hsi_anchor_id
entry_hsi_anchor_price
stop_price
```

は同じEntry IDへ紐づける。

```text
Stop Price
= Entryに使用したHSI起点価格
```

Entry後に新しいHSI起点が確定しても、既存PositionのStopを新しい起点へ差し替えない。

```text
新しいHSI起点
= 次のEntry / ReEntry / Expansion Add-on候補に使用できる

既存EntryのStop
= Entry時に固定したHSI起点のまま
```

Targetも同じHSI起点から算出し、Entry時に固定する。

```text
1 Entry ID
= 1 HSI Anchor
= 1 Stop Price
= 1 Target Price
```

通常Entry、Expansion Core、Expansion Add-onのすべてにこの契約を適用する。

## 4. Position Management / Entry Unit Contract

v0.7では、管理の最小単位をTrade全体ではなくEntry単位とする。

```text
1 Entry ID
= 1 Position ID
= 1 Direction
= 1 Entry Price
= 1 Entry HSI Anchor
= 1 Stop Price
= 1 Target Price
= 1 Terminal Close Event
```

Terminal Close Eventは、次のどちらか一つ。

```text
CLOSE_OK
STOP_CLOSE / CLOSE_MISS
```

同一Entry IDでPartial Closeや複数回Closeは行わない。

### 通常Entry

```text
同時保有数 = 1
initial_units = 10
Add-on = 不可
Close = 全10単位を一度に決済
```

Close後に条件が再成立した場合は、別TradeとしてReEntryできる。

### Expansion Entry

ExpansionではCore Entryに加えて、条件成立時だけAdd-onを許可する。

```text
Expansion Core
= 独立したEntry ID / Position ID

Expansion Add-on
= Coreとは別のEntry ID / Position ID
```

CoreとAdd-onは、それぞれ別のHSI起点・Stop・Targetを持つ。

```text
Core Entry    → Core用HSI起点でStop判定 → Core Targetで1回Close
Add-on Entry  → Add-on用HSI起点でStop判定 → Add-on Targetで1回Close
```

### Management Timeframeの扱い

Management Timeframeは、Entryの背景やExpansion文脈を記録するために保持する。
ただしv0.7では、管理時間足の昇格を理由に既存EntryのStopを広げない。

```text
H1管理からH4管理へ昇格した
→ Stopを下へ広げる
```

という損切り先延ばしは禁止。

既存EntryのStop / TargetはEntry時に固定する。
上位足の状態変化は、次のEntry・ReEntry・Expansion Add-onを許可するかどうかの判断に使う。

## 5. NoTrade / Watch を先に判定する

Entry判定では、通常M5 EntryとExpansion EntryのNoTrade条件を分ける。

### 5.1 通常M5 EntryのNoTrade

```text
1. H4 T3方向が未確定
2. H4 T3方向とH1 Dow方向が不一致
3. H1 DowとM5 Dowが不一致
4. H1 DowがREVERSAL_WATCH / NO_TREND / UNDETERMINED
5. M5 DowがREVERSAL_WATCH / NO_TREND / UNDETERMINED
6. H4 Cycle = LATE
7. H1 Cycle = LATE
8. 確定済みHSI起点がない
9. 確定済みHSI起点からR2未到達
10. 通常Positionをすでに保有中
11. Stop Price / Target PriceをEntry時に固定できない
12. future data insufficient / 検証不能
```

通常M5 Entryでは、以下をNoTrade条件にしない。

```text
- H4 Dow Trend
- WEEK Cycle
- DAY Cycle
- Expansion Confirmed
- H4 BB Opening
- DAY Expansion Grade
```

通常Entry中のAdd-onは常に禁止する。

```text
Normal Add-on Allowed = false
```

### 5.2 Expansion Entry / Add-onのNoTrade

Expansion Entryでは、従来どおり上位足を厳しく扱う。

```text
1. WEEK Expansion Season = CLOSED
2. DAY Expansion Age = 60本超
3. H4 Trend / Structureが未確定
4. H4 Cycle = LATE
5. H1 Cycle = LATE
6. PostExpansion PullbackWindow中
7. Expansion Confirmed未成立
8. Entryに使う確定済みHSI起点がない
9. Stop Price / Target PriceをEntry時に固定できない
10. future data insufficient / 検証不能
```

Expansion Add-onは、Expansion Core保有中かつAdd-on条件成立時だけ許可する。
通常EntryをExpansion Add-onへ読み替えない。

### 5.3 Entry判定順序

```text
第0関門: Entry Modeを選ぶ
第1関門: Cycle Lateではないか
第2関門: 方向条件が一致しているか
第3関門: 確定済みHSI起点があるか
第4関門: R2へ到達しているか
第5関門: 建玉状態がEntry可能か
第6関門: Entry HSI AnchorをStopとして固定できるか
第7関門: 次のHSI Targetを固定できるか
```

## 6. Entryモード整理

現時点では、Entryモードはこの5種類に分ける。

```text
A. Normal Trend Entry
B. ReEntry / Add-on Entry
C. Expansion Pullback Entry
D. Pre-Expansion R3.5 Breakout Entry
E. Post-Expansion Reverse Entry
```

---

---

## A. Normal Trend Entry

v0.6の通常M5 Entryは、H4 Dowを使わず、
H4 T3・H1 Dow・M5 Dowを中心に判定する。

### Long Entry

```text
H4 Direction Permission:
  最新確定H4 T3 > 1本前の確定H4 T3
  AND 最新確定H4 Close > 最新確定H4 T3

H1 Direction:
  H1 Dow Trend = UP

M5 Trigger:
  M5 Dow Trend = UP

Cycle Guard:
  H4 Cycle != LATE
  AND H1 Cycle != LATE

HSI:
  確定済みUP方向HSI起点あり
  AND 起点からR2以上

Position:
  新規Entry可能な建玉状態
```

### Short Entry

```text
H4 Direction Permission:
  最新確定H4 T3 < 1本前の確定H4 T3
  AND 最新確定H4 Close < 最新確定H4 T3

H1 Direction:
  H1 Dow Trend = DOWN

M5 Trigger:
  M5 Dow Trend = DOWN

Cycle Guard:
  H4 Cycle != LATE
  AND H1 Cycle != LATE

HSI:
  確定済みDOWN方向HSI起点あり
  AND 起点からR2以上

Position:
  新規Entry可能な建玉状態
```

### 明示的に使わない条件

通常M5 Entryでは、以下を必須条件にしない。

```text
H4 Dow Trend
WEEK Expansion Season
DAY Expansion Grade
Expansion Confirmed
H4構造ブレイク
H4 BB Opening
```

H4 Dowは観測対象として残してよいが、
通常Entry判定ロジックには接続しない。

### Cycle Guard

```text
H4 Cycle EARLY / MIDDLE → Entry可
H4 Cycle LATE           → Entry不可

H1 Cycle EARLY / MIDDLE → Entry可
H1 Cycle LATE           → Entry不可
```

CycleがUNDETERMINEDの場合は、初期版ではEntry不可として扱う。
Entry頻度が少なすぎる場合は、UNDETERMINEDの扱いを次の緩和候補とする。

### HSI Stop / Target / Close Policy

通常Entryでは、Entryに使用した確定済みHSI起点をStop Priceとして固定する。

```text
Long Stop:
  stop_price = Entryに使用したUP方向HSI起点価格

Short Stop:
  stop_price = Entryに使用したDOWN方向HSI起点価格
```

Stop判定。

```text
Long:
  M5 Low <= stop_price
  → 全建玉StopClose

Short:
  M5 High >= stop_price
  → 全建玉StopClose
```

Targetは、Entry位置が属するHSIエリアの次境界へ固定する。

```text
R2以上 〜 R2.5未満   → Target = R2.5
R2.5以上 〜 R3未満   → Target = R3
R3以上 〜 R3.5未満   → Target = R3.5
R3.5以上 〜 R4未満   → Target = R4
R4以上 〜 R4.5未満   → Target = R4.5
```

Target判定。

```text
Long:
  M5 High >= target_price
  → 全建玉CloseOK

Short:
  M5 Low <= target_price
  → 全建玉CloseOK
```

通常EntryのClose Policyは、`SINGLE_CLOSE`をdefaultとする。

```text
Entry
↓
Target到達
→ 10単位すべてCloseOK

または

Entry HSI Anchor到達
→ 10単位すべてStopClose
```

Partial Close、Target更新、Runnerは使用しない。

### 検証上のEntry頻度目安

```text
0.5回未満 / 営業日
→ 条件が厳しすぎる可能性

0.5〜1.5回 / 営業日
→ 違和感を回収しやすい観測帯

1.5回超 / 営業日
→ 条件が緩すぎる可能性
```

これは利益性能の評価値ではない。
人間がEntry地点を見てルールを育てられるか、という検証体験の目安である。

## B. ReEntry / Expansion Add-on Entry

### 通常ReEntry

通常EntryのClose後、建玉がFlatになり、通常Entry条件が再成立した場合はReEntryを許可する。

ReEntryは前Tradeの継続Positionではなく、新しいEntryとして扱う。

```text
前Trade = 終了済み
新しいReEntry = 新しいTrade ID / Entry ID / Position ID
```

通常ReEntryにも、v0.7の共通Entry Gateを適用する。

```text
H4 T3方向許可
AND H1 DowとM5 Dowが一致
AND H4 Cycle != LATE
AND H1 Cycle != LATE
AND 確定済みHSI起点からR2以上
AND 通常Positionを保有していない
```

ReEntry時点で使用したHSI起点を、そのReEntry専用Stopとして固定する。
Targetもその起点から算出し、1回の全Closeで終了する。

### 通常Add-on禁止

```text
Normal Add-on Allowed = false
```

通常Entry中に新しいHSI起点やM5 Dow確定が出ても、追加建玉は作らない。
それらは既存PositionのStop / Targetも変更しない。

### Expansion Add-on

Add-onはExpansion方向だけで許可する。

```text
Expansion Add-on Allowed =
  Expansion Core Positionが存在
  AND Core Positionが含み益
  AND H4 Expansion方向と同じ
  AND WEEK Expansion Season = OPEN
  AND H4 Cycle PhaseがEarlyまたはMiddle
  AND H1 Cycle != LATE
  AND 新しい確定済み押し目 / 戻り目HSI起点がある
  AND その起点からR2到達
  AND M5 Dow confirmed
```

Add-on禁止条件。

```text
H4 Cycle Late
OR H1 Cycle Late
OR WEEK Cycle Late
OR BBが閉じ始め
OR H1高値更新失敗
OR 価格がMA/T3へ戻り始め
OR Coreが含み損
```

Expansion Add-onは、Coreへ単位を足し込むのではなく、独立Positionとして作る。

```text
Add-on Entry ID
Add-on HSI Anchor ID
Add-on Stop Price
Add-on Target Price
Add-on Units
```

を個別に固定する。

```text
1 Expansion Add-on
= 1 Entry
= 1 Stop
= 1 Target
= 1回の全Close
```

合言葉。

```text
買い増しはナンピンではない。
勝っているExpansion波にだけ追加する。
```

## C. Expansion Pullback Entry

H4でR4級のExpansionが出ても、そこで即Entryしない。

```text
R4到達 = Entryではない
R4到達 = Expansion Watch / 例外アラート
```

R4到達後に押しを待つ。

```text
Expansion Detection Anchor
= Expansion判定用の大起点

Expansion Entry Anchor
= R4到達後の直近押し安値/戻り高値

Entry Trigger Anchor
= 実際にR2判定する確定済み押し目起点
```

④→⑤→⑯パターンなら、

```text
④ = Expansion Detection Anchor
⑤ = Pullback / Entry Trigger Anchor
⑯ = ⑤起点R2 + M5 Dow Up confirmed
```

ただし、勝負している波は⑤ではなく④。

```text
Entry判定  = ⑤起点R2
Hold判定   = ④起点Expansion文脈
Target判定 = ④起点R5以上
```

Expansion EntryのStopは、実際のEntry判定に使用したHSI起点へ固定する。

```text
⑤ Pullback / Entry Trigger Anchor
= Expansion Core Entryに使用するHSI起点
= Expansion CoreのStop Price

④ Expansion Detection Anchor
= Expansion文脈の観測起点
= v0.7では直接のStop Priceにしない
```

Expansion Add-onも、Add-on判定に使用した新しい確定済みHSI起点を、そのAdd-on専用Stopとして固定する。

Expansion Entryでは、通常Entryより大きなTarget候補を使う。

```text
minimum target  = ④起点R5
extended target = ④起点R5.5 / R6 / R6.5
```

```text
Expansion Core Entry
→ Targetを一つ固定
→ Target到達でCore全建玉CloseOK

Expansion Add-on Entry
→ Add-on用Targetを一つ固定
→ Target到達でAdd-on全建玉CloseOK
```

## 7. Expansion候補の再定義

今回の整理で、Expansionは距離だけでは判定しないことが明確になった。

```text

DAYサイクル年齢で格付けする。
```

```text
R4到達はアラート
```

### Expansion Watch

```text

= 確定済み起点からR4以上に到達した状態
```

### Expansion Candidate

```text

= R4到達
  AND H4構造ブレイク
  AND H4 BB Opening / ボラ拡大
```


### Expansion Grade

DAYで格付けする。

```text
これはH4だけの小爆発か？
それとも日足構造を変えに来ている爆発か？
```

を見る。

### Expansion Confirmed

```text
Expansion Confirmed
= Expansion Candidate
  AND 押し/戻りを作った
  AND 押し戻り後に再度継続方向へ動いた
  AND H1/H4文脈が崩れていない
```

### Expansion Invalid

```text

= R4到達後、構造ブレイクできずレンジ回帰
  OR MA20/T3下へ戻る
  OR BB Openingが続かない
  OR DAY格付けでLate Cycle扱い
```

## 8. DAY Expansion Age Rule

今回の最重要追加ルール。

DAY Confirm=45で見ると、1サイクルがおおむね90日級に見える。
つまり、日足安値から45本を超えた場所は、上昇波の前半ではなく後半・成熟期として扱う必要がある。

Long Expansionの場合。

```text
DAY basis = 直近の日足Active Low
day_cycle_age = 現在足 - DAY basis足
```

Short Expansionの場合。

```text
DAY basis = 直近の日足Active High
day_cycle_age = 現在足 - DAY basis足
```

判定。

```text
45本以内:
  Expansion候補として見てよい

45本超え:
  だいぶ怪しい
  Expansion Grade Down / 要警戒

60本超え:
  Expansion扱いしない
  Late Cycle / 調整待ち扱い
```

これはEntry禁止ルールではなく、Expansion判定の格付けルール。

```text
45本超えだから絶対NoTrade
```

ではなく、

```text
45本超えだから、それをExpansionとして扱うのは怪しい
```

という整理。

60本超えたら、もうExpansionではない。

```text
R4到達 / H4で勢いあり
  ↓
でもDAY安値から何本経っている？
  ↓
45本以内ならExpansion候補
45本超えならLate寄り
60本超えならExpansion却下
```

### 22×2意識

```text
22営業日 ≒ 1か月
45営業日 ≒ 約2か月
```

日足で大きな山谷を見るなら、1か月単位より少し長め、つまり2か月級の確認幅が自然。

```text
DAY Confirm 45
= 日足の短期ノイズを捨てて、
  約2か月級の大きな山谷だけを材料点として見る設定
```

### DAYの右端解釈

DAY右端で、緑丸が立ったあとに価格がT3/MA20から浮き、BB上限側に寄っている場合、

```text
上昇は継続している
でも、もうすぐ調整下げが来そう
```

という絵に見える。

この感覚を可視化するために、DAY Confirm=45を暫定defaultとする。

## 9. WEEK Expansion Season / Late-Cycle Entry Guard

WEEKの季節判定は難しいため、初期版では「大波を最大限取る」より「Expansion Entry可能期間を短くする」方向へ倒す。

目的。

```text
取り逃し回避より、高値づかみ回避を優先する。
WEEKの1サイクル後半ではExpansion Entryをさせない。
```

初期状態は、まず2状態で扱う。

```text
WEEK_EXPANSION_OPEN
= Expansion Entry候補を検討してよい

WEEK_EXPANSION_CLOSED
= 新規Expansion Entry禁止
= Expansion ReEntry禁止
= Expansion Add-on禁止
= H1弱化観測を強める（v0.7では直接Closeしない）
```

将来的にはTransitionを追加してもよい。

```text
EXPANSION_ALLOWED
TRANSITION
EXIT_PERMISSION
```

### WEEK Cycle Lateの効果

```text
WEEK Cycle Late = true

Expansion Entry Allowed  = false
Expansion ReEntry Allowed = false
Expansion Add-on Allowed  = false
WEEK Direct Close         = false
H1 Early Exit Trigger     = true
```

重要。

```text
WEEK Cycle Late
≠ 即Close
```

WEEKは「もう新しく乗る季節ではない」「H1で崩れたら早めに降りてよい」という許可を出す。
実際のCloseはH1以下で判断する。

### Late判定の初期候補

最初から完全なCycle判定を目指さない。
次のような終盤要素が増えたら、保守的にCLOSEDへ倒す。

```text
- WEEK起点からの経過バー数が上限を超えた
- WEEKの高値更新 / 安値更新が鈍化した
- WEEK BBの拡大が止まり、収縮へ向かった
- WEEK MA20 / T3の傾きが鈍化した
- WEEKでミニサイクルを複数消化した
- 長期トレンドライン突破後でも、次の週足押し目時期が接近している
```

初期実装では、経過バー数など単純な条件から始め、後からOPEN期間を延長する方向で調整する。

## 15. Close / Stop Architecture

v0.7では、Close Policyを `SINGLE_CLOSE` に統一する。

```text
1 Entry ID
= 1 Stop Price
= 1 Target Price
= 1 Terminal Close Event
```

同一Entryで複数Closeを行わない。

```text
Partial Close = 使用しない
Scale-out     = 使用しない
Runner        = 使用しない
Target更新    = 使用しない
```

### 15.1 通常EntryのClose

通常Entryは、Entry位置が属するHSI帯の次境界をTargetにする。

```text
R2 Entry帯   → R2.5 Close
R2.5 Entry帯 → R3 Close
R3 Entry帯   → R3.5 Close
R3.5 Entry帯 → R4 Close
R4 Entry帯   → R4.5 Close
```

10単位でEntryした場合、Target到達で10単位すべてCloseOKする。

```text
Entry 10単位
↓
Target到達
↓
CloseOK 10単位
↓
Position = Flat
```

### 15.2 通常EntryのStop

StopはEntryに使用したHSI起点価格へ固定する。

```text
Long:
  M5 Low <= Entry HSI Anchor Price
  → 10単位すべてStopClose

Short:
  M5 High >= Entry HSI Anchor Price
  → 10単位すべてStopClose
```

Entry後に別のHSI起点が確定しても、既存EntryのStopを変更しない。

### 15.3 Expansion Core / Add-onのClose

Expansion CoreとExpansion Add-onは、Expansionグループとして関連づける。
ただしPositionは混ぜない。

```text
Expansion Group
  Core Entry     = 独立Position
  Add-on Entry 1 = 独立Position
  Add-on Entry 2 = 独立Position
```

各Positionは、Entry時に一つのTargetを固定し、Target到達で全単位を1回Closeする。

```text
Core Entry
→ Core Target到達
→ Core全単位CloseOK

Add-on Entry
→ Add-on Target到達
→ Add-on全単位CloseOK
```

### 15.4 Expansion Core / Add-onのStop

Expansion Coreは、Core Entryに使用したPullback / Entry Trigger HSI起点をStopにする。

Expansion Add-onは、Add-on Entryに使用した新しい確定済みHSI起点をStopにする。

```text
Core Stop
= Core Entry HSI Anchor

Add-on Stop
= Add-on Entry HSI Anchor
```

Expansion Detection Anchorは大波の文脈観測に使用するが、v0.7では既存PositionのStopを広げる理由にはしない。

### 15.5 H4 / H1 Profit-Take情報の扱い

H4 Cycle、BB Phase、HSI Confluence、H1 Structure Breakは、ExpansionのTarget選択や次のAdd-on可否を考える観測情報として残す。

ただしv0.7では、Entry後に別のClose Eventを追加するためには使わない。

```text
Entry時:
  StopとTargetを固定

Entry後:
  Target到達 → CloseOK
  Stop到達   → StopClose
```

H1/H4構造Exitを再導入する場合は、Single Close契約を壊さず、TargetまたはStopと競合しない独立ルールとして将来検討する。

### 15.6 同一M5足でStopとTargetの両方へ到達した場合

同一M5足内の到達順序はOHLCだけでは分からない。
このケースの優先順位は未確定パラメータとして記録し、Simulation Traceに `AMBIGUOUS_STOP_TARGET` を残す。

初期結果へ都合よくCloseOKを採用しない。

### 15.7 Close理由コード

```text
CLOSE_OK_NEXT_HSI_TARGET
STOP_CLOSE_ENTRY_HSI_ANCHOR
AMBIGUOUS_STOP_TARGET
```

表示例。

```text
R2.5到達：10単位全決済

または

Entry HSI起点 158.305到達：10単位StopClose
```

## 18. 現時点の最重要ルールだけ短く

```text
1. 通常M5 EntryとExpansion Entryを分離する。

2. 通常M5 EntryではH4 Dowを使わない。

3. H4はT3だけで通常Entry方向を許可する。

4. Long許可:
   H4 T3上向き
   AND H4 Close > H4 T3

5. Short許可:
   H4 T3下向き
   AND H4 Close < H4 T3

6. H1 DowとM5 Dowが同じ方向の場合だけEntry候補にする。

7. H4 Cycle Lateでは新規Entry / ReEntry / Expansion Add-on禁止。

8. H1 Cycle Lateでは新規Entry / ReEntry / Expansion Add-on禁止。

9. Cycle UNDETERMINEDは初期版ではEntry不可。

10. HSIのR判定は確定済み起点からしか使わない。

11. 確定済みHSI起点からR2以上をEntry距離条件とする。

12. WEEK / DAY / Expansion Confirmedは通常M5 Entryの必須条件にしない。

13. 1 Entry ID = 1 Position = 1 Stop = 1 Target = 1回の全Close。
```

## 20. 今日の結論

v0.7の最大変更は、複数Closeをやめ、従来のHSIルールに近い単純なPosition管理へ戻したこと。

```text
1 Entry
= 1 Stop
= 1 Target
= 1回の全Close
```

通常Entry。

```text
H4 T3方向許可
+ H1 DowとM5 Dowの一致
+ H4 Cycle Lateではない
+ H1 Cycle Lateではない
+ 確定済みHSI起点からR2以上
↓
10単位Entry
↓
Entryに使ったHSI起点をStopに固定
↓
Entry帯の次HSI境界をTargetに固定
↓
TargetまたはStopで10単位を一度に全Close
```

具体例。

```text
R2 Entry帯
↓
Target = R2.5
Stop = Entryに使用したHSI起点
↓
R2.5到達なら10単位CloseOK
HSI起点到達なら10単位StopClose
```

通常Entry中のAdd-onは行わない。

```text
Normal Add-on Allowed = false
```

通常Close後に条件が再成立した場合は、別TradeとしてReEntryする。

Add-onはExpansionだけで許可する。
ただしCoreとAdd-onを一つのPositionへ混ぜない。

```text
Expansion Core
= Core専用HSI起点 / Stop / Target / 1回Close

Expansion Add-on
= Add-on専用HSI起点 / Stop / Target / 1回Close
```

Scale-out、Partial Close、Runnerはv0.7の現役ルールから外す。

今回の目的は、複雑な建玉管理を先に完成させることではない。

```text
Entry地点を見る
↓
TargetとStopを見る
↓
勝った / 負けたを一度のCloseで理解する
↓
違和感を回収する
```

まずは、人間の頭が追いつく単純な形でSimulationを回し、従来の自分のルールへ近づける。
