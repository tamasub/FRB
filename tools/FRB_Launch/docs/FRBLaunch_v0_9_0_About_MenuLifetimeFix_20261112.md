# FRB Launch v0.9.0｜バージョン情報と設定メニューのライフサイクル修正

## 現象
- 「設定 → バージョン情報...」の後、設定メニューが画面に残る。
- 情報ダイアログがメニューの背面に隠れ、トレイ「終了」などが操作できなくなる。

## 原因
- 設定メニューは、ぐりぐり操作のため、マウスを奪わない `Qt.Tool` の `QMenu`。
- このメニューの `QAction.triggered` 内で同期的に `RemoteConfirmation.ask()` を呼ぶと、元メニューを閉じる前にネストしたイベントループとアプリ全体の入力ガードが始まる。
- `Qt.Tool` メニューが画面上に残った場合、ダイアログが隠れ、他の操作も入力ガードでブロックされる。

## 変更
- 「バージョン情報...」選択時に設定メニューと開いている子メニューを明示的に閉じる。
- `QTimer.singleShot(0, ...)` で、メニューの終了処理がQtイベントループに反映された後に情報ダイアログを開く。
- 連打による情報ダイアログ二重起動を防ぐガードを追加し、ダイアログの成否にかかわらず解除する。
- `RemoteConfirmation` 本体やぐりぐり操作、トレイの終了処理、設定JSONには変更を加えない。

## 対象
- `src/app.py`
- `tests/test_version_about_menu_20261111.py`

## 検証
- バージョン情報のテスト7件 PASS。
- 関連テスト38件 PASS（うち上記7件を含む）。
- 別のFiles Exp既存テスト3件は `QColor` 未定義によりFAILするが、提供元ZIPでも同じ3件がFAILするため、今回の改修による退行ではない。
- Windows実GUIでの操作は未確認。Qt.Tool/ぐりぐりのイベント処理は実機での最終受入が必要。

## Windows実機受入
1. 設定 → バージョン情報... → **設定メニューが消えること**。
2. バージョン情報の **閉じる** と **バージョンをコピー** がマウス・ぐりぐりで動くこと。
3. 情報ダイアログを閉じた後、設定メニューを再度開いて正常に閉じられること。
4. 通知領域（タスクトレイ）の **終了** でLaunchを終了できること。

※確認ダイアログを表示している間は、既存共通の入力保護により背景操作が抑止される。情報ダイアログは「閉じる」で閉じてからトレイの終了操作を行う。
