# FRB Launch 手裏剣「一の手」：ボタン内フリックの上下不安定対策（2026-11-10）

## ユーザーの実際の操作と観測

- 手裏剣「一の手」ボタンの中（50×46px）のみでマウスを押し、上下左右へ移動している。
- 画面上側に表示されるポケモンボール風プレビューへ、マウスは移動していない。
- 左右は比較的自然、上下は追従しない場合があり、押下中に処理が実行されることがある。

## 原因候補（Windows実機では未確定）

1. 前回のプレビューは可視円の半径72pxに対して、透過ネイティブウィンドウの高さが320pxだった。円はボタンの上にあっても、その透明領域が操作ボタンを覆っていた可能性がある。
2. ボタン高さ46pxに対し、方向選択の移動しきい値14pxは特に上下方向で大きい。
3. 16ms監視タイマーは `GetAsyncKeyState` の一度のOFFを実行確定としていた。マウスボタンのReleaseイベント以外で処理を起動できる危険な経路だった。

## 対応

- `ShurikenPreview.CANVAS_HEIGHT` を320→166pxへ縮め、通常の画面位置では透過ウィンドウの下端も「一の手」ボタンの上に収める。大円の半径72px、中央円24px、目玉の位置・ラベルは不変。
- `DRAG_DEADZONE` を14→8pxに変更。ボタンから出ずに上下を動かす操作に合わせる。
- 16msのポーリングは追従更新にのみ利用。**監視タイマー単独で実行確定しない**。
- 一瞬の押下OFF読み取りで起動しない。Qt Releaseイベントが届かずOFF状態が連続した場合は、誤実行を避けてキャンセルする（12回・約192ms）。
- 実行確定は、Qt MouseReleaseがあり、ネイティブ押下状態も解除されている場合のみ。緑の目玉が示した対象をそのまま実行する。

## 変更しない契約

- 件数1〜4の可変レイアウト／5件目以降は無視。
- Studioの表示優先順による割当、JSONの構造。
- 大円半径、中央円、目玉のレイアウト、背景色、ラベル、ポケモンボール風の描画。
- ぐりぐり／Files Exp等、ほかの操作UI。

## 実機の確認ポイント

1. ボタンの中だけで左ボタンを押したまま、上／下へ8～15px移動 → 目玉が期待通りに動くこと。
2. 目玉を選択したまま左ボタンを長く押し続けても、処理が勝手に実行されないこと。
3. 左ボタンを離した瞬間にだけ処理が一度実行されること。
4. 1件、2件、3件、4件の各レイアウトも従来のままであること。
