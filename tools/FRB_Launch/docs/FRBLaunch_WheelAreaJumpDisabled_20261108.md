# FRB Launch：ホイール端での別エリア自動ジャンプ停止（2026-11-08）

## 期待する動作

- ホイールを上端／下端で回し続けても、別エリア（Back、Files Exp、Files List、Bookmarks、Pageなど）へ自動ジャンプしない。
- 別エリアへの自動ジャンプ用「静止時間待ち・入力ロック」を無効化する。端から逆回転したホイールを食い潰さない。
- マウスポインター自動移動がONでもOFFでも、上記は同じ。
- 現在のFiles Listの「ポインター位置からぐりぐり開始する」挙動は維持する。カレント行のジャンプそのものは、今回の修正対象にしない。
- 通常のハイブリッドスクロール・ぐりぐりカレント・手裏剣スクロールの起動／加速／減速／停止は変更しない。
- クリック、キーボード、Pageタブによる明示的な移動は維持する。

## 実装

- `src/expanded_view.py`：`WheelZoneNavigation(enabled=False)` をアプリの標準設定とする。
- `src/wheel_zone_navigation.py`：`enabled=False` の間はジャンプ判定 `feed` と入力ロック `wheel_is_locked` を無効化。
- 機構自体は削除せず、旧動作のテストや将来の実験のために残す。ユーザーに見える自動ジャンプは全域で停止。

## 確認

- `tests/test_wheel_area_jump_disabled_20261108.py`：7件PASS。上下端からの逆回転、ポインター起点、旧機構の分離を確認。
- 関連重点テスト：修正版81件中74件PASS・7件FAIL（元ZIPでは同一テスト75件中68件PASS・7件FAIL）。7件は旧設定値を前提とするテストなどで、元ZIPにも存在。
- 別の旧テスト群も元ZIPと同じ失敗2件を確認済み。
- Windows実機でのホイールイベント、画面表示、手裏剣との体感連動は未検証。

## Windows実機確認のポイント

1. 自動移動OFF、スクロールバーなしのFiles Listで、上下端までホイール回転 → 逆回転で戻れること。
2. 自動移動ONでも、端からほかのエリアへ勝手に飛ばないこと。
3. カレントがポインター位置を起点にする既存動作を維持していること。
4. 手裏剣の自動起動、加速、減速、停止を従来どおり使えること。
