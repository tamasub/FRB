# FRB Launch 一の手：上下追従・押下中の誤実行防止（2026-11-10）

## 対象

ユーザー提供 `launch_app_20261110_135251.zip` を唯一の改修起点とする。

## 観測された問題

- 左右移動では目玉が動く一方、上下移動では追従しない場合がある。
- まだ左ボタンを押しているのに対象処理が実行される場合がある。

## 原因候補（実機未確定）

従来の `ShurikenButton` は Qt の `mouseMoveEvent` のみで選択を更新し、`mouseReleaseEvent` が来ると無条件に実行していた。ガイドは別の透過 Tool ウィンドウのため、Windows側のマウス捕捉が変化すると移動イベントの欠落や意図しない Release 通知につながる可能性がある。Windows固有の根本原因は未検証。

## 対応

- 押下中、`QTimer` (16ms) と `QCursor.pos()` により位置を追跡。Qt の `mouseMoveEvent` も従来どおり利用する。
- Windowsでは `GetAsyncKeyState(VK_LBUTTON)` で物理押下状態をチェックし、押下中に届いた Qt Release では実行しない。
- Qt 側で Release が欠落しても、実際のボタンアップをタイマーが検出して一度だけ確定する。
- **描画済みの緑の目玉を最終選択とする**（ボタンアップ時に別の角度で再判定しない）。
- 選択結果が変わらないポーリングでは、ガイドを再配置・再描画しない。
- ボタンが非表示になったら、追跡を解除してキャンセル。

## 変更しない契約

- 1〜4件の可変扇形、表示優先順、時計回りの割当、5件目以降の無視。
- 3件のときの手描き図、2件の左右、4件の上下左右。
- 円半径72px、中央リング24px、目玉位置、ラベル、Release時の実行連携。
- 設定 JSON、ViewDef、Studio本体には変更なし。

- WindowsネイティブAPIの読み出しもモックで検証。Windowsでの実機フリック確認は別途必要。
- 旧テストには「現在の一の手は3件」という固定前提があるが、現行個人設定は4件のため、今回以前から失敗するテストが残る。テスト数の増減をバグ判断に使わず、契約ごとのテストで評価すること。

## Windows 実機の確認ポイント

1. 1件：上へ押したまま動かす→目玉は上へ、下/左右は中央、離すまでは処理を実行しない。
2. 2件：左右へ動かす→左右の目玉、上下は無選択。
3. 3件：左上/右上/下の3方向、中央に戻した場合はキャンセル。
4. 4件：上/右/下/左。上下へゆっくり動かしたり、そのまま保持したりしても Release まで処理が実行されない。
5. プレビュー上へカーソルを移動しても、追従が途切れない。
