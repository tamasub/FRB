# FRB Launch ― ポインター自動移動OFF時のList逆走防止 (2026-11-08)

## 目的・判断

手裏剣スクロールは正式版の標準機能として維持する。今回は「ハイブリッド方式を諦める」のではなく、**物理マウスポインターを動かさない状態で、同方向のぐりぐりに対してListのカレントが逆走しない**ことだけを実験・修正する。

## 再現した問題

- マウスポインター自動移動をOFFにする。
- Listの画面下端付近で物理ポインターを下から5～6行目に置く。
- 手裏剣後または通常のスクロール・追従の切り替え後、下向きにホイールを回す。
- 以前の処理では、スクロール位置が変わるたびに追従アンカーが破棄され、固定ポインターの下にある古い行から追従を再開し、**下へ回したのにカレントが上へ戻る**ことがあった。

Qtを使わない既存のListハンドラ再現環境では、選択行28・ポインター下の行24・下向き1ノッチという条件で、**元のFULL版は25行目へ逆走、今回版は29行目へ前進**することを確認。

## 今回の修正

- `src/wheel_adaptive.py`：`monotonic_edge_anchor` を新設。選択カレントとホバー行のうち、実際のホイールの進行方向に逆行しないものを基準にする。
- `src/expanded_view.py`：Files Listの `wheel_middle_at_edge` で、ポインター自動移動OFFの場合にだけ上記の制御を適用。継続追従中の既存の1行ずつの精度は維持。
- ポインター自動移動ONは従来のホバー起点のまま。
- 通常のスクロールバー操作・手裏剣自動発火判定・加減速・着地処理は無変更。

**注意**：今回はGUIのQtイベント自体を完全に再現できていない。Windows実機で逆走が残る場合は、別経路（カレントの自動修復、実際のマウス移動イベント、スクロール時の項目再生成等）を追加調査する必要がある。変更を本番確定するのは実機で確認してから。

## 回帰確認

- 新しい単体・イベント再現テスト：`tests/test_vdi_reverse_only_guard_20261108.py`。下方向の繰り返し操作、アンカーの消失、上方向の操作、ポインターONの従来動作などを確認。
- 既存の抽出ハンドラをテストできるよう `tests/test_wan_middle_files_20261025.py` のテスト用グローバルに関数を追加。
- `tests/test_vdi_no_cursor_warp_20261026.py` の過去のソース文字列固定チェックを新方式に合わせた。
- 選択した12テストファイル：**117 PASS / 10 FAIL**。FAILの10件は元のFULL版でも同じ内容で発生。主に旧仕様に固定されたテストのため、今回の修正による増分失敗ではない。
- 依存のないPythonコードは構文検査済み。Qt/PySide6のWindows GUI実機動作までは未確認。

## Windows実機での重点確認

1. ポインター自動移動OFF／Files Listの大量ファイルを表示。
2. ポインターを下から5～6行目に固定し、下へぐりぐりして最終行まで到達。
3. そのまま下へ回して、カレントが上へ戻らないことを確認。
4. 手裏剣を自動起動し、末尾で止めてから同じ操作を繰り返す。
5. 上方向のぐりぐりでも逆走しないこと、ポインター自動移動ONでは従来操作を維持することを確認。

別の副作用が出た場合は、元の `FRBLaunch_ポインターOFF_手裏剣着地追従修正_20261108_FULL.zip` に戻して切り分ける。
