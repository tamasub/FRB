# FRB Launch 共通Interaction／Exp・List右クリックの回帰修正

- 基準: `launch_app_20261112_110708(1).zip`（本ZIPを正本とする）
- 対象: Launchのみ。Studio Change Coreや設定JSONの実データは変更しない
- 状態: 静的・Qt不要テスト済み／Windows実画面受入待ち

## 目的・判断

- Exp列での全コンテキストメニューに **「List列へ進む」**、List列での全コンテキストメニューに **「Exp列へ戻る」**を共通追加する。
- 旧「戻る」「進む」を列切り替えと取り違えない。列切り替えはナビゲーション履歴を変更しない。
- リモコンの表示・非表示によってメニュー操作の可否を変えない。
- 選択されたダイアログのOK/CancelはLaunchの任意の面をクリックして確定する。ただし、ダイアログ内で実ボタンを直接クリックした場合は、その実ボタンを優先する。
- バグを個別入口に貼り付けて回避するのでなく、入口を共通操作契約へ接続する。

## 今回特定した抜け

1. Listの現在位置が設定JSONのPage/カテゴリーのとき、とんとん親帰り用余白の右クリックが実フォルダー用メニューに流れていた。ファイルパスがなければ無表示になり得る。
2. Listヘッダー（Files List）が共通の右クリック入口に接続されていなかった。
3. Expヘッダーは埋め込み表示時に右クリックメニューを早期終了する条件があった。
4. Listに対象フォルダーがない場合、右クリックで列切り替え専用メニューを表示するフォールバックがなかった。

## 修正

- `src/files_column_context.py`：`Exp→List`・`List→Exp`の表示名、アイコン、dispatchを単一箇所に定義。
- `src/app.py`：共通install、表示済みメニューを閉じてから列切り替え。背景で対象がない場合はナビゲーション専用メニューを提示。
- `src/expanded_view.py`：Listの余白、親帰りエリア、見出しを`show_list_background_context`へ集約。設定JSONと実フォルダーのメニュー経路を正しく分離。
- `src/remote_files_explorer.py`：Expヘッダーは埋め込みでも共通メニューを提示。移動・整列の機能はフローティング時のみ維持。
- `src/remote_confirmation.py`：Launch全域のクリック確定と、ダイアログ実ボタン優先を共通化（前段作業で実装済みの差分を含む）。
- テスト：新しい入口の契約テスト、旧ナビゲーション期待値から新しい列切り替え契約への更新。

## 検証範囲

- Qtを使わない実コード抽出テスト：列の表示名、単一登録、ページ直下・実フォルダー・対象なしの右クリック、クリック先・キャンセル優先、入口が共通化されていることを確認。
- 2026-11-12検証：関連テスト51 PASS、1 FAIL。FAILは`test_new_folder_file_markdown_exist_before_inline_rename`で、`notify_folder_mutation`を持たない古いテストモックの不一致。**元ZIPでも同じ失敗**。
- GUI環境にPySide6がないため、実機のWindowsネイティブ右クリックとホイールイベントは未受入。テストPASSを実機PASSと混同しない。

## Windows受入チェック

1. Expルート余白、設定JSONフォルダー、登録済みFilesルート、展開実フォルダー、PC、Expヘッダー：右クリックでメニューが出て「List列へ進む」がある。
2. Listの設定JSONページ、カテゴリー配下、末端メニュー、実フォルダー、余白、とんとんエリア、Files List見出し：右クリックでメニューが出て「Exp列へ戻る」がある。
3. リモコンあり／なし：右クリック→ホイール→クリックで、同じメニュー項目を実行。メニュー残留なし。
4. ダイアログ：OKをぐりぐり選択後、Launch上の余白をクリックするとOK。実Cancelボタンを押した場合はCancel。ダイアログ外の別アプリのクリックでは確定しない。
5. 列の切り替えで表示中のページ・ディレクトリ・選択アイテムを変化させない。物理ファイル操作と設定JSONの保存処理を起動しない。
6. 設定JSONから実フォルダーに入って`←`で元の設定JSONに戻る動作、簡易編集コンボのハイブリッド方式は**今回のWindows実機で引き続き確認する残課題**。今回のコード差分で修正完了と断定しない。

## リスク・残課題

- PySide6の実GUI／Windowsイベント配信経路は未実証。再現する入口をスクリーンショットと操作条件で再報告してもらい、ソース上の接続点と照合する。
- GUI共通化を今後さらに進める場合は、Menu/Buttons/ComboのAdapter責務とGUI回帰テストを優先する。テストモックの古い仕様に合わせて本体を個別化しない。
