# 一の手：上下ドラッグ時のプレビュー瞬断・押下中実行対策（診断版）

## 症状（Windowsユーザー報告）
- 左右移動では目玉が自然に追従するが、上下移動では目玉が動かないことがある。
- マウスを放していないのにアクションが実行される。
- 上下へ動かすとポケモンボール風プレビューが一瞬消えることがある。
- 操作するのは 50×46px の「一の手」**ボタンの内部のみ**。プレビューは見るだけ。

## 対策（実機未確認）
1. `ShurikenPreview.present` で、表示中・同一ボタンの目玉更新は **再配置も `show()` もせず再描画だけ**にした。Qtの別ウィンドウを選択変更のたびに動かさない。
2. Releaseを受けても即実行しない。Windows側の左ボタン解除が約80ms（5回×16ms）継続した場合のみ、**目玉に表示していた選択**を1回だけ実行する。
3. 一瞬だけ物理押下状態が解除されたように見えてもプレビューを閉じない。Qt Releaseが来ないまま約1.5秒押下解除状態が継続した場合は安全側で**キャンセル**し、実行はしない。
4. `first_hand_trace.py` を追加。プレビュー表示／非表示、イベント受付、選択変更、キャンセル／確定／実行のタイミングをログに記録する。個人の項目名・コマンド・パスは記録しない。

## 不変条件
- 一の手は登録数に応じ1〜4件、5件目以降は無視。
- Studio側は表示対象と優先順だけ定義。方向はLaunch内部で決定。
- 円の半径72px、中央円半径24px、目玉半径12.5px、目玉移動42pxは維持。
- 実行先は、最後に描画された目玉と同じIDとする。
- その他のボタン、Files Exp/Files List、JSON設定には変更なし。

## Windowsでの確認方法
1. Launchを終了して差分ZIPを適用後、起動する。
2. 「一の手」ボタンを押したまま、**ボタンの内部だけで**上下、次に左右へ動かす。目玉の追従とプレビューの点滅を確認する。
3. 押したまま保持し、意図しないアクションが実行されないことを確認する。
4. 離した後に一度だけ実行されるか確認する。実機GUIはここで初めて検証できる。
5. 異常があれば `%LOCALAPPDATA%\FRBLaunch\first_hand_trace.log` を確認。

### ログの見方（主なイベント）
- `preview_show` / `preview_hide_event`：表示／消失
- `eye_changed`：目玉の選択変更（`slot:0` は未選択）
- `qt_release_ignored_held`：Qt側のReleaseが来たが物理ボタンは押下中、実行せず継続
- `qt_release_candidate` → `release_confirmed` → `execute`：押下解除が安定してから実行
- `native_up_without_release` → `button_state_recovered`：一時的なボタン状態不整合が復帰
- `cancel_missing_qt_release`：Qt Releaseが来ず、安全にキャンセル
- `button_hide_event`：操作ボタン自体が非表示にされた

※ ログは最大256KB＋旧1世代。公開版では`src/first_hand_trace.py`の`FIRST_HAND_TRACE_ENABLED=False`に変更可能。
※ 症状の根本原因はまだWindows実機では特定できていない。今回のZIPは対策と観測を兼ねる診断版。
