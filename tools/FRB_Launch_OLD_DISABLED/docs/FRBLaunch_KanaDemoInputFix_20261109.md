# FRB Launch — デモ操作時のかな入力／ファイル名編集修正（2026-11-09）

## 入力基準

`launch_app_20261109_162352.zip` を変更元とする。

## 利用者が報告した再現条件

1. Launchの検索・履歴画面ではWindows IMEを半角英数字として扱う。FRBかなフリックを開いたときは、かなモードならIMEを日本語入力へ戻してほしい。
2. Files Listでファイル名の一部が選択されている場合、かなフリックの「送信」は選択範囲を置き換える。単なるカーソル状態の場合はその位置へ挿入する。意図せぬ全置換を避ける。

## 実装

- `src/remote_kana_integration.py`:
  - FRBかなを表示するたび、フォーカス確定後に日本語IME状態の再指定を要求する。既存の検索欄のIME=英数既定は変更しない。
  - `QApplication.focusChanged` はフォーカス喪失**後**の通知なので、ここで選択範囲を再採取すると空選択でスナップショットを消してしまう。これを禁止。
  - メニューがフォーカスを取っても実際にFiles List / Files Expで編集中のリネーム入力欄が存在する場合は、その入力欄を送信先として優先する。単に選択されているファイル行からは推測しない。
- `src/remote_kana_target.py`:
  - `selectionChanged` に加えて `cursorPositionChanged` を追跡。IME側への切替前に保存しておいた選択範囲またはキャレット位置を利用する。
  - テキスト内容が変わっていない場合に限り、対象入力欄の選択範囲／キャレットを復元し、Qt標準の `QLineEdit.insert` / `QTextCursor.insertText` で編集する。
  - 送信済み文字列の再置換は行わない。複数回送信は前回の挿入位置から継続。
  - Qtテキスト欄以外の通常ファイル行を送信先とみなさない。外部アプリへの送信は既存のWin32 Unicode SendInput契約を維持。
- `experiments/frb_japanese_input/frb_japanese_input.py`:
  - かなモード／編集欄へのフォーカス確定／未確定IME変換なしの場合だけ、日本語IME状態を再指定する。
  - ABC/数字/記号ではかなIMEを強制しない。IMEが使えないWindows環境では、エラーをステータスに表示する。
