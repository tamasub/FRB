# 一の手｜長押し開始判定とReleaseチャタリング対策（2026-11-10）

## 起点と目的
- 起点：ユーザー提供 `launch_app_20261110_215510.zip`。
- 観測：一の手ボタンの長押しだけでもプレビューがちらつき、意図しないReleaseを経由して確認画面へ移行する場合がある。Windowsエクスプローラーでも長押しがダブルクリックとして認識される場合がある。
- 今回の目的：**プレビューのちらつきにつながる短いPress・Releaseを、操作確定の前に抑制する。** マウスのハードウェア故障自体を修復するものではない。

## 変更後の入力契約

| フェーズ | 条件 | 実際の動作 |
| --- | --- | --- |
| 最初のPress | 250ms未満でRelease | プレビュー表示なし、候補なし、実行なし |
| 最初のPress | 250ms継続 | ポケモンボール風プレビューを初めて表示する |
| フリック中 | マウスMove | 1〜4件の共通選択判定は従来どおり。目玉のみ更新 |
| フリック中 | 一度Release | 120ms保留。プレビューは維持。確認に進まない |
| 保留中 | 120ms以内に再Press（Qtのダブルクリック2回目も含む） | 同じフリックを継続。目玉を維持し、確認画面を開かない |
| 保留中 | 再Pressなしで120ms経過 | 最後に見えていた目玉が中央ならキャンセル、項目なら同一IDの確認画面へ |
| 確認画面 | 表示から250ms以内に開始したクリック | 無視（前回からの仕様） |
| 確認画面 | 上記時間後の新規クリック | 初期Cancelでも応答可能。OKはぐりぐり／直接ボタンで明示選択した場合のみ実行 |

**原則**：最初のReleaseも、保留タイマーも、機能を実行してはならない。ZIP作成などの実行には別途OKの明示操作を必要とする。確認中のぐりぐりルーティングや1〜4件の配置は変更しない。

## 自動テストと差分
- 長押し開始／短い押下／上下左右の候補固定／Release→再Press／二重クリック／中央へ戻すキャンセル／明示的OKを新規12件で検証。
- 関連集中テスト：134件PASS（ヘッドレスのQt模擬環境）。
- `test_*shuriken*`・`test_first_hand*` の周辺：284件PASS・12件FAIL。元ZIPでは271件PASS・13件FAIL。残る失敗は主に既存のぐりぐり自動スクロール系、およびログ出力パスのテストで、今回の一の手改修によって新たに発生した失敗は確認されていない。
- `src/remote_shuriken.py` の構文チェック：PASS。
- Python上の模擬マウスイベントの確認であり、**Windows + PySide6の実機GUI動作は未確認**。

## Windows実機の確認ポイント
1. 一の手を素早くクリックして離す（250ms未満想定）：プレビューは出ない。
2. 一の手を押し続ける：およそ250ms後に一度だけプレビューが表示される。
3. 長押しで上下左右に動かす：目玉が安定するか。上へ動かした後に中央へ戻すケースを重点確認。
4. 上選択のまま離す：120ms程度後に確認画面が開く。**まだ実行はされない**。
5. 確認画面上でCancel／OKをぐりぐりで選択し、一の手をクリックして確定できること。
6. ちらつきや誤遷移が残る場合、診断ログで `first_hand_press_qualified`、`first_hand_release_candidate`、`first_hand_release_bounce_suppressed`、`first_hand_release_settled` の時系列を見る。

## 制限事項
- この方式ではフリック開始時の操作感に最大約250ms、Releaseの確認画面への切替に約120msの待ち時間が加わる。
- 120msより長いチャタリングやWindowsによるウィンドウ非表示の別経路には、追加の検証が必要。
- ファイル・フォルダーのDrag＆Dropは実装していない。ユーザーデータの移動／上書き操作は本修正の対象外。
