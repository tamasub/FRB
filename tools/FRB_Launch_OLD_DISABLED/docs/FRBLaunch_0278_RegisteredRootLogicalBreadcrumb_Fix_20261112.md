# FRB Launch 0278 — Files登録ルートの論理パンくず統一・親混線修正

対象: 0277 の `FRBLaunch_0277_full_20261112.zip`。
設定JSONおよび登録済み物理ファイルは変更しない。

## 発見された事象

1. `testwk > zz` を参照したあとで `FRB_docsExcel` に登録されている物理フォルダー `設計書` を開くと、パンくずが `testwk > zz > 設計書` になる場合がある。
2. Files Expに `FRB Root` として登録した `F:\FRB` を開くと、パンくずが `F:\ > FRB` と物理パスから再構築される。

## 原因

- `go_to_directory()` が明示的なJSONマウント元を受け取らない場合も、直前の `_virtual_directory_node` を新しい実フォルダーの出発元として流用していた。
- JSONマウントと直接パス入力の起点は0277で定義済みだったが、**Files Expに登録された実フォルダーの起点（登録名・登録ID）**をパンくずと履歴へ渡す契約が不足していた。

## 0278の仕様

- **JSON内の登録フォルダー**: 例 `testwk > zz > サウンド レコーディング`。今までどおりJSONの親子を表示。
- **Files Expの登録フォルダー**: 例 `FRB_docsExcel > 設計書`。登録した `FRB_docsExcel` が論理ルート。物理親 `F:\` へ遡らない。
- **別名登録**: `FRB Root` の実体が `F:\FRB` ならパンくずは `FRB Root`。その子なら `FRB Root > tools` のように表示。
- **直接パス入力**: 前回の仕様どおり入力した実パスが新しい独立起点。登録ルートと混同しない。
- **上部「←」ボタン**: 訪問場所の論理IDも履歴へ記録。登録ルート同士または直接パスと同一実パスでも区別。
- **「←」キー**: Files List先頭からExpへカレント移動。登録ルートがある場合は、その登録のExp枝へ同期。
- **「↑」ボタン**: 登録ルート内は親へ進むが、登録ルート境界では物理親へ上がらない。
- **実パス**: パンくずのツールチップ・編集欄から確認できる。実際のファイル操作には変更なし。

## 修正箇所

- `src/expanded_view.py`: JSON起点の暗黙流用を廃止。登録実フォルダールートを保持し、パンくず・Up・履歴へ渡す。
- `src/remote_files_explorer.py`: 選択中のFiles Exp枝から登録ルートID・表示名・実パスを取得。Exp同期ではそのIDを優先。
- `src/app.py`: Exp選択時に登録ルート情報を引き継ぎ、Exp/List・「←」キーの同期でも使用。
- `src/directory_navigation_history.py`: 登録ルートID + 実パスを履歴キーへ追加。復元時も登録ルートを保持。
- `tests/test_launch_0278_registered_root_breadcrumbs_20261112.py`: 主要ケースのheadless回帰テストを追加。

## 実機での重点確認

1. `testwk > zz` から `FRB_docsExcel` の `設計書` へ移動 → `FRB_docsExcel > 設計書` が表示され、Expも同じ枝を選択する。
2. `FRB Root` をクリック → `FRB Root`（子フォルダーへ進むと `FRB Root > ...`）になる。`F:\ > FRB` にはならない。
3. `FRB Root > tools` から「↑」→ `FRB Root`。もう一度「↑」しても `F:\` へ移動しない。
4. 「←」キーでList先頭→Files Expへ移り、同じ登録ルートの枝が選択される。
5. 上部履歴「←」で JSONフォルダーと登録ルートの行き来ができる。
6. `testwk > zz > サウンド レコーディング` の旧動作と、直接パス入力起点の旧動作に影響がない。
