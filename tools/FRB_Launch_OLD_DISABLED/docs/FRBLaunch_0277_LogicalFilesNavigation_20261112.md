# FRB Launch 0277 — Files論理パス統一 / JSONパンくず / Expマウント

対象の入力正本：`launch_app_20261112_184234.zip`（2026-11-12）。

## 決定した不変条件

- **Exp・List・パンくず・履歴Back・Left・Upで参照する階層は、同一のLaunch論理パス。**
- **上部の「←」ボタン**：訪問先の論理ロケーションを履歴として1件戻す。直前の階層に戻るとは限らない。Forwardも同じ履歴。
- **「←」キー**：Listの途中ならまず先頭行へ。次の「←」でExpへ操作列を戻し、Expで**現在表示中の論理フォルダー**を選択。訪問履歴も物理親もたどらない。
- **「↑」ボタン**：現在の論理パスの親へ。JSONから接続した物理フォルダーの入口で押せばJSON上の親（例：`testwk > zz`）。
- **パンくず**：すべてクリック可能なLaunch論理階層。単一テキスト `testwk › zz` ではなく、各セグメントが個別の行き先を持つ。
- **物理パス**は読込・実行・ディスク操作のために保持。パンくずバー・接続済みフォルダーのツールチップと編集欄から確認できる。
- **青い「→」で明示した絶対パス**は、新たな独立論理起点と実パスの両方になる。Expにはそのフォルダー自体をルートとして置き、Cドライブ上位の親をExpへ展開しない。「↑」では起点の上へ行かない。ただし上部の履歴「←」では入力前の場所へ戻れる。
- **同じ実パスに複数のJSON登録元**があっても、`page_id / item_id` を含む論理識別子で区別する。実パスだけで戻り先を決定しない。

## 主要ユースケース

```
Files Exp                          Files List
▼ 💟 testwk
  ▼ zz                 →  zzの直接の子を表示
    ▼ サウンド レコーディング  → C:\Users\...\サウンド レコーディング の中身
      ▶ 実際の子フォルダー    → そのフォルダーの中身
```

「サウンド レコーディング」は設定JSONで登録した**実フォルダーへのマウントポイント**であり、実フォルダーの `C:\Users\...` の親をExpへ生成しない。JSON構造と物理ディレクトリ構造はマウント以降だけ接続する。

`testwk › zz › サウンド レコーディング › 子フォルダー` のパンくずは、JSONと物理の境界をまたいで一体の操作になる。「zz」を押せば「zz」のListへ戻る。

## 実装範囲

- `launch_virtual_tree.py`：登録された `item_kind=directory` を `linked_directory` として扱う。List上でも `directory` 表示を維持。
- `remote_files_explorer.py`：Linked nodeのExp行を投影し、下位実フォルダーだけを遅延生成。物理祖先によるExp同期を避ける。直接パス入力のルート行を追加。
- `expanded_view.py`：共通パンくず、JSON識別子クリック、マウント/直接入力の起点、Left/Up制御、訪問履歴。
- `directory_navigation_history.py`：JSONノードID、マウントID+実パス、直接入力起点+実パスを独立した履歴キーへ。
- `directory_entry_origin.py`：`linked_directory` の起点を保持。
- `app.py`：表示切替時のExpカレント同期とList→Expのキー操作を論理パス基準に。
- `tests/test_launch_logical_navigation_0277_20261112.py`：追加のheadless回帰テスト。
- `tests/test_launch_0274_four_followups_20261112.py`：旧仕様「LeftでJSON親へ戻る」を今回の承認済み仕様（LeftはExpへ戻る／Upは論理親へ）に更新。

設定データ `config/frb_launch_sample_data_v0_1.json` は変更しない。登録済みパスを書き換えず、画面上の投影・ナビゲーションだけ変更する。

## 検証と限界

- Python全ソースの構文コンパイルと、変更範囲のheadlessテストを実行。
- 本環境にPySide6がなく、**Windows上の実際のクリック、キーフォーカス、Expツリー描画、D&Dの実機検証はできない**。テストPASSをGUI完了の保証とはしない。
- 以前のテストには、0277以前の意図や既存実装との差を検査する古いstatic assert／不完全モックが残っている（今回と無関係な失敗が存在）。新しい0277テストを検証基準とする。

## Windowsで確認してほしいこと

1. `testwk > zz` のListに `サウンド レコーディング` がディレクトリとして表示され、Expにも `zz` の子として表示される。
2. クリックして内容を開いたときExpがCドライブの親階層へ飛ばず、`testwk > zz > サウンド レコーディング` を選択する。
3. 実フォルダー内の子へ入って「←」を2回（途中行の場合）押す。List先頭行→Exp現在地の順に移動する。
4. 「↑」で物理の子→サウンド レコーディング→`zz` と戻る。`OneDrive` / `Users` には上がらない。
5. パンくず `testwk › zz › サウンド レコーディング` の `zz` をクリックするとzzへ。バーにマウスを置くと実パスを確認できる。
6. 青い「→」で `C:\Users\tsub-\OneDrive\Pictures` を直接入力する。独立起点としてExpに見え、その下だけ展開。UpはPicturesより上に行かないが履歴Backは以前のJSON状態へ戻る。
7. 同じ実フォルダーを別々のJSONカテゴリへ登録しても、Expに現れる場所と履歴Backが混線しない。
8. Home／ブラウザ／ブックマーク／実ファイル実行の従来動作を簡易確認。
