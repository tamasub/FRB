# FRB Launch — 手裏剣スクロール自動起動の継続回転補助判定（2026-11-08）

## 事象と確認できた原因

- ホイールによるエリアジャンプをOFFにした最新版で、手裏剣がなかなか走り出さないと報告された。
- **前版と最新版のファイル比較では、手裏剣起動判定のソース自体は変更されていない。** エリアジャンプOFFとの因果関係はコード比較だけでは確定できない。
- しかし従来起動条件 `AUTO_SHURIKEN_MIN_SPAN_MS=220` と `AUTO_SHURIKEN_MIN_RATE_NPS=25` は、1イベント1ノッチの入力では両立しづらい。例：4ノッチが220msに分布すると約18.2ノッチ/秒で条件未達。
- 原版の `WheelShurikenGate.feed()` を使い、**1ノッチ/80msを30回続けても起動しない**再現ケースを確認した。

## 変更内容

- `src/guriguri_shuriken_auto.py` に**継続ぐりぐり補助判定**を追加。
- 「高速バースト判定」は元の条件・調整値を保持する。
- 追加の継続判定：同方向、同一入力元、同一時間窓内で **7イベント・7ノッチ以上かつ420ms以上継続**した場合に起動。
- 従来の `AUTO_SHURIKEN_WINDOW_MS=700`、`MAX_GAP_MS=150`、逆方向や入力元切替によるリセット、再発火禁止時間も適用。
- 調整値は**同じソース冒頭**に集約。`AUTO_SHURIKEN_SUSTAINED_ENABLED=False` で補助判定だけOFFに戻せる。
- 手裏剣スクロールエンジン（起動後の滑走・加減速・停止）、List高速ハイブリッド、ポインター起点、エリアジャンプOFFのコードは変更しない。

## 操作上の制約

- **スクロールバーに可動範囲がないListでは、手裏剣の滑走先が存在しないので発動しない。** これは設計上の既存仕様。
- すでに上端で上向き、または下端で下向きにいる場合も、その方向には滑走できない。
- 実機確認は、スクロールバーが動ける大きなフォルダーで、バーの中間位置から行う。
- フォーカス、物理ホイールイベント、Windows/Qt描画の実機検証は未実施。

## テスト結果

- 新規 `tests/test_shuriken_sustained_wheel_20261108.py`: 8件PASS。
- 周辺重点テスト: 49件PASS、11件FAIL（うち11件は最新版**元ZIP**でも同じFAIL。旧チューニング値とテストの固定期待値が不一致）。
- 元ZIPに新規テストを追加して同じ一式を実行すると、45件PASS、15件FAIL。新規テストの4件が修正前に失敗し、修正後にPASSになった。

## 所長の試験手順

1. Launchを完全終了。差分ZIPをLaunchルートに上書き、`_run_windows.bat` で起動。
2. **スクロールバーが表示されるList**で、バーを真ん中付近にする。
3. マウスポインター自動移動OFFのまま、下方向へ1ノッチを連続して7〜10回程度ぐりぐりし、手裏剣が始まるか確認。
4. 逆回転で減速できるか、通常のクリックや端で停止できるか確認。
5. List端で連続してぐりぐりしても、別エリアへ自動ジャンプしないことを確認。

## 戻し方

`src/guriguri_shuriken_auto.py` 冒頭で `AUTO_SHURIKEN_SUSTAINED_ENABLED = False` に変更すれば、元の高速バースト判定のみに戻せる。
