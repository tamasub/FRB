# FRB Launch — マウスポインター自動移動OFF時のListカレント迷子対策

## 現象（実機報告）
- Files Listを下方向にぐりぐりすると、末尾付近でカレントがマウスポインター近辺へ戻り、また末尾へ進むような挙動がある。
- ポインター自動移動OFFの場合、マウスの物理位置は固定される。
- 手裏剣スクロールは正式機能として残す。

## 再現したコード上の原因
- 手裏剣停止後に `remote_scroll_files_list_settle` が List の**最終行**（または停止位置の中央行）を `currentItem` に引き継ぐ。
- 一方、`wheel_middle_at_edge` はスクロール端で新たなホイール入力を受けると、追従セッションの記録が無い場合、**物理マウスポインター下の行**から始める。
- ポインターが末尾から5〜6行上に残っていると、手裏剣着地で最終行に移ったカレントが次のホイール入力で過去の行に戻り、往復して見える。

## 対応（最小変更）
1. `src/app.py`: 手裏剣着地時に `currentItem` が決まり、かつマウスポインター自動移動OFFで、ポインターが実際にList内にあれば、同じポインター座標を `_middle_vdi_anchor_pos` として登録する。次回の端追従は**着地後のカレント行**から続ける。
2. `src/expanded_view.py`: List内で**物理ポインターが実際に移動した場合**だけ、固定ポインター追従アンカーをクリアする。座標が変わらないマウス移動通知では消さない。
3. 手裏剣の起動条件、物理スクロールエンジン、加速・減速値、既存のスクロール優先ハイブリッド、選択済ファイル一式は変更しない。

## ローカル確認
- 新規テスト `tests/test_warp_off_shuriken_handoff_20261108.py`：5件PASS。
- 同じテストを元のZIPに適用すると、停止後アンカーの不足に関する期待値が失敗することを確認。
- 周辺のQt非依存テストで変更に起因する追加の失敗なし。古いテスト9件の失敗は元ZIPでも同一（ユーザー調整済みの手裏剣起動・減速パラメータと、古いGitダイアログサイズ期待値に関連）。
- この実行環境にはPySide6/Windows UIがないため、Qt実機の描画・イベント連鎖そのものの再現は未検証。

## Windows実機でお願いしたい確認
1. **OFF**・File List で System32 等の多数ファイルを表示。画面下寄り（末尾から5〜6行上）にマウスポインターを置く。
2. 下方向へ高速ぐりぐり→手裏剣を発動→最下端まで自然停止。
3. ポインターを動かさず、さらに下へぐりぐり。最終行から過去の行へカレントが飛び戻らないこと。
4. 逆方向にぐりぐり→普通のスクロールが戻ること。実際にマウスを動かしたら、そこからの通常追従に戻ること。
5. **ON** に切り替え、従来のポインター自動移動・手裏剣を確認。
