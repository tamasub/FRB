# FRB Launch — List右クリック確認のぐりぐりクリック受付（2026-11-10）

## 症状
Files Listのファイルを右クリック → Gitコミットなどの確認ダイアログで、ぐりぐりのホイールでYes/No・OK/Cancelの選択はできるが、クリックしても確定できない。

## 原因（コード上）
`RemoteConfirmation` と `RemoteTextDialog` は、List上のWheelイベントを `ConfirmationInputGuard` で確認応答へ転送していたが、MouseButtonPress/Releaseイベントはすべて背景入力として遮断していた。また、確認表示中の実際の「ぐりぐり」ボタン押下を、ダイアログの選択確定へ直接結ぶ保証がなかった。

## 対応
`src/remote_confirmation.py` の `ConfirmationInputGuard` だけを変更。

- ぐりぐり本体：確認中の明示的な左クリック（Press→Release）を、ダイアログの現在選択中のボタンの `click()` に直接転送。`WheelPad` 本来のCLICKとは二重発火させない。
- Files List：同じListのホイールで確認ボタンを選択した後だけ、List上の明示的な左クリックを同じ確認へ転送。元のList選択・ファイル開封には渡さない。
- ダイアログ上のOK/Cancel・Yes/Noの直接クリックは従来どおりQtネイティブ操作を許可。
- 受付条件：確認表示から250ms以上経過してからの新規Press、左ボタンの対応したRelease、同じウィジェット、移動6px以内、押下継続1.5秒以内。
- 無効化：開くきっかけの古いRelease、PressのないRelease、右クリック、ダブルクリック2発目、ドラッグ、別ウィンドウでのクリック、対象未選択のListクリック、Browser上のクリック。
- `RemoteTextDialog` も同じガードを利用するため、Gitコミットメッセージの入力画面とYes/No確認画面の両方が対象。
- Git実行処理、手裏剣1〜4件、Browser横スクロール、設定JSON、Studioは一切変更しない。

## Windows実機での確認
1. Files Listの対象ファイルを右クリックし、Gitコミットを選択する。
2. メッセージダイアログでぐりぐりを回してOKを選択。**ぐりぐりボタンをクリックして確定**できるか確認する。
3. 次の確認ダイアログでぐりぐりを回してYesを選択。ぐりぐりクリックで確認できるか確認する。Gitコミットする場合はテスト用のリポジトリを使用する。
4. List上の同じ位置からホイール選択・左クリックしても確定できるか確認する（この操作は今回の追加対応）。
5. ダイアログが現れた瞬間のクリックや長押し・右クリックで勝手に実行されないことを確認する。

## テストについて
PySide6/Windowsの実GUIはこの環境では利用できず、Qtを模した入力イベントの単体テストを実施。実機GUIの操作感は未検証。
