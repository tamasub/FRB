# FRB 設計書・実験ログ GitHubアーカイブ（圧縮後50MiB版）

## 置き換え・実行

`archive_export` 内の **BAT・PS1・README** を次の既存フォルダーに上書きしてください。

`F:\FRB\tools\archive_export\`

その後 `Export-FrbDocsArchive.bat` をダブルクリックします。PowerShell 5.1 対応。実行途中で異常が起きたら、画面のエラーを確認してください。

## 対象と出力

| 入力 | 出力 |
| --- | --- |
| `F:\FRB_docsExcel\設計書` | `F:\FRB\_archive\設計書.zip_` |
| `F:\FRB_docsExcel\実験ログ` | `F:\FRB\_archive\実験ログ.zip_` |

- ZIPの中身は標準ZIP。GitHubで `*.zip` が除外されるので、拡張子のみ `.zip_` にします。
- 元フォルダー・サブフォルダー構成をZIP内に残します。隠しファイルも対象、リンク/リパースポイントは従来どおり除外します。
- **圧縮前の合計サイズでは分割しません**。圧縮してみて **ZIP実サイズが50MiB以下なら1本**、超えた場合だけ、ZIP内部の圧縮済みサイズを参考に分割して個別ZIPを再作成します。各パートの実サイズも再検査し、50MiB以下になるまで再分割します。
- 分割が必要なら `実験ログ_001.zip_`、`実験ログ_002.zip_`…のように出力します。
- 圧縮後でも**単一ファイルだけで50MiBを超える場合**は、普通のZIPを分割できないため、その対象はエラー終了し、前回分を残します。Git LFSなど別方式を検討してください。

## 古い分割ファイルを自動整理

**新しい対象アーカイブをすべて作成し、ZIP内の全ファイルをSHA-256で読み戻し検証した後**、前回の同名/分割形式のアーカイブから切り替えます。

例えば、今回のログが約15MiBに圧縮されるなら、次のように変わります。

```text
切り替え前:
  実験ログ_001.zip_  (8.50MiB)
  実験ログ_002.zip_  (6.43MiB)
切り替え後:
  実験ログ.zip_      (約15MiB)
```

新しいZIPを全て検証する前には、前回アーカイブを削除しません。切り替え失敗時は旧版に戻す処理を試みます。途中で電源断などが起きた際は `*.previous-*.bak` が残る可能性があります。手動で復旧状況を確認するまで削除しないでください。

## 空フォルダー・異常時

- 設計書または実験ログのフォルダーが存在しない場合、その対象だけ警告してスキップします。
- フォルダー内にファイルが0件なら、**前回のアーカイブを保護してスキップ**します。
- 圧縮・読み戻し検証に失敗した場合、その対象の前回アーカイブは保持します。
- `-DryRun` はファイル数・圧縮前合計サイズだけを表示します。圧縮後のサイズや分割数は、実際に圧縮しないと分かりません。

```powershell
cd F:\FRB\tools\archive_export
.\Export-FrbDocsArchive.ps1 -DryRun
```

## GitHubへの登録

GitHubの `tamasub/FRB` は公開リポジトリです。実験ログ・設計書に秘密情報が含まれていないことを確認してください。

```powershell
cd F:\FRB
git status -sb
git add -A -- _archive
git diff --cached --stat
# 内容を確認してからコミット/Push
```

`git add -A -- _archive` は、**新規の `実験ログ.zip_` の追加だけでなく、古い `_001.zip_`・`_002.zip_` の削除もステージ**します。Gitの過去コミットに保存された古い内容までは削除しません。

### 注意

- 通常のGitHub Pushでは1ファイル100MBのハード制限があります。デフォルトの50MiBの分割はこの制限より十分小さい設定です。
- ファイル内容が変化するたびに、バイナリZIPの履歴は増えます。F/Dの別ドライブへのバックアップも継続してください。
- `.zip_` のままGit管理できます。展開したいときは `.zip` に名前を戻してください。
- Windows実機での実行確認は未実施。最初の実行ログで `[OK]` と出力されたファイル数・サイズを確認してください。
