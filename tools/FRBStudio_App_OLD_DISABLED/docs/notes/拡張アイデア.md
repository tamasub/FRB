## 思考拡張インターフェースボタン（仮）

Studioくんのグリッド上部に置く、単なる操作ボタンではなく、

> **成果物に対して、どの思考・検証アクションを実行するか選ぶ入口**

として扱う。

### 例

* AI依頼プロンプト生成
* Git Diff → JSON View
* AI差分物語生成
* 判断ログ生成
* Expected比較
* テスト実行
* 関連テスト実行
* 承認

同じ「テスト実行」でも、対象によって意味が変わる。

```text
TestPattern
→ 選択したテストを実行する

Incident
→ 関連するテストを実行し、問題が解消したか確認する
```

画面ごとに処理を直接書くのではなく、共通インターフェースでActionを呼び出す。

```js
const action = actionStrategyRegistry[actionId];
await action.execute(context);
```

```text
ActionDef
= どの思考操作を提供するか

ActionStrategy
= その操作をどう実行するか

ViewDef
= どの画面に、どのボタンを表示するか

Context
= 対象データや関連情報をActionへ渡す
```

これにより、同じ思考アクションをインシデント、テストパターン、ルール、ExpectedDef、判断ログなどで再利用できる。

> **ボタンを再利用するのではない。
> 思考へ加える操作を再利用する。**

仮称：**思考拡張インターフェースボタン**。
名前は大げさだが、Studioくんが「JSONを見る画面」から「成果物を考え、検証し、承認する操作盤」へ進む入口になるかもしれない。
