## 物語の起点

話のスタートは「テストコードを書きましょう」ではない。

AIは短時間で膨大なコードを生成する。
400KS/人月という、昔なら冗談みたいな量が現実味を帯びる。

しかし、問題はそこから始まる。

```text
AIは400KS書けるかもしれない。
でも、人間は400KS読めるのか？
400KSを納得して承認できるのか？
400KS分の品質を説明できるのか？
```

ここから、AI時代の本当のボトルネックが見えてくる。

```text
書く時間ではなく、承認する時間。
```

## 竹槍エビデンス文化

現場には、テストコード文化が根付いていないことが多い。

かわりにあるのは、Excelにスクリーンショットを貼り付け、人間が何重にもチェックする文化である。

それは竹槍だ。

でも、竹槍を笑って終わりではない。
Excelエビデンス文化は、何かを守ろうとしていた。

- 確認した事実を残したい
- あとで説明できるようにしたい
- レビューしたい
- 品質を担保したい
- 本番を壊したくない

目的は正しい。
手段がAI時代の生成量に耐えられないだけである。

---

## テストコードを叫ばない世界観

テストコード文化を根付かせたい。

でも、現場に向かって「テストコードが必要です！」と叫んでも、たぶん根付かない。

AI駆動開発を語ると、話は自然に変わる。

```text
AIに安全にコードを書かせるには期待値が必要になる。
AIの変更を承認するには差分が必要になる。
差分を納得して見るには証跡が必要になる。
次のAI修正へつなぐには失敗結果が必要になる。
```

気づいたら、テストコードは目的ではなく、AI駆動開発を成立させる自然な装置になっている。

```text
テストコード文化は、テストコードを書けと叫んでも根付かない。
期待値・差分・証跡が必要になる世界を作ると、自然に生えてくる。
```

## ウォーターフォールの亡霊

古い開発手法には、しんどい部分があった。

- 重い
- 遅い
- 形式主義
- Excel方眼紙
- 作ったあと誰も読まない

でも、芯には価値があった。

- 責務を切る
- 入出力を決める
- インターフェースを守る
- 単体と結合を分ける
- 証跡を残す

Studioくんは、その芯だけを取り出してAI駆動開発に転生させる。

```text
昔のプログラム一覧
  → ResponsibilityDef

昔の入出力仕様
  → Input Contract / Output Contract

昔の単体テスト仕様
  → TestPattern / ExpectedDef

昔の結合テスト仕様
  → InterfaceExpectedDef

昔のエビデンス
  → Actual / Diff / Screenshot / Story
```

つまり、これはこういう作業である。

```text
ウォーターフォールの亡霊を、
AI駆動開発の守護霊にする作業。
```

## 責務境界の城門

Studioくんは、JSONも読む。ViewDefも読む。Markdownも読む。Diffも見る。Gitも絡む。スクショも将来語りたい。

なんでもできるカオス生命体である。

だからこそ、機能単位でテストを切ると死ぬ。

必要なのは責務境界である。

さらに、その責務境界はただの分類ではない。
責務単位インターフェースの入口は、城門でなければならない。

```text
責務境界の外は疑う。
責務境界の内は信じる。
```

小さいFunctionすべてにガチガチの入力防衛を入れるのは現実的ではない。
だから、責務単位の入口でガチガチに守る。

これが ResponsibilityDef の本質である。

## 見た目まで語り始める

最初からピクセル完全一致でFAILにする必要はない。

まずは人間確認用スクショを保存する。

```text
この操作をしたら、この画面状態になった。
その証跡としてスクショを保存する。
```

そして将来、スクショ差分物語へ進む。

```text
コード差分物語
  = ソース変更の意味を語る

JSON差分物語
  = Data / ViewDef / ExpectedDef の変更意味を語る

スクショ差分物語
  = 見た目変更の意味を語る
```

Studioくんは、ついに見た目まで語り始める。

## 性能の話へつながる

テスト設計は性能設計にもつながる。

たとえば、グリッドに100列は出さない。

これは単なる性能問題ではない。

- 人間が読めない
- ExpectedDefが巨大化する
- 差分確認が困難になる
- スクショ証跡が意味を失う
- AI差分物語にも向かない

つまり、100列グリッドは人間承認性を壊す。

```text
Gridは全項目表示の場所ではない。
Gridは、人間が一覧判断するための入口である。
```

性能もまた、責務境界防衛の一部である。

## 記事の締め候補

AI時代に必要なのは、AIにたくさん書かせることだけではない。

AIが書いたものを、人間が短時間で、納得して承認できる構造である。

Excelにスクショを貼り続ける竹槍文化を、ただ否定しても文化は変わらない。

その竹槍が守ろうとしていたものを救出し、Expected / Actual / Diff / Evidence へ転生させる。

そして、ウォーターフォールの亡霊を、AI駆動開発の守護霊にする。

Studioくんは今日も、カオスの中に責務境界を立てている。
