今回の構想は、**Studioで管理するJSONを、日常の操作に使うための「Launcher View」**やね。昨日の日付入力から、だいぶ育った笑

### 1. 基本方針

- **Ctrl＋Shift＋`;`で呼び出す。**
- キーボード中心で、検索・選択・実行を気持ちよく操作する。
- 設定データはJSON Studio対応のJSONにする。**専用のメンテ画面は作らず、Studioで編集する。**
- アクションと変数展開を追加して、用途を育てていく。

### 2. 画面構成

**タイトル表示なし。検索欄・Pageタブ・メニュー一覧のシンプルな構成。**

| 要素 | 内容 |
|---|---|
| 検索欄 | ヘッダーに配置。クリックしなくても文字を打てば入力される |
| Page | 多数の登録項目を大きく分類する |
| メニュー一覧 | 縦一列。各行はアイコン＋タイトル＋説明 |
| トップの項目 | 基本はカテゴリー。頻繁に使う実行項目も直接置ける |
| 子メニュー | 親一覧を残したまま、横に展開する |

見た目は、余白・文字・アイコン・選択色を揃えた、シンプルでおしゃれな方向。色や寸法の具体値はこれから決める。

### 3. Pageとカテゴリー

整理の階層は **Page → カテゴリー → 子カテゴリー／メニュー項目**。

| 種類 | 内容 | アイコンの方向 |
|---|---|---|
| ランチャーのカテゴリー | JSONで登録した子項目を表示 | 青系のフォルダー |
| 実フォルダー | 実際のファイル・子フォルダーを取得して表示 | 黄色系のフォルダー |
| 実行項目 | テキスト入力、起動などを実行 | 用途別／アプリ固有アイコン |

カテゴリーと実行項目は同じ一覧に混在できる。カテゴリー内の項目をトップにも置く場合は、同じ定義を参照する形がよさそう。

### 4. 検索

**検索は全Pageを横断し、登録カテゴリーの下の階層も対象にする。**

| 検索対象 | 例 |
|---|---|
| タイトル | 昨日の日付、Roaming |
| 説明 | Wi-Fi接続後、計測画面を開く |
| 実行先・設定値 | `shell:AppData`、URL、ファイルパス |
| 別名・キーワード | エクセル、表計算 |
| 所属Page・カテゴリー | 仕事、ZIP作成 |

`appdata`で `shell:AppData`と `shell:Local AppData`の両方が出るようにする。

検索欄が空なら選択中Pageの通常一覧、文字があれば検索結果を表示。結果には所属Page・カテゴリーを添え、クリアしたら検索前の場所へ戻る。

※実フォルダーの中身をどこまで検索するかは、登録メニューの検索とは別に決める。

### 5. 操作性

| 操作 | 動作案 |
|---|---|
| 文字入力 | 検索欄へ入力 |
| ↑／↓ | 項目を移動 |
| →／← | 子一覧へ入る／親へ戻る |
| Enter | 実行、または選択一覧を開く |
| Space | 複数選択のチェック切り替え |
| F12 | 複数選択を確定して実行 |
| Ctrl＋PageUp／PageDown | Page切り替え |
| Esc | 検索解除／階層を戻る／閉じる |

**マウスオーバーでもカテゴリー・実フォルダーを次々に展開**する。子一覧へ移動する途中で展開が切り替わらないよう、反応を調整する。

検索欄のカーソル操作や日本語IMEの変換操作と、一覧操作がぶつからない設計も必要。

### 6. 値の準備と変数展開

アクションの前に、共通の仕組みで入力値を作る。

- 定型文中の **`%変数%`を展開**する。
- 一覧から選択した値を、指定した区切り文字で結合する。
- 必要な値をその場で入力してもらう。

変数は、昨日・今日・年月から始め、環境情報、クリップボード、選択結果などへ増やしていく。テキストだけでなく、パス・URL・起動引数にも使う。**変数の具体的な記法はまだ未確定。**

メール宛先なら、  
**組織 → 人の一覧 → チェック → F12 → メールアドレスを結合 → 呼び出し元へ入力**。

### 7. アクションと外部処理

これまでの話では、共通の入口は次の形に整理できる。

| アクション案 | 役割 |
|---|---|
| `text.send` | 作成した文字列を呼び出し元へ入力 |
| `clipboard.copy` | 作成した文字列をコピー |
| `system.open` | フォルダー、ファイル、URL、`shell:`、`ms-settings:`などを開く |
| `process.run` | EXE・バッチ・各種スクリプトを起動 |

Wi-Fi切り替え、スピーカー切り替え、ZIP作成などは、外部処理として追加できるようにする。各種コマンド実行環境への対応も、この部分で扱う。

複数アクションの順次実行にも対応したい。**起動と処理完了を区別し、成功したら次へ進む。** 必要なら、作成したZIPのパスなどを結果として受け取る。

### 8. 現時点で使いたいもの

| 用途 | 動作 |
|---|---|
| 日付入力 | 昨日・今日・年月を展開して入力 |
| 定型プロンプト | 変数を展開して入力 |
| 組織別メール宛先 | 複数選択して結合入力 |
| フォルダー・お気に入りURL | 開く／フォルダー内を展開 |
| アプリ | 起動 |
| Windowsの各種場所 | `shell:`などで開く |
| FRB FFT／CAM | Wi-Fi接続 → 接続確認 → 対応画面を開く |
| 通常のWi-Fi | 普段の接続先へ戻す |
| 音声出力 | ディスプレイスピーカー／イヤフォンを切り替える |
| ZIP作成 | カテゴリーから対象バッチを選んで実行 |

### 9. 到達したい姿

**「ランチャーが、作業中の画面に合わせて道具を出してくれる」こと。**

呼び出し元のアプリやWebページを把握して、関連する操作を先頭に出す。さらに、認証画面の「続行」ボタンなどを、ランチャーから選んでクリックできるようにする。ブラウザー連携の実現方法は別途検討が必要。

作る順番としては、**検索と階層操作の感触 → 文字列入力と起動 → 外部処理の連携 → 作業画面に応じた候補とWeb操作**がよさそう。

最初の版から大切にしたいのは、**呼び出した瞬間に打てること、矢印で迷わずたどれること、元の入力欄へ確実に文字を送れること**やね。
