# 180円商品の正体

## CONTEXT DIFF #1

### 同じ画像・同じ質問。判断軸と制約で、AIが見る世界はどう変わる？

**先行体験版：180円**

商品のExpectedは、この3つで十分。

1. 判断軸を共有すると、AIが何を本質として見るかが変わる可能性を体験する
2. 制約を追加すると、判断軸を維持したまま、AIが結論を出す境界が変わる可能性を体験する
3. 自分がAIと共有したい判断軸・制約を一つずつ考える

つまり、

```text
判断軸
＝ 何を見るか

制約
＝ どこまで言い切ってよいか

AI思考余白
＝ 方向と境界の内側で、AI自身が具体的に考える
```

を、理屈ではなく差分で感じてもらう。

あなたの共有文脈も、単なるプロジェクト紹介ではなく「何を重視し、どんなズレを避け、どう協働するか」を渡す土台として定義されている。さらに、説得よりも参加余白を作ることを重視している。今回の商品は、その思想をそのまま最小体験へ変換したものやね。

# 180円に含める範囲

## 体験1：判断軸編

```text
文脈なし
↓
人間と外部システムの協調構造

判断軸あり
↓
体験を別の人が追体験・再現できる構造
```

持ち帰る発見：

> 答えを指定しなくても、判断軸を渡すことでAIの着目点が変わる可能性がある。

## 体験2：制約編

```text
判断軸のみ
↓
YES

判断軸＋判定条件
↓
部分一致
```

持ち帰る発見：

> AIは共通点を忘れたのではない。制約によって、根拠を越える直前で止まった。

この2本で十分。
JSON出力構造の研究過程や、4条件比較などは**商品開発側の裏側**へ置いて、購入者には見せすぎない。

## 付属物

```text
01_体験用HTML
02_比較画像2枚
03_固定質問文
04_判断軸入りcontext.md
05_判断軸＋制約入りcontext.md
06_自分のAIで追試する手順
07_観察シート
08_自分用の判断軸・制約ミニワーク
09_結果が変わらなかった場合の読み方
```

ここでHTMLは二層にすると強い。

### 見本体験

検証済みの回答をボタンで順番に表示する。
これは購入者のAI環境に左右されず、商品の核となる体験を保証する。

### 追試体験

同じ画像・質問・文脈を自分のChatGPT、Claude、Copilotへ渡して試す。

```text
見本体験
＝ 商品側で再現するExpected

購入者のAI
＝ Actual

両者の違い
＝ Diff
```

またExpected／Actual／Diffに帰ってきた爆笑

# 商品の外に置く3つの層

## ① 無料の物語

はてなブログやZennで、

> 会社で同じ2枚の絵を複数人のCopilotへ見せたら、自分のCopilotだけ別の構造を見つけた

という実話を書く。

結果も隠さない。

最後に、

> あなたのAIでは、どうなるでしょうか？

と置く。

無料部分の役割は、**自分でも試したいという未完了感を作ること**。

## ② 180円の体験

本人の手を動かして、

> 文脈は事情説明だけではなく、AIへものの見方と境界を共有するものなのかもしれない

と気づいてもらう。

## ③ 無料の研究解説

体験後に読める記事として、

* 判断軸
* 制約
* AI思考余白
* 結論を指定することとの違い
* 今回の実験で失敗したv1〜v3

を公開する。

有料商品で理論を囲い込むのではなく、

> **有料部分は体験装置、理論は公開研究**

という立場が、あなたには一番合うと思う。

# その後の商品シナリオ

体験の深さに沿って階段を作る。

| 段階    | 商品                | 購入者の変化               |
| ----- | ----------------- | -------------------- |
| #1 観察 | 判断軸・制約の差分体験 180円  | 文脈でAIの見方が変わると知る      |
| #2 作成 | 自分の判断軸・制約を作るミニキット | 自分用context.mdの原型ができる |
| #3 循環 | AI協働スターターキット      | 文脈・作業・判断ログを一周する      |
| #4 運用 | Studioくん体験ラボ      | 成果物として継続管理する         |

価格は今決め切らなくていいけど、役割は分けたほうがいい。

## #2：自分の文脈を作る

購入者自身の題材を使う。

```text
何を大切にしているか
何を避けたいか
AIへどこまで任せたいか
どんな回答なら嬉しいか
```

を整理し、自分用の小さな `context.md` を完成させる。

## #3：本当のAI協働スターターキット

```text
context.md
incident.json
decision_log.json
constraints.json
AIへの依頼文
Before / After観察
```

を使い、AI協働を一周させる。

ここで初めて「スターターキット」という名前が似合う。

## #4：Studioくん体験ラボ

GitHubで無料公開しているStudioくんを、体験環境として使う。

Studioくん本体を売るのではなく、

> 文脈・判断・差分を成果物として扱う操作体験

を売る。

Studioくんは、見えない思考をJSONやViewDef、Actionを介して体験へ変換する構想として育ってきた。今回のシリーズの最終到達点とも自然につながる。

# 180円商品の販売後にやること

購入者へ、任意でこの4点だけ聞く。

```text
・どのAIで試したか
・一番「おおっ」と思った場所
・分かりにくかった場所
・自分のAIでも差が出たか
```

全文回答の提出は求めない。個人の会話内容も集めない。

集まった差分から、

* 体験時間
* 詰まりやすい箇所
* AIごとの反応
* 変化が出なかったパターン
* 新しい判断軸候補

を整理する。

そして、

> **CONTEXT DIFF 実験記録 #1**

として無料記事へ還元する。

```text
無料記事
↓
180円の追試
↓
体験ログ
↓
商品の改善
↓
新しい無料記事
↓
次の参加者
```

これが商品と研究の循環になる。
