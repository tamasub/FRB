# AI協働031 責務定義とテスト設計

## 会話の流れ（要約）

1. Diff JSON ViewerのDiff定義にJSON StudioのValidation Type思想を継承する方法についての「ふんわり質問」
2. 責務(Responsibility)にresponsibility_typeを持たせ、そこに標準TestPattern(EMP/ONE/MULTI/NONE/DUP/SCOPE/RESET等)を紐づける案 → [[責務定義駆動テスト設計]]
3. 1責務が複数のBehavior Type(FILTER+SCOPED+SELECTION_REQUIRED等)を合成しうるという気づき
4. RESETを「STATE_TRANSITION → RESTORE_TO_BASELINE」として汎用化する議論
5. 話題転換: 「400KS/人月」仮説 — AIの共通化能力を使い、人間の承認対象をコードから責務定義/TestPattern/Expected/Diffへ降ろすことで、承認単位が「KS」から「新規判断数」に変わるという整理 → [[400KS人月仮説と承認単位のシフト]]
6. 過去のgrid_column_build責務サンプル(01b_axis_commonize_priority)を振り返り、5つのGuaranteeがFILTER/ORDER_PRESERVE/EMPTY_SAFE/POLICY_INJECTION/NO_MUTATIONという標準Behaviorに圧縮できることを確認
